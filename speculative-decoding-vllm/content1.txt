S# 逐 token 解码：延迟的根源
T 大模型输出文字的方式，决定了它的速度上限：它不是一次写完一整段，而是严格按顺序一个 token 一个 token 往下写。
T 每推进一个 token，都要走完四步：
L 模型读取提示词，以及到此刻为止已经生成的文字。
L 计算下一个 token 的概率分布。
L 把概率最高的那个 token 拼到文本末尾。
L 带着更新后的文本回到第一步，继续重复。
T 每一步都包含一次完整的模型前向计算，所以你要求的输出越长，等待就越久。对做实时应用的开发者来说（聊天机器人、代码助手、RAG 系统），这种高延迟是最直接的痛点。

S# 推测解码：草稿模型猜，目标模型验
T 推测解码让两个模型分工协作，把逐 token 的串行等待换成一次并行验证，从而跳出单个模型的速度上限。
L **目标模型（主模型）**是主力，例如 Llama-3.3-70B。它输出质量高、结果可靠，但单步慢、成本高，职责是保证正确性。
L **草稿模型（辅助模型）**更小更轻，例如 Llama-3.1-8B。它生成速度极快，但容易在小地方猜错，职责是用尽量准的猜测省下时间。
T 速度收益有一个硬性前提：草稿模型与目标模型必须属于同一模型家族，而且词表必须完全一致，也就是共用同一个 tokenizer。只有词表对齐，草稿模型给出的 token 才能被目标模型直接验证，不需要额外的映射或翻译开销。

H# 推算流程：猜、验、留、纠
T 推测解码的关键洞察是：token 必须一个一个生成（每个新 token 都依赖前一个），但验证可以并行完成。Transformer 在一次前向里就能处理整段序列，所以生成 N 个 token 不必把昂贵的目标模型跑 N 次，只要跑一次，就能同时验证 N 个候选 token。
T 这套流程可以拆成四步：
L **起草（猜）**：草稿模型快速读取上下文，一次给出若干个可能的后继 token，比如 5 个。
L **验证（查）**：目标模型把原始输入与这 5 个猜测一起接收，用一次计算同时检查它们。
L **决策（拒绝采样）**：目标模型把自己的预测与草稿的猜测逐 token 比较，决定哪些留下。
L **纠正**：一旦发现坏 token，就把它以及它之后的所有 token 全部丢弃；目标模型补上正确的 token，草稿模型从这个新位置重新开始猜。
T 每一个被接受的 token 都省下了一次目标模型的顺序前向；被拒绝的那一位由目标模型亲自纠正，不会污染后面的结果。

H# 接受还是拒绝：拒绝采样的判定逻辑
T 草稿模型的猜测并不要求与目标模型完全一致，判断依据是概率比较，这套机制叫拒绝采样。
T 草稿模型给出一个 token 时带着自己的置信度（概率），目标模型随后计算同一个 token 的概率，两者逐 token 比较：
L **目标概率大于等于草稿概率**：目标模型认为这个 token 比草稿模型认为的更可能或同样可能，直接接受，这一步的猜测有效。
L **目标概率小于草稿概率**：不直接拒绝，而是掷一次概率骰子。目标模型的置信度相对草稿模型越低，被拒绝的概率越高。
T 这套判定保证最终输出的分布与高质量的目标模型在数学上一致，即使起草的是一个更小的模型。
T 换句话说，推测解码改变的是生成速度，不改变生成结果的质量。

H# 走一遍具体例子：The quick brown fox
T 用一句经典文本 The quick brown fox 来看加速是怎么发生的。草稿模型先读完这句话，然后往下预测 5 个新 token。

T **第 1 步，猜**：草稿模型根据 The quick brown fox 一次预测 5 个新 token。
T 它给出的结果是后面接上 jumps over the lazy dog。注意，这句话本该是 jumps over the log。
T **第 2 步，查**：目标模型拿到提示词和这 5 个猜测，用一次计算同时验证全部猜测。
T **第 3 步，出结果**：目标模型逐个复核概率。
L jumps：接受。
L over：接受。
L the：接受。
L lazy：拒绝。目标模型判断这里更可能出现 log，lazy 的概率过低，无法通过拒绝采样。
T **第 4 步，拿到加速**：虽然在第 4 个 token 上失败，但系统用平时生成 1 个 token 的时间成功生成了 3 个 token，也就是 jumps over the，这一步相当于 3 倍加速。
T **第 5 步，纠错**：目标模型用正确的 log 替换掉被拒绝的 lazy。
T **下一轮**：系统从确认后的新文本 The quick brown fox jumps over the log 重新开始起草。

H# N-Gram Matching：向历史文本要答案
T N-Gram Matching 是一种简单但有效的猜测方式：它不预测未来，而是回看已经生成的文本与输入提示词，从中找重复出现的模式。
T 具体做法分四步：
L **定义模式**：N-gram 就是 N 个 token 组成的序列。在 the quick brown fox 里，一个 3-gram 就是 quick brown fox。
L **回看历史**：系统取最近生成的 N 个 token，向前搜索提示词和全部已生成文本，找出这段序列此前出现过的位置。
L **推测后续**：找到匹配后，看此前那次出现之后紧跟的是哪些 token，并推测这次也会接同样的内容。例如 the quick brown 此前后面跟着 fox jumps over，那么再次出现 the quick brown 时，就可以把 fox jumps over 作为候选。
L **验证**：目标模型用一次前向把这些猜出来的 token 全部验证，流程与草稿模型推测解码一致。
T 它在文本重复度高的场景里特别有效：
L **代码生成**：反复出现的模板代码、循环结构、import 语句。
L **RAG（检索增强生成）**：把源文档里的大段内容原样搬进回答。
T 它最大的优势是零显存开销，因为不需要额外加载第二个草稿模型。
