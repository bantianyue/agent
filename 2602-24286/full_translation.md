# CUDA Agent：面向高性能 CUDA 算子生成的大规模智能体强化学习（逐句翻译基线）

## 1 引言

GPU 算子是现代深度学习基础设施的基础组件，其中 NVIDIA 的 CUDA 架构目前主导着 AI 硬件生态。尽管 CUDA 被广泛采用，高性能 CUDA 算子的开发与优化依然极具挑战性，这需要对 GPU 微架构特性有深入理解，并熟练运用性能剖析工具。

尽管大语言模型（LLM）在通用软件开发任务中已展现出可与人类比肩的能力，现有的 CUDA 算子生成方法仍然缺乏竞争力，即便借助 torch.compile 这类自动优化工具也如此，更遑论人类专家。

一条先前的 CUDA 代码生成研究路线聚焦于设计无需训练的工作流，这类方法依赖由执行反馈引导的、人工设计的精炼启发式策略。然而，这些方法并未从根本上弥补基础模型在 CUDA 编码能力上的缺失，导致性能提升被模型自身的内在能力严重限制。另一条研究路线尝试在由代码执行反馈驱动的固定多轮精炼循环中微调基础模型。然而，这类方法把所有历史解法都塞进上下文，浪费了上下文长度，并且限制了智能体自主学习调试、搜索和性能剖析策略的自主权。

为克服这些局限，我们提出 CUDA Agent，一个大规模的 CUDA 智能体训练系统，它从三个互补的维度系统性地增强基础模型的 CUDA 算子编码能力：数据、智能体环境、以及强化学习（RL）算法技术。

为支撑大规模强化学习，我们设计了一套可扩展的数据合成流水线，生成覆盖广泛难度等级的训川练问题，从而实现有效的课程式 RL 训练。在智能体环境方面，我们采用 Agent Skills 范式，为模型配备一套结构化规范，将编写、验证和优化 CUDA 算子的标准工作流形式化，并配合自动化测试与性能剖析脚本以提供基于执行的反馈。值得注意的是，我们实现了严格的正确性与性能测试，以及系统级权限隔离，以防范奖励作弊并确保准确的奖励信号。至于 RL 算法改进，我们分析了 RL 优化中不稳定的来源，并提出了针对 actor 与 critic 模型的多阶段预热策略，使大语言模型能够稳定训练 150 步。

整合这些组件后，CUDA Agent 成功扩展到 128k token 的上下文长度，并支持多达 200 次交互轮次，取得了最先进（SOTA）的性能。具体而言，在 KernelBench 的 Level-1、Level-2、Level-3 三个划分上，CUDA Agent 相较 torch.compile 分别实现 100%、100%、92% 的加速率，并在最难的 Level-3 划分上以约 40% 的优势超过 Claude Opus 4.5 和 Gemini 3 Pro 等先进专有模型。（注：我们发现 ChatGPT-5 系列模型不便于在该任务上评测，因为它们持续拒绝响应 CUDA 相关的提示。）

我们提出 CUDA Agent，一个用于自动生成 CUDA 算子的大规模智能体强化学习系统，它通过可扩展数据合成、技能增强的 CUDA 算子开发环境，以及为稳定长上下文多轮智能体训练而设计的 RL 技术，系统性地提升了基础模型的 CUDA 编码与优化能力。

## 2 相关工作

### 2.1 无需训练的算子生成系统

若干近期工作探索通过显式搜索来应对算子优化那不规则的地形。STARK 采用一支由规划、编码、调试角色组成的策略性智能体团队，在 KernelBench 上探索树状搜索空间，利用编译、正确性检查与计时反馈迭代精炼算子。ReGraphT 提出一个无需训练、检索增强的框架，将 LLM 的 CUDA 优化轨迹提炼为推理图，再经蒙特卡洛图搜索来引导较小模型达到有竞争力的性能。EvoEngineer 将 CUDA 算子优化建模为受约束的代码演化问题，应用 LLM 驱动的演化循环迭代编辑并验证算子以提升性能，同时保持正确性。CudaForge 引入一个无需训练的双智能体系统，其中 Judge 利用 Nsight Compute 剖析与硬件规格诊断瓶颈，并向 Coder 提供针对性的优化反馈，在多种 GPU 上实现一致的加速。

尽管这些工作展示了可观的性能提升，它们严重依赖基础模型的 CUDA 编码能力。此外，这些测试时扩展方法与我们的模型正交，也可应用于我们的模型。

### 2.2 为算子生成微调 LLM

与此同时，另一条研究路线试图通过监督微调或强化学习训练基础模型来改进 CUDA 算子生成。Kevin 提出一个用于 CUDA 算子的多轮强化学习框架，建模迭代的开发者工作流，在其 QwQ-32B 基础模型上于 KernelBench 取得正确性与性能上的显著提升。CUDA-L1 提出一个对比式强化学习框架，用基于执行的奖励评估多个 CUDA 算子变体。但其训练与评测都在同一 KernelBench 数据集上进行，缺乏合理的训练-测试划分，这种数据泄露使得其报告结果无法直接与我们比较。ConCuR 合成并整理带推理轨迹的 CUDA 算子，并用所得数据集将 QwQ-32B 微调为 KernelCoder，在开源模型中取得性能提升。

总体而言，这些方法仍从根本上受限于高质量训练数据的稀缺、有限的训练规模，以及人工设计的优化循环，这些因素共同限制了它们的性能提升。

## 3 方法

我们的大规模智能体强化学习系统 CUDA Agent 建立在三个关键组件之上：1）可扩展的数据收集流水线；2）集成了技能、且带有鲁棒奖励调度设计的不可作弊训练环境；3）为稳定训练而提出的强化学习算法技术。每个组件对取得最终强劲的实证结果都至关重要。

### 3.1 可扩展的训练数据合成流水线

高性能 CUDA 算子的稀缺性给监督微调造成了显著瓶颈，因为人工实现专家级参考代码成本高得令人却步。为克服这一点，我们采用强化学习（RL）来训练 CUDA Agent。RL 需要大量多样、以 PyTorch 实现的参考算子作为训练任务。由于现有公开数据集缺乏必要的多样性与规模，我们开发了一套可扩展的数据收集流水线，通过种子问题爬取、基于 LLM 的组合合成，以及严格的基于执行的过滤（图 1）来系统性地扩展任务空间。

我们组合式数据合成的核心观察是：将多个算子组合成融合任务，能产生有价值的新型 CUDA 智能体训练问题。这是因为组合问题通常不等价于分别优化每个算子再串联。融合通过避免中间全局内存的物化、将各阶段通过共享寄存器/共享内存/占用率约束耦合起来，并要求统一的并行映射与数据布局（可能有利于下游消费），从而重塑了优化地形。

种子问题爬取：首先，我们从 torch 和 transformers 库中挖掘以 PyTorch 实现的参考算子，建立一个全面的种子问题集。每个算子表示为一个带有初始化与 forward 方法的 Python 类。这些算子类被广泛使用且维护良好，因此我们排除了缺乏足够代码质量的独立维护仓库。

组合问题构造：接下来，为扩展数据集并引入更高复杂度，我们利用 LLM 合成聚合算子。具体地，提示 LLM 从 torch 库中采样不超过 5 个算子类，将这些采样到的算子类按顺序堆叠成单一计算层来组合。我们不采样 transformers 库中的算子类，因为它们通常是已经封装了多个原始操作的高层模块。

问题过滤：最后，我们实现一个严格的数据筛选过程，根据执行反馈过滤掉过易或过难的问题。我们对每个算子验证四项标准：（1）该算子必须在 Eager 与 Compile 两种模式下都成功执行；（2）为保证可复现性，排除具有固有随机性的算子；（3）为防作弊，我们验证不同输入下的输出既非常量值也非数值上不可区分；（4）为过滤掉琐碎或过重任务，我们将 Eager 模式下的执行时间限制在 1 毫秒到 100 毫秒之间。此外，我们排除与 KernelBench 测试用例高度相似的算子。

总计，经过滤的合成训练数据集包含 6000 个样本，构成 CUDA-Agent-Ops-6K，一个用于训练具备 CUDA 能力的智能体的、经过整理的算子级数据集。

### 3.2 技能集成的智能体循环

智能体循环：由于 CUDA 算子编码天然是编码智能体的子任务，我们设计的智能体循环与广泛采用的 OpenHands 框架对齐以保证通用性。LLM 被提供一套标准的 shell 工具——BashTool、GlobTool、MultiEditTool、TodoWriteTool——以全面支持 CUDA 编码开发。在此之上，我们的智能体循环（图 2 所示）遵循 ReAct 式范式，交错进行推理、动作执行与观察，从而实现迭代式编码、调试与性能优化。

CUDA 编码技能：受 Agent Skills 思想启发，我们有意将 CUDA 编码专用指令与工具（例如用于将生成算子与 torch.compile 性能做对比的剖析工具）以 Agent Skills 格式呈现。我们还设计了一个 CUDA 算子编码专用指令 SKILL.md，规定了优化 CUDA 算子的标准流程：
- 使用提供的 profile.py 脚本分析原生 PyTorch 实现的性能，识别性能瓶颈与优化机会，如过多的算子启动与次优的内存访问模式。
- 通过将模型重写进 model_new.py 并实现相应的 CUDA 算子源文件与绑定代码，来实现自定义 CUDA 算子，目标是分析阶段识别出的性能关键算子。
- 在提供的 GPU 沙箱环境中编译并评估优化后的模型，迭代精炼 CUDA 算子实现，直到同时满足数值正确性与性能要求。
- 从步骤 2 开始重复优化过程，直到最终实现相较 torch.compile 基线至少获得 5% 的加速，且通过全部数值正确性检查。

鲁棒奖励调度：现有的 CUDA 生成 RL 方法用相对基线的加速作为奖励信号。然而，我们观察到这种方法受离群值影响，并偏向简单算子。这是因为算子的优化难度差异巨大，使得原始加速成为代码质量不可靠的代理。为此，我们提出一种归一化、鲁棒的奖励方案来补救，并联合优化正确性与执行延迟。

我们基于正确性与性能分配奖励分数 r ∈ {−1, 1, 2, 3}：其中 t 是生成算子的运行时间，t_native 与 t_compile 分别是 PyTorch eager 实现与 torch.compile 版本的运行时间，b(t, t0) = 𝕀[(t0 − t)/t0 > 5%] 表示相对基线 t0 的显著加速。我们在 4.3.2 节验证了该设计显著优于常用的加速奖励。

避免奖励作弊的努力：我们注意到先前工作存在作弊问题。具体地，我们的系统强制执行以下约束以避免奖励作弊：（1）用于正确性验证与性能剖析的 Python 脚本通过文件权限控制受保护，防止智能体修改或干扰评估逻辑；（2）为避免平凡回退，我们使用上下文管理器强制限制执行时间，明确禁止调用 torch.nn.functional 中的回退实现，确保性能提升纯粹来自生成的 CUDA 算子；（3）对每个问题，我们针对五个随机采样输入验证算子输出，严格遵循 KernelBench 评估协议以确保功能正确性；（4）剖析流水线经精心设计，带有适当的设备同步、预热迭代与重复测量取平均，大幅降低测量噪声与指标波动；（5）智能体不被提供任何网络搜索或外部信息检索工具，确保所有解纯粹源自本地执行环境。

### 3.3 稳定 RL 训练的算法改进

我们观察到，最初的 RL 试训只能在模型性能崩溃前稳定训练 17 步。我们定位了该不稳定的根因，并提出对 actor 与 critic 模型都进行预热以适配模型分布。经此修改，我们的 RL 试训可稳定训练 200 步且奖励持续增长。

训练不稳定的根因来自严重的领域分布失配，即基础模型学到的先验与 CUDA 算子编码所需的数据分布显著偏离。这是因为 CUDA 编码数据在预训练数据中占比不足 0.01%。这种分布鸿沟导致采样出大量低概率的 CUDA 算子代码 token。此外，当训练与推理引擎使用不同的数值精度（如 BF16 对 FP16）时，那些低概率 token 会造成重要性采样比方差巨大，因为在精度下限（如 π_θ(a_t|s_t) ≈ 10⁻⁹）附近计算 token 概率时的微小数值误差，会使重要性比 ρ_t(θ) 剧烈波动甚至爆炸。

为实现稳定的强化学习，我们提出一个简单而有效的预热策略：用基础模型经单轮 RL 生成的智能体轨迹来初始化 actor 与 critic 模型（图 3 所示）。

单轮预热：我们首先在基础模型上执行单轮 RL 以增强其 CUDA 算子生成能力。我们使用 PPO 进行优化，其中基础模型同时充当策略网络与价值网络。

Actor 初始化：随后我们对智能体轨迹采用拒绝微调（RFT）阶段来初始化 actor 模型 π_θ。单轮 RL 得到的模型被用来在 3.2 节的智能体循环中运行智能体以收集 CUDA 智能体轨迹。接着，我们对收集到的 CUDA 智能体轨迹应用 RFT。拒绝采样用于仅保留高质量 rollout：（1）结果过滤：仅保留获得正奖励（R > 0）的轨迹；（2）模式过滤：丢弃表现出低效或无效行为的轨迹，如冗余的多轮循环或违背预定义工具调用模式的幻觉。

过滤后的轨迹随后通过标准监督微调来优化 actor。

Critic 初始化：我们执行 Value Pretraining 来初始化 critic，具体地，利用由状态序列及其对应结果奖励组成的采样轨迹数据来预训练 critic 网络。我们用广义优势估计计算目标值，时序差分误差 δ_t = r_t + γV_ϕ(s_{t+1}) − V_ϕ(s_t)，其中 V_ϕ(s_T) = 0。实验中设 γ = 1，λ = 0.95。我们通过最小化均方误差来优化 critic 参数 ϕ。

RL 算法：我们采用 PPO 优化 actor 模型 π_θ。我们使用截断代理目标最大化期望回报，其中 ρ_t(θ) 是当前策略与旧策略之间的重要性采样比，ϵ_lower = 0.2，ϵ_higher = 0.28。

## 4 实验

### 4.1 实验设置

RL 训练设置：我们以 Seed1.6 为基础模型，一个拥有 23B 活跃参数、230B 总参数的 MoE 模型。全局批大小为 1024，与在线 PPO 更新的小批大小一致。actor 与 critic 的学习率分别为 3×10⁻⁶ 与 6×10⁻⁶。上下文窗口长度：单轮 RL 为 32768，智能体 RL 为 131072。训练 rollout 中最多 150 个智能体轮次，评测时放宽到 200 轮。模型训练 150 步。

沙箱环境：为确保准确的加速测量与高效的 GPU 利用，我们设计了一个 CPU-GPU 资源解耦的沙箱架构。基于 Docker 的终端沙箱处理 CPU 中心任务（如算子编译），而智能体利用预定义的 CUDA Agent 技能脚本将验证与剖析任务分派给专用的 GPU 沙箱池（128 块 NVIDIA H20 GPU）。这种进程级隔离与独占资源分配消除了进程间干扰，确保稳定的延迟测量与有保障的 HBM 容量。

基准：我们在 KernelBench 上评测，使用 Level 1 至 Level 3 子集，共 250 个不同算子任务。为保证公平比较，我们将这些任务从原始单文件格式适配到我们的多文件开发环境。

基线模型：我们与前沿专有编码模型比较：Claude Opus 4.5 与 Gemini 3 Pro，以及两个强开源编码模型：GLM 4.6 与 Kimi K2。这些模型在当前主要编码智能体排行榜上居领先地位。为公平比较，基线模型在 3.2 节相同的智能体循环下评测。

评估指标：我们用三个关键指标评估性能：（1）通过率（Pass Rate），即智能体生成能通过编译与功能正确性检查的算子的任务百分比；（2）加速率（Faster Rate），即生成的算子正确且执行时间快于基线（eager 与 compile 模式）的任务百分比；（3）加速比（Speed-up），相对基线的执行加速比的几何平均，仅对正确解计算。为确定每个任务的最终指标，我们从智能体交互轨迹中提取表现最优的解，即相对 torch.compile 加速最大的那个。

### 4.2 主要结果

表 1 总结了 CUDA Agent 与强专有模型基线在 KernelBench 上的性能。我们的分析得出关于智能体 RL 用于 CUDA 算子优化的三个主要洞见。

第一，与强专有模型相比，CUDA Agent 提供了显著更强的 CUDA 算子编码性能。尽管 Claude Opus 4.5 与 Gemini 3 Pro 取得了尚可的通过率（91.2%–95.2%），它们的加速率仍低至 66%–69%，表明通用 LLM 常产生无法超越 torch.compile 的朴素算子。相比之下，CUDA Agent 达到 98.8% 的通过率与 96.8% 的加速率，证明专门的 RL 训练能带来持续正确且高度优化的 CUDA 实现。

第二，相比静态的 torch.compile，CUDA Agent 证明了习得优化策略能持续优于静态编译器启发式，尤其在算子融合等复杂场景中。这在 Level 2 任务（算子序列）中最明显，CUDA Agent 取得完美的 100% 加速率，并相对 torch.compile 实现高达 2.80× 的加速。传统编译器依赖预定义的、基于规则的算子融合模式，常在非平凡算子组合上受阻。相比之下，CUDA Agent 通过迭代智能体循环探索更大的设计空间，发现硬件特定的内存访问模式与分块策略，这些是静态后端无法触及的。

### 4.3 消融研究

#### 4.3.1 技能集成智能体循环的影响

为评估交互环境在策略学习中的关键作用，我们在两种不同协议下训练两个独立模型：（1）单轮模型，用标准代码生成目标训练，模型在单轮中预测最终算子与绑定，无执行反馈，作为我们训练流水线的预热阶段；（2）CUDA Agent，遵循完整训练流水线，允许策略在多轮交互中看到编译错误与剖析器反馈。

表 2 凸显了单轮代码生成的局限，并强调了我们技能集成智能体循环的必要性。移除智能体循环导致正确性与优化质量双双大幅下降。更重要的是，所得算子不仅优化程度更低，且常出现性能回退。暴露于编译错误、运行时失败与剖析器反馈后，智能体能够迭代诊断错误并跨轮次精炼转换。

#### 4.3.2 奖励设计的影响

为确定算子优化奖励的最优塑形，我们评估两种奖励公式：（1）加速奖励，对正确解定义为 r_s = t_compile / t_gen 的连续奖励，错误解为 −1；（2）我们的鲁棒奖励调度（图 3），对达成特定性能里程碑赋予离散值。

如表 2 所示，奖励设计对优化结果有显著影响。用原始加速奖励替换我们的鲁棒奖励调度（w/o Robust Reward）得到可比较的功能正确性，但优化性能大幅减弱。

这些结果表明，归一化、基于里程碑的奖励更契合"产生持续更快算子"的目标。通过对清晰性能目标赋信，而非直接对噪声运行时间比做回归，策略更可靠地发现相对于 eager 执行与编译器基线的真实加速转换。

#### 4.3.3 多阶段训练的影响

如表 2 所示，移除 RFT 或 Value Pretraining 任一项都会导致优化性能大幅退化，尽管通过率大体保留。更重要的是，两种消融都表现出训练不稳定并最终崩溃。

拒绝采样微调（RFT）提供了一个防止策略崩溃的关键先验。如图 4(a) 所示，移除 RFT 阶段导致训练奖励快速且灾难性地崩溃。为诊断潜在原因，我们检查图 4(b) 的策略熵，揭示出与奖励崩溃相吻合的急剧上升。这一熵激增表明策略分布变得日益弥散，产生不连贯且结构不良的输出。通过以强行为先验初始化策略，RFT 约束了强化学习期间的熵增长，并将优化轨迹保持在结构良好的输出分布内。

Value Pretraining 对提供可靠优势估计、防止病态搜索行为不可或缺。没有初始化的 critic，模型无法捕捉多轮交互状态的价值地形（图 5(a)）。这种糟糕的估计导致轨迹长度爆炸（图 5(b)），因为未初始化的 critic 无法惩罚徒劳或冗余的搜索路径。Value Pretraining 确保 critic 能立即提供准确反馈，引导智能体走向高效优化路径，避免近无限交互循环的计算不稳定。

## 5 结论

我们提出 CUDA Agent，一个大规模智能体强化学习系统，赋予大语言模型在真实、执行驱动的开发工作流下生成并优化 CUDA 算子的能力。通过联合扩展数据合成、智能体环境与面向稳定的 RL 训练，CUDA Agent 将 LLM 从语法代码生成推向硬件感知的性能优化，在 KernelBench 上相对 torch.compile 与强专有模型取得持续增益。这些结果暗示一个更广义的后果：为基础模型配备结构化环境与可靠的基于执行的奖励，能将它们从被动的代码生成器转变为主动的系统优化器，为自动化 GPU 计算中性能关键的软件开发开辟道路。
