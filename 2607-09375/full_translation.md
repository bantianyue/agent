# 全文翻译：Mach-Mind-4-Flash Technical Report

## Abstract

我们提出 Mach-Mind-4-Flash，一个 350 亿参数（35B）的混合专家（MoE）智能体模型，激活参数仅 30 亿（3B）。仅通过后训练优化、而不扩大预训练算力，该模型就能达到与 1000 亿（100B）参数级别模型相当甚至更优的性能。通过为大规模强化学习引入可扩展的智能体交互环境，模型在真实世界应用任务上获得显著提升。我们的流水线包含三个阶段：（1）统一的 RL/OPD 训练基础设施，具备动态多教师调度与算子级加速，带来 17% 的端到端训练提速；（2）多个领域专属的 RL 专家在推理、通用、智能体三条轨道上并行训练，随后通过多教师同策略蒸馏（MOPD）融合为单一通用模型——MOPD 是一种路由式反向 KL 目标，消除了混合奖励 RL 的跷跷板退化；（3）混合中位数长度策略优化（HMPO），一种单阶段 token 效率方法，将推理链压缩 19–46%，准确率损失不超过 0.7 个百分点。Mach-Mind-4-Flash 在 AIME'26 上得分 92.70，IFBench 82.82，Behavioral-SafetyBench 80.74，BFCL-v4 75.80，BrowseComp-zh 72.31，ClawBench 84.20——以极小的一部分推理成本，领先或追平激活参数规模为其 10–30 倍的模型。

## 1 Introduction

扩展语言模型一直是能力增长的主导配方，但其伴随的推理成本使得万亿参数模型在延迟敏感型部署中不切实际。一个新兴的替代方案是扩展后训练流水线，通过强化学习、专家融合与推理时效率优化，将紧凑的基础模型推向前沿性能，而不是仅扩展预训练算力。Mach-Mind-4-Flash 是我们沿着这一方向的贡献：一个 35B MoE 模型（激活 3B），其后训练栈将其提升到比其激活参数量多 10–30 倍的前沿模型性能层级。支撑这一结果的三大技术支柱如下：

（1）具备算子级加速的可扩展训练基础设施。后训练一个通用模型需要编排多条 RL 专家轨道、一个多教师蒸馏阶段和一个 token 效率阶段，它们共享同一分布式基础设施。我们构建了统一的强化学习 / 同策略蒸馏（RL/OPD）训练范式，通过单一加权损失在纯 RL、纯蒸馏和联合模式之间无缝切换。在此之上，我们设计了动态多教师架构，新增一个专家无需侵入训练核心。在算子层面，我们深度集成了 SonicMoE 索引式分组通用矩阵乘法（GEMM）算子，以及一种将通信与计算重叠的分段共享专家融合策略，在 Qwen3.5-35B-A3B 训练上带来最高 17% 的端到端提速。

（2）先专业化后整合：多个专家，一个通用模型。我们不是用异构奖励混合物训练单一模型（这不可避免地会遭受能力跷跷板效应），而是在三条轨道上独立训练多个 RL 专家：推理（数学、代码、STEM）、通用（指令遵循、写作、安全）、智能体（工具使用、深度搜索、代码智能体、Claw 智能体）。每个专家都用领域适配的数据合成、可验证奖励信号和定制训练策略（例如稀疏结果域的两阶段奖励课程、智能体域的可执行多轮环境）进行优化。这些专家随后通过多教师同策略蒸馏（MOPD）整合，MOPD 将每个训练样本路由到其对应的冻结教师，并通过 token 级反向 KL 目标在学生自身的 rollout 上监督它。这种设计将专家开发并行化、消除了顺序依赖，并产生一个保留、偶尔还超越单个专家性能的统一模型。

（3）不牺牲准确率的 token 效率。强推理模型倾向于过度思考，产生冗长的推理链，在不成比例地提升准确率的情况下抬升服务成本。我们用 HMPO（混合中位数长度策略优化）解决这个问题，这是一种作为流水线最后一步应用的单阶段 RL 方法。HMPO 从正确 rollout 的中位数推导出一组自适应长度预算，并应用乘法式「正确性优先」奖励，从数学上防止对「短但错」输出的奖励 hacking。仅在数学上训练，这种压缩就能泛化到代码、科学、指令遵循，将生成长度减少 19–46%，准确率损失最多 0.7 个百分点。

## 结果

最终模型 Mach-Mind-4-Flash 证明，激进的后训练可以缩小紧凑的 35B MoE 与显著更大的前沿模型之间的差距。在竞赛数学（AIME'26：92.70）、代码生成（LiveCodeBench-V6：80.91）、指令遵循（IFEval：94.64；IFBench：82.82）、安全（Content-SafetyBench：98.20；Behavioral-SafetyBench：80.74）和自主智能体任务（ClawBench：84.20；BFCL-v4：75.80）上，Mach-Mind-4-Flash 持续匹配或超越 1200 亿级别的模型，并与万亿参数系统保持竞争力——而推理时仅需 3B 激活参数。我们发布这份技术报告，以详细记录训练方法、基础设施创新和评估结果。

## 2 Related Work

近期大模型正从通用聊天助手转向面向生产的智能体系统，能够推理、调用工具、执行代码、与环境交互并完成长周期任务。我们从三个方面总结相关工作：智能体基础模型与基准、智能体后训练与强化学习、高效且安全的智能体部署。

## 3 Infra

为了提升后训练阶段（包含强化学习 RL 和知识蒸馏）的训练效率与系统灵活性，我们系统性升级了现有成熟的 RL 训练框架。我们提出了 RL 与同策略蒸馏（OPD）统一的联合训练范式，并构建了动态多教师可扩展架构。此外，我们从系统框架层和底层算子层两个维度进行深度训练加速与优化。

### 3.1 基于 RL 框架的统一 OPD 训练范式

传统知识蒸馏通常与 RL 训练流水线独立，难以充分利用 RL 框架在分布式调度、经验采样和策略优化上的系统优势。为此，我们将 OPD 深度集成到 RL 框架中，构建了统一的联合训练范式。该范式通过一个统一的加权损失函数实现全局优化控制：

- ℒ_OPD：应用于蒸馏路径。为适配复杂知识迁移需求，我们扩展了 OPD 的损失函数形式。除传统 MSE 损失外，还支持 Forward_kl_TopK 等多种蒸馏目标，使学生的输出分布更准确、高效地逼近教师的目标分布。
- ℒ_RL：应用于策略梯度路径。它基于任务奖励信号执行序列级裁剪更新。

通过动态调整权重系数 α 和 β，该公式可以灵活切换三种训练模式：

1. 纯 RL 模式（α=0，β>0）：禁用蒸馏路径，框架退化为标准 RL 训练，完整保留原生 RL 能力，如策略梯度更新和多轮工具调用。
2. 纯 OPD 模式（α>0，β=0）：禁用基于任务奖励的策略更新，仅保留蒸馏路径。学生模型完全以教师为监督目标进行在线蒸馏。该模式收敛更稳定，适用于模型能力初始化阶段。
3. 联合 RL+OPD 模式（α>0，β>0）：蒸馏和策略梯度损失同时启用。两条优化路径相互独立且自然叠加，展现出极好的兼容性。

受益于这种深度集成，统一范式直接继承了 RL 框架的系统级能力：复用成熟的分布式训练和调度机制；继承异步奖励路由机制，支持超过 20 类任务的并行奖励计算；在单一框架内实现在线采样、奖励评估、策略优化和蒸馏监督的闭环，显著增强训练流水线的一致性和可维护性。

### 3.2 动态多教师可扩展架构

在实际大规模后训练场景中，单一教师模型往往难以全面覆盖所有任务域。反之，为不同任务构建独立的训练流水线容易造成资源浪费和工程碎片化。因此，我们设计了动态多教师可扩展架构，支持灵活、按需整合教师模型，实现「积木式」组合训练能力。

架构设计与路由机制。多教师架构的核心设计原则是：新增一个教师对框架核心逻辑零侵入，对学生模型的训练过程完全透明。具体而言，每个教师实例作为独立的配置节点注册到蒸馏配置树中。Rollout 阶段完成后，框架根据每条数据的路由标识，异步将样本分发到对应的教师实例。获取目标 logits 后统一聚合计算蒸馏损失。这一过程与学生的训练更新完全解耦，避免教师侧逻辑对主训练流水线的干扰。在数据层面，只需为样本增加路由标识列，就能绑定并动态切换到任意教师模型，全程无需修改训练代码，赋予系统极致灵活性。

弹性资源调度。该架构依赖 Ray 集群实现透明的多节点资源调度。学生模型（Actor）节点和教师节点的 GPU 分配由框架根据张量并行（TP）规模和副本数自动绑定，无需人工干预。每个教师可独立配置副本数，Ray 自动将对应进程调度到指定 GPU。同时，多个教师的并行推理与学生模型的训练通过 Ray 的异步机制解耦，确保教师数量增加不会成为训练吞吐的串行瓶颈。当业务需要为某新域引入教师时，只需申请额外节点并完成注册，即可通过「配置即扩展」实现无缝集成。

### 3.3 训练加速与极致优化

为实现复杂联合 RL 与蒸馏训练场景下的极致吞吐，我们从系统框架层和底层算子层两个维度深度优化。

系统框架级加速：

- 多维混合并行：学生模型基于 Megatron-Core 后端，原生支持张量并行（TP）、流水线并行（PP）、专家并行（EP）等多维并行策略。结合 MoE 分组 GEMM 算子融合技术，显著提升 MoE 架构模型的训练吞吐。
- 细粒度算子级重计算：采用选择性激活重计算策略，仅对轻量算子（如 RMSNorm）重计算，跳过计算密集算子（如 Linear）。该策略在节省 GPU 显存和控制计算开销之间取得最优平衡，使系统支持更大批次、进一步提升整体训练效率。
- 多 token 预测（MTP）加速：框架支持 Megatron-Core 原生 MTP 模块，并在 vLLM 采样阶段利用 MTP head 进行投机解码，大幅减少 Rollout 阶段耗时。

底层算子级优化：

- SonicMoE 深度集成：针对 Transformer 层计算最密集的 MoE MLP 模块，我们将 SonicMoE 深度集成到 Megatron 框架。SonicMoE 充分利用 Hopper 架构 GPU 的硬件特性（如 TMA 拷贝引擎、Warp 专门化、多阶段生产者-消费者流水线），实现高效的索引式分组 GEMM 算子及其 Gate-Up 融合变体。该设计消除了 token 重排步骤，降低全局显存访问延迟，大幅提升 GPU 计算吞吐。反向传播阶段引入局部重计算策略降低显存访问开销，并用 DeepEP 替代传统 All-to-All 集合通信，进一步提升多节点通信效率。
- 共享专家分段融合：在引入 SonicMoE 的基础上，我们高效的共享专家分段融合策略实现了通信-计算重叠。我们引入多流机制，将共享专家的计算拆分为三个阶段：AllGather、专家计算、ReduceScatter，与标准专家在 EP 模式下的计算阶段（Dispatch、专家计算、Combine）交错融合，实现通信-计算重叠并隐藏共享专家耗时。此外，我们发现当 TP、EP、ETP 同时开启时，若共享专家仅采用 TP 并行，通常导致通信量激增。为此，我们强制在共享专家模块设置 TP=1，减少通信导致的计算资源空闲浪费。该策略将共享专家计算与 SonicMoE 主计算并行调度，有效掩盖通信延迟，进一步突破训练速度瓶颈。

## 4 Post-Training

如图所示，Mach-Mind-4-Flash 的后训练流水线采用分层的「先专业化后整合」方法。基于 Qwen3.5-35B-A3B，我们首先进行有监督微调（SFT）建立基础对齐。然后将训练分叉为三条并行的强化学习（RL）轨道，每条产出多个专家检查点：推理 RL（数学、代码、STEM）、通用 RL（指令遵循、写作、安全）、智能体 RL（工具使用、深度搜索、代码智能体、Claw 智能体）。为在不退化的前提下将这些各异专家整合为统一模型，我们引入多教师同策略蒸馏（MOPD）实现无缝专家融合。最后，一个 token 效率 RL 阶段在保持准确率的同时压缩生成长度，得到部署版 Mach-Mind-4-Flash。

### 4.1 有监督微调（SFT）

为后续强化学习建立稳健基础，我们从 Qwen3.5-35B-A3B 出发，进行大规模多域 SFT。目标是将基础模型与多样化任务格式对齐，并赋予其在推理、通用对话和智能体交互上的广泛能力。

数据构成。我们的 SFT 语料覆盖七个域。各域样本数与 token 量分布如图所示。关键设计选择：数学与 STEM 聚焦可验证、有明确真实答案的问题，通过更强教师模型的拒绝采样合成高质量推理链，并用基于难度的过滤器只保留挑战当前基础模型的样本；代码域采用长代码生成与竞赛编程轨迹，从强教师蒸馏并用基于执行的正确性验证过滤。

### 4.2 推理与通用 RL

（推理 RL 与通用 RL 的奖励策略）采用规则化、可验证奖励；指令遵循采用两阶段奖励课程与程序化约束验证引擎（如 LexInstructEval）。

### 4.3 安全 RL

安全 RL 覆盖内容安全与行为安全。采用 Constitutional AI 式原则对齐与基于规则的奖励（RBR），并在智能体场景下评估模型是否恰当调用工具、遵守约束、避免不安全操作。

### 4.4 工具使用 RL

工具使用 RL 在可执行环境中训练多轮函数调用，采用迭代奖励校准处理中间工具动作。

### 4.5 深度搜索 RL

深度搜索 RL 训练长周期、带约束追踪的网页浏览能力，应对稀疏奖励与状态保持。

### 4.6 代码智能体 RL

代码智能体 RL 在仓库级环境中训练（SWE-bench 类），通过交互式 RL 提升长周期软件工程任务能力。

### 4.7 Claw 智能体 RL

Claw 智能体 RL 训练广义自主在线任务能力，覆盖日常任务与可信轨迹评估。

### 4.8 多教师同策略蒸馏（MOPD）

MOPD 将各域专家融合为单一通用模型。核心是一个路由式 token 级反向 KL 目标：每个训练样本按其路由标识发送到对应冻结教师，学生仅在自身 rollout 上以教师分布为监督目标。该设计并行化专家开发、消除顺序依赖，并避免混合奖励 RL 的跷跷板退化。两个从单教师试点沿用下来的设计选择：教师参数量与学生匹配时重叠率明显高于大得多的教师，且最终质量无损；在教师自身见过的 prompt 上训练能进一步提升重叠率与最终学生质量。

### 4.9 混合中位数长度策略优化（HMPO）

为什么需要 token 效率。MOPD 阶段将所有分域专家融合为单一通用模型，但它继承了强 CoT 推理模型众所周知的副作用：过度思考，即融合模型产生远长于任务所需的推理链，在不成比例提升准确率的情况下抬升推理延迟与服务成本。

方法：HMPO。我们采用 HMPO，一种高性价比的单阶段 RL 框架。与依赖刚性人工预算或昂贵多阶段剪枝的以往长度控制方法不同，HMPO 动态从正确 rollout 的中位数推导出一组自适应预算 b，并应用长度感知的 token 奖励。HMPO 构建于 GRPO 之上，唯一改动是重新设计 rollout 奖励 R_i 为预算感知，通过三个组件实现：

（1）自适应中位数预算。静态预算忽略难度，先验 rollout 估计代价高，因此我们将预算设为组中正确 rollout 的中位数长度 b = median({n_i | i∈C})。这把长度信号与失败轨迹隔离，具备难度感知（更难的问题产生更长的正确 rollout，从而更宽松的 b），并随策略改进自我收紧——一种零调参的隐式课程。

（2）余弦衰减 token 奖励。朴素惩罚会引发奖励 hacking，因此我们只奖励短于 b 的正确轨迹，并采用平滑着陆。

（3）乘法式组合。R_final = R_acc · R_token 强制严格的「正确性第一、长度第二」层级：错误或超预算轨迹获得恰好为零的奖励，拒绝向错误答案提供效率梯度；而加性组合仍会奖励冗长但正确的轨迹。通过避免任何辅助阶段，单遍运行比多阶段基线少用 1.5×–2.5× 的 GPU 小时。

训练配置。我们在约 6.5K 高质量数学问题的紧凑子集上运行 HMPO，刻意混合不同难度与推理链长度的样本，使组自适应预算暴露于广泛的正确 rollout 长度谱。每问组大小 G=10，奖励偏移 λ=0.8。值得注意的是，尽管仅在数学上训练，学到的长度控制行为泛化到未见域——代码生成、科学问答、指令遵循——表明 HMPO 灌输的是通用的「在正确性允许范围内尽可能简洁作答」策略，而非数学特定的捷径。

## 5 Experimental Results

### 5.1 整体结果

我们在覆盖广阔激活参数范围的开放与闭源基线上评估 Mach-Mind-4-Flash：万亿规模 MoE（Kimi-K2.5-1T-A32B）、约 120B 模型（Qwen3.5-122B-A10B、Nemotron-3-Super-120B-A12B）和紧凑的 ≤35B 模型（Qwen3.5-35B-A3B、GLM-4.7-Flash-30B-A3B）。为保证自洽比较，我们对所有模型使用自己的评估框架和相同解码设置；官方数字可用时采用官方，否则采用我们复现的值。基准套件覆盖八个能力轴：推理与知识、指令遵循、写作、安全、工具使用、代码智能体、深度搜索和 OpenClaw。

推理与知识。Mach-Mind-4-Flash 在 AIME'26 得分 92.70，AIME'25 92.08，匹配约 120B 的 Qwen3.5-122B-A10B（91.67），并将与万亿规模 Kimi-K2.5（93.30）的差距缩小到 1 分以内——有力证明激进后训练压缩不牺牲多步推理深度。代码生成 LiveCodeBench-V6 达 80.91，领先所有同规模模型，仅落后于 Step-3.5-Flash 和 Kimi-K2.5。GPQA-Diamond（83.08）情况类似：尽管激活参数少 30 倍，仍与 120B 级基线竞争。

指令遵循与写作。指令遵循是模型的突出强项：Mach-Mind-4-Flash 在三项基准上均居首，IFEval 94.64、IFBench 82.82、LexInstructEval 74.63。IFBench 领先尤其说明问题——许多在 IFEval 上高分的基础模型在留出约束上骤降，表明其过拟合已知模板而非真正理解约束。WritingBench 达 74.61，与 Qwen3.5-122B（74.80）持平，领先多数同规模模型。

安全。Mach-Mind-4-Flash 在安全上同样是明显强项：在两项基准均居首，Content-SafetyBench 98.20，Behavioral-SafetyBench 80.74。Behavioral-SafetyBench 结果尤其惊人——Mach-Mind-4-Flash 领先亚军（Kimi-K2.5，67.75）约 13 分，而多数基线落在 20–35 区间，揭示智能体场景下的行为级安全仍是领域未解难题，也是本模型的独特优势。

工具使用与代码智能体。BFCL-v4 上 Mach-Mind-4-Flash 得分 75.80，超越所有同规模 35B 模型（Qwen3.5-35B 67.30、GLM-4.7-Flash 68.40），匹配当前 SOTA MiMo-V2-Flash（76.30），同时超越大得多的模型 Qwen3.5-122B（72.20）和 Kimi-K2.5（74.50）。τ2-bench 达 80.04，大幅领先 Kimi-K2.5（72.82）和 Qwen3.5-122B（79.50）。SWE-bench Verified 70.60，与 Qwen3.5-122B（72.00）相当。

深度搜索。Mach-Mind-4-Flash 在 BrowseComp-zh 居首（72.31），领先 Qwen3.5-122B（70.30）和 Kimi-K2.5（71.28）；英文 BrowseComp（61.70）和 X-Bench（65.00）保持竞争力。该轴在所有基线上分化最剧烈：弱模型跌破 45 分，证实带约束追踪的长周期网页浏览仍是领域未解瓶颈。

Claw 智能体。Mach-Mind-4-Flash 在 ClawBench 得分 84.20（pass@3），ClawEval 69.49。ClawBench 上超越 Kimi-K2.5（82.20）和 Step-3.5-Flash（83.97），仅落后于 Qwen3.5-122B（85.11）。ClawEval 上落后于 Kimi-K2.5（74.90）但超越 Qwen3.5-122B（68.20）。PinchBench 74.90，落后于更大的 Kimi-K2.5（79.60）和 Qwen3.5-122B（80.60），但领先所有同规模模型。

### 5.2 专家训练与 MOPD 融合的效果

推理。推理 RL 专家将 LiveCodeBench-V6 从 79.39（SFT 基）提升到 80.23。MOPD 融合后达到 80.12，与专家持平。消融实验显示，从 MOPD 教师池中移除推理专家会导致推理基准下降 2–4%，证实该专家是防止多域融合中能力退化的关键锚点。

通用。通用 RL 专家较 SFT 基带来显著提升，IFBench 从 72.79 升至 82.65（+9.86），IFEval 从 92.42 升至 94.64。MOPD 融合后增益完全保留：融合模型 IFEval 94.84、IFBench 82.92、LexInstructEval 75.63，匹配或略超专家，证实多教师蒸馏在该轴无稀释。

智能体。智能体 RL 专家较 SFT 基在各自任务上提升：代码智能体专家 SWE-bench Verified 达 73.80（+4.80），Claw 智能体专家 PinchBench 77.10（+2.79）。MOPD 融合后 SWE-bench 保留大部分增益至 71.10（差距 2.7 分，反映多域蒸馏中保留高度专门的长周期行为的挑战）。有趣的是，MOPD 融合模型在 ClawBench（83.20 vs 80.30）和 ClawEval（70.35 vs 67.23）上超越单个智能体专家。我们归因于跨域迁移：工具使用、指令遵循、推理专家的能力补充了 Claw 智能体专家，提供更强的通用推理，有益于开放自主任务。

总结。三条轨道上观察到三种不同的融合结果：（1）推理的能力锚定，专家防止融合中退化；（2）通用的完全保留，融合模型匹配专家；（3）智能体的混合结果，SWE 上部分保留、OpenClaw 上正向迁移。这验证了 MOPD 设计：与混合 RL 训练典型的跷跷板退化不同，来自路由专家的同策略蒸馏以最小干扰、偶尔协同的方式整合多样能力。

### 5.3 Token 效率（HMPO）

图 14 在 AIME'26 上绘制准确率与每条轨迹平均 token 数的关系。除自我提升外，Mach-Mind-4-Flash 从根本上重塑了相对大得多的前沿模型的帕累托前沿。它决定性超越 Nemotron-3-Super-120B-A12B（89.90% @ 13.4K），并与巨型模型 Kimi-K2.5-1T-A32B（93.30% @ 16.6K）高度竞争。这表明 HMPO 使推理模型能显著超越其重量级，以极小的前沿推理成本交付顶级数学性能。

## 6 Limitation and Future Work

在本工作中，我们提出了 Mach-Mind-4-Flash，一个通过「先专业化后整合」后训练流水线达到前沿级性能的 35B MoE 模型。其能力主要来自三方面：Qwen3.5-35B-A3B 提供的强初始化、支持并行专家开发与算子级加速的可扩展训练基础设施，以及将异构专家能力整合为单一可部署模型而无混合奖励 RL 跷跷板退化的多教师同策略蒸馏。

在将紧凑模型推向万亿参数级性能的努力中，我们识别出若干剩余挑战。第一，MOPD 融合在极长周期任务（如仓库级软件工程）上引入小而一致的差距，此类脚手架特定行为在蒸馏中被部分平滑。第二，token 效率方法（HMPO）目前针对单轮推理；将预算感知压缩扩展到多轮智能体轨迹——模型须在数十个工具调用轮次间分配精力——仍是个开放问题。第三，持久多约束网页浏览（深度搜索）与长上下文理解仍是紧凑模型最弱的轴，表明仅扩展智能体周期不够，还需提升模型在超长交互中维持连贯状态的能力。未来工作将聚焦智能体场景的轮次感知 token 效率、更好保留长周期专家行为的蒸馏策略，以及在同一后训练框架内启用视觉定位与 GUI 交互的多模态扩展。
