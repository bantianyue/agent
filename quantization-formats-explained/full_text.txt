Folks here have probably heard that quantization means lowering precision, but FP8, INT4, NVFP4 and the rest still confuse a lot of people. it scared me too ngl :( So this post is a simple map of what each one actually means and how quantization is actually done.

So let's start with a basic idea: a model is basically just billions of numbers. And every number is stored in a particular format, like FP32 or BF16. So for starters, refer this map:
- FP32 = 32 bits per value
- BF16 = 16 bits per value
- FP8 = 8 bits per value
- INT8 = 8 bits per value
- INT4 / FP4 = 4 bits per value

So lets say we have a model of 100B parameters, so just for the weights we have (Approx):
BF16 = 200 GB
8-bit = 100 GB
4-bit = 50 GB
(raw weight storage, ignoring scales/metadata)

Let me explain the calculation for BF16 here. If 1 parameter is 16 bits, thats 2 bytes per parameter. so : 100 billion x 2 bytes = 200 billion bytes = 200 GB (approx). Similarly, do this for 8 bit and 4 bit and you would get the above answers.

So you could say fewer bits means less memory occupied and less data that has to be moved around the GPU. But not everything about this looks good since now every parameter is represented by fewer bits, we lose some precision and this is where the quantization problem starts.

So what does quantizing a number actually mean? In simple words, quantization means representing values using lower precision so they take less memory and can often be processed more efficiently.

Lets understand this with the help of an example: Lets say some weights are stored at higher precision as: [-0.82, -0.31, 0.17, 0.58, 0.91] now suppose we want to quantize them to signed INT4. INT4 can only store a small set of integer values, roughly: (-8 ... 7) so first we choose a scale. so for a simple symmetric example: scale = max(|weights|) / 7 => scale = 0.91 / 7 = 0.13 (approx)

So like this divide every weight by that scale and round and we would get something like (approximate values):
-0.82 / 0.13 = -6
-0.31 / 0.13 = -2
0.17 / 0.13 = 1
0.58 / 0.13 = 4
0.91 / 0.13 = 7

So now our weights look like this: [-6, -2, 1, 4, 7] + scale 0.13

So here we say we have quantized weights to lower precision. but the best part is we can use the scale (0.13) to approximately recover the original weights. and its very simple. Just multiply it with the scale value. In this example its 0.13
So we get something like:
-6 x 0.13 = -0.78
-2 x 0.13 = -0.26
1 x 0.13 = 0.13
4 x 0.13 = 0.52
7 x 0.13 = 0.91

But you can see there is a small difference between the actual original numbers and the computed original numbers and we call it quantization error. So so quantization is not just "cutting decimal places" but it is mapping high-precision values into a much smaller set of representable values, then using a scale to approximately recover their original magnitude.

Now the main question, what does these quantization types mean and how to remember them? Learn this framework that makes most quantization names much easier. Whenever you see one, ask these 4 things:
1. what is being quantized? - weights? - activations? - KV cache?
2. what numerical format is used? - FP8? - INT8? - INT4? - FP4?
3. how is it scaled? - one scale for everything? - per group? - per block?
4. how did we get the quantized model? - PTQ? - QAT? - AWQ? - GPTQ?
almost every scary term fits somewhere in this map.

Now lets learn some of the common names:
1. W8A8 / W4A16 (W = weights, A = activations). W8A8 = 8-bit weights + 8-bit activations. W4A16 = 4-bit weights + 16-bit activations
2. FP8 vs INT8. INT8 = integers + scale; FP8 = floating point with 8 bits. So the basic difference is the data type, one is int other is float.
3. What is per-tensor / per-group / per-block? This simply tells you how many values share one scale. one tensor = shares one scale; small group = shares one scale; small block = shares one scale
4. NVFP4. It is NVIDIA's 4-bit floating-point quantization format with fine-grained block scaling. So it's not a completely different idea, just FP4 values combined with a specific scaling strategy to preserve accuracy better.

What is AWQ / GPTQ / PTQ / QAT? These are not formats like FP8 or INT4. AWQ / GPTQ -> post training quantization methods. PTQ / QAT -> broader ways of applying quantization.

So the easiest way to remember everything:
FP8 / INT4 / FP4 -> format
W8A8 / W4A16 -> what gets which precision
per-group / per-block -> scaling
AWQ / GPTQ / PTQ / QAT -> quantization method
