JetSpec：用并行树状草稿打破投机解码的扩展天花板

摘要
投机解码（SD）通过并行起草多个 token 并验证来加速自回归大语言模型，但它面临扩展瓶颈：只有当接受率保持高位且起草开销保持低位时，增加草稿预算才能提升速度。这个天花板难以突破，因为已有的基于 head 的 SD 方法面临因果性-效率的困境。自回归 drafter 产生路径条件化的候选，对树状投机解码有效、接受长度更高，但起草成本随树深度增长。双向块扩散 drafter 一次生成所有位置，但其分支不可知的边缘分布会形成各自合理但相互不一致的树，浪费预算并降低接受率。我们提出 JetSpec，一个基于 head 的 SD 框架，将一次性前向起草的效率与分支级因果条件结合起来。JetSpec 用冻结目标模型的融合隐藏状态训练一个因果并行草稿 head，产生分数与目标模型自回归分解对齐的候选树。这使 JetSpec 能把更大的草稿预算转化为更长的被接受前缀和更高的端到端加速。在 dense 和 MoE Qwen3 模型的数学、代码、对话基准上，JetSpec 一致优于双向 head 和基于树的 SD 基线。在 H100 上，JetSpec 在 MATH-500 上达到 9.64× 加速，在开放式对话负载上达到 4.58×，并通过 vLLM 集成在真实服务负载下展示进一步延迟收益。

1 引言
现代自回归 LLM 的解码基本是串行的，使延迟成为主要挑战。现有方法要么在预训练/中训练中加入多 token 预测（MTP），要么用后训练把预训练 LLM 适配为扩散 LLM（带来性能下降），要么在推理时应用投机解码（SD）降低延迟且保持质量。
SD 因适配成本低、简单而突出。基于 head 的方法如 Medusa、EAGLE 避免独立的 draft-target 模型设置，降低部署复杂度。更新的 EAGLE-3、DFlash 继续提升起草质量和降低成本。但 head-based SD 仍面临因果性-效率困境：自回归 drafter（如 EAGLE）产生高质量路径条件候选，但树深度增长时需要串行起草；双向块扩散 drafter（如 DFlash）一次生成草稿，但分支不可知的边缘分布会形成各自合理却相互不一致的树，浪费预算、降低接受率。
我们提出 JetSpec，训练一个因果并行草稿 head，在一次前向中预测多个树节点，同时通过基于隐藏状态的块级因果注意力保留分支级因果条件。这让每个分支获得与目标模型自回归分解对齐的路径条件起草分布，使树接受率随草稿预算增加更好地扩展。
实证上，低预算（16 draft token）JetSpec 有竞争力；高预算（256 draft token）JetSpec 增益强，MATH-500 达到 τ=10.7 和 9.5× 加速，MT-Bench 上 τ=5.9、超过 4×。集成到工业级服务引擎后，在小到中等服务负载下一致优于基线，在 B200 等高端 GPU 上增益尤其强。

2 JetSpec
2.1 背景
SD 中轻量近似模型 Mq 先提议 N 个草稿 token，目标模型 Mp 并行验证，接受与自身预测一致的最长前缀，从首个被拒 token 续算。实际吞吐依赖接受率和相对起草成本。标准 i.i.d. 接受假设下，每次投机迭代期望推进 token 数 = (1-α)N+1/(1-α)，端到端加速 = (1-α)N+1 / ((1-α)(Nc+1))。这暴露关键扩展瓶颈：增大草稿长度 N 仅当接受率 α 高且累计起草开销 Nc 小时才提升吞吐；N 增长时 α 的轻微下降或不可忽略的起草成本会迅速抵消并行验证收益。图2表明同时降低起草成本和提升接受质量对解锁更长草稿的有利扩展至关重要。
已有工作分别改进这两项。提升 α：draft-model 对齐方法改进 Mq 与 Mp 一致性。树状 SD（SpecInfer、Medusa、EAGLE）通过并行展开验证多候选分支提升验证效率。降低 c：head-based 方法避免独立部署 draft 模型；DFlash 用块扩散式起草一次生成多 token，把每 token 起草成本压到极低。但更长草稿扩展要求同时高 α 和低 c，这正是 JetSpec 联合优化的动机。

2.2 Head-based 因果并行起草
能否两者兼得：自然方向是结合树起草（高接受）与并行起草（低成本）。但现有并行起草（如 DFlash）会破坏有效建树所需的因果结构：独立预测的未来位置不条件于各分支上选定的 token，导致不一致的续写。JetSpec 训练因果并行草稿 head，在保留并行预测效率的同时保留分支级依赖。
为何因果性重要：并行树起草的关键要求是每个节点分布条件于其自身分支前缀。没有因果条件时，建树按伪分布 qsur ∝ ∏ r_i(y_i|x) 排序分支，其中 r_i 是位置 i 上分支不可知的起草分布。这样建树会偏好 token 各自合理但相互不一致的续写。验证通过拒绝无效前缀保持无损，但树本身在 qsur 而非因果有效起草分布下优化，导致更低接受率。
架构：JetSpec 采用 head-based 起草架构，草稿 head 复用目标模型丰富中间特征且保持起草廉价。DFlash 表明轻量块并行草稿 head 能复用目标模型隐藏状态并将融合目标上下文特征注入草稿层 KV cache 以获得强引导。JetSpec 在此基础上引入因果并行解码 head 做树起草。
给定前缀 x 及融合隐藏状态特征 h_x^o，草稿 head 并行预测多个活动树节点的 logits。目标模型定义长度 k 续写的自回归分布 p(y1:k|x)=∏ p(y_i|x,y_<i)。为让并行起草与该因果分解对齐，对草稿 head 施加树因果注意力掩码：每个节点可注意原始前缀及其祖先，但不能注意后代或无关兄弟分支。掩码 M_v,u = 0 若 u∈Anc(v)∪{v}，否则 -∞。这允许所有树节点并行处理，同时每分支遵循类自回归依赖结构，诱导出分支级起草分解 q(π(v)|x)=∏ q(y_u|x,h_x^o,π_<u)，与目标模型自回归分解镜像对应，但每个草稿节点条件于其自身路径上的具体祖先 token。相比式3的分支不可知块扩散起草，这让起草分布更对齐自回归 Mp，同时仍允许所有树深度的 logits 并行计算。

2.3 训练
数据准备：在目标对齐序列上训练草稿 head，序列来源可以是训练语料（如 MTP），或目标模型重新生成的续写。对序列 (x, y1:k)，采样锚点位置，在每个锚点构造长度 N 的训练块（N 个连续未来位置），草稿 head 在块因果掩码下并行预测这 N 个位置，匹配目标模型在同一真实前缀上产生的逐位置 teacher logits。
蒸馏损失：用软标签蒸馏目标，使起草分布保留目标模型跨多合理续写的相对偏好。forward KL 鼓励覆盖目标模型概率质量，保留 top 预测之外的软标签信息；reverse KL 更 mode-seeking，把概率集中到高置信 teacher 模式。实践中 reverse KL 大幅落后，forward KL 略优于硬标签 SFT，故默认采用 forward KL。对每个活动起草位置 m，定义温度归一化分布 q~(m)=softmax(z_q(m)/T_KD)、p~(m)=softmax(z_p(m)/T_KD)，最小化 forward KL L_FKL(m)=D_KL(p~(m)∥q~(m))。最终目标按活动位置掩码归一化，T_KD>0 为蒸馏温度。

2.4 起草与验证
并行树起草：每个解码步 i，因果草稿 head 条件于上一步验证接受的 token 隐藏状态 h_x^o，构造最大深度 N、分支宽度 W、总节点预算 B 的候选树。一次草稿 head 前向得到所有深度的 logits，提取每深度 top-W 候选 token。树扩展由分支评分函数 s(π(v)) 驱动，默认用累计草稿对数概率：s(π(v))=∑ log q(y_u|x,h_x^o,π_<u)。反复弹出最高分可扩展节点，用至多 W 个子节点展开，更新分数后重新插入，直到预算填满或无节点。得到候选树 T(x)。
树验证：构造候选树后，目标模型 Mp 用树注意力并行验证所有节点。验证者沿每条候选分支应用 SD 接受规则。非贪婪 SD 用拒绝采样：α_t=min(1, p(y_t|x,y_<t)/q(y_t|x,y_<t))，拒绝时采样目标模型修正 token。接受前缀长度 a=max{r≤k: A_t=1, ∀t≤r}。贪婪设置下 A_t 确定化：草稿 token 与目标模型同上下文下下一 token 预测一致则接受。

3 实验
3.1 实验设置
模型与数据集：在 Qwen3-8B 和 Qwen3-30B-A3B（dense 和 MoE）上评估，主评估用非思考模式。训练数据从 Nemotron Post-Training Dataset V2 精选 780K 样本（含全部代码和数学切分、STEM 和 chat 的随机样本、20K CodeAlpaca），对重新生成的训练序列用对应 chat 模板由目标模型续写。评估数学（GSM8K、MATH-500、AIME25）、代码（HumanEval、MBPP、LiveCodeBench）、开放式对话（MT-Bench）。消融在 Nemotron V2 数学切分上进行。
基线与训练设置：对比 EAGLE-3 和 DFlash。DDTree 用 DFlash 的逐位置块扩散分布通过 best-first 树扩展建树，但用无损失加权的纯块扩散 head。为公平，JetSpec 与所有基线在相同数据混合上训练，学习率 3e-4，8×H100。
实现细节：离线推理在 8×H100 或 B200，表2用优化 Triton 核。服务引擎评估把 JetSpec 集成进 vLLM，含用 NVIDIA CuTe DSL 的自定义 SM90 paged FlashAttention 核（共享内存树掩码暂存与树尾掩码）。

3.2 结果
低预算：相比自回归起草基线 EAGLE-3，JetSpec 在每个预算上都明显更高加速，避免了 EAGLE-3 更高的串行起草开销。预算16时 DFlash 与 JetSpec 几乎相同（短线性草稿已足以覆盖多数高概率续写）。预算增至32时 JetSpec 略有提升，DFlash 常饱和或下降，说明 JetSpec 把额外草稿预算转化为被接受 token 更有效。
高预算：表2中随草稿预算增大，JetSpec 增益更大，数学和代码基准从约 4-6× 提升到 7-10×。DDTree 更温和地扩展到至多 9×，表明因果树起草比分支不可知建树有更高接受率。温度1下 JetSpec 仍有效，说明因果树起草在非贪婪解码下收益稳健。

3.3 系统性能
把树起草与验证集成进 vLLM 评估端到端服务。服务性能不仅依赖接受长度，还依赖树预算与批处理、验证开销、内存流量、GPU 占用的交互。大预算可减少目标模型验证轮数，但引入更高草稿 head 与树验证成本，使最优预算依赖负载。
预算分配：表11显示大预算在批大小1时最有用。批大小1时预算16→128，吞吐从443.3升至968.2 TPS，加速从3.09×升至6.75×。随批大小增大收益递减：预算256在批大小16降到4.51×，批大小32降到2.85×，接近预算128，出现饱和。
实际含义：树预算应按服务负载选择。低到中负载用大预算，重负载用较小或中等预算更高效。

3.4 消融
除非注明，消融在 4×B200、块大小16、目标正常前向用 FlashAttention-2、Triton 树注意力、累计草稿对数概率启发式（式10）、节点预算255。
学习率：网格搜索 5e-5 到 1e-3。极小学习率落后，3e-4 达到峰值（8.30×），6e-4 与 1e-3 在峰值 2% 内。
损失：SFT 与 forward-KL 蒸馏在各数据集相差 ~3%，reverse-KL 相比 forward-KL 有 36-46% 相对下降，说明 mode-seeking 目标把草稿概率质量集中过激，不适合树起草。
模型泛化性：Qwen3-30B-A3B（MoE）上 JetSpec 保持更高加速，表明因果树起草超越 dense Qwen3-8B 泛化。
训练数据：目标模型重新生成的续写提供最强性能，确认让草稿 head 匹配目标模型自身生成对最大化接受长度重要。JetSpec-Corpus 直接在语料序列上训练，落后但仍一致加速，说明因果并行起草可纳入中训练甚至预训练。

3.4.2 扩散 head 的树起草
表7比较因果 head 与扩散 head 在不同 γ（控制 DFlash 目标对远离锚点位置逐位置损失的降权程度）下。因果 head 对各种 γ 稳健；扩散 head 对 γ 敏感，在端点崩塌（γ=7 时 8.36×，γ=0 时 5.46×，γ=15 时 6.17×）。
失败例子：MATH-500 prompt 0 解码步0，扩散 head（γ=0）把" given told that"排第一（累积草稿代理 -3.76，但累积目标条件 -63.32 nats），该分支结合两个互斥开场，是式3 qsur 失败模式的典型。真正连贯的" are given that the"（目标联合 -0.08）排第3。因果 head 在同 prompt 把" are told that"排第一，代理≈目标联合。
