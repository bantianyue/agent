要点速览

- 固定状态：线性注意力把 unbounded 历史压缩进一个固定尺寸的矩阵，读写成本恒定，但会损失信息。- 干扰根源：固定尺寸下，重叠的 key 会互相串扰：这恰恰是整个家族所有改进都在对抗的唯一限制。- delta 规则：给旧 key 换新 value 时，先读旧值、减去、再写新值，只改目标槽位、不动其他事实。- 并行训练：分块 + 一次小的三角求解，把看似串行的 delta 更新变成纯 matmul，可大规模并行。- 三层精炼：标量衰减 → 逐通道衰减(KDA) → 解耦擦除/写入门(GDN-2)，逐步给编辑更细的控制。- 部署现实：纯线性注意力难以完全替代 softmax，实际多为混合架构(Qwen3-Next/Kimi Linear/MiniMax-01)。

线性注意力把记忆压缩进一个固定尺寸的矩阵。真正的难点，是在不搅乱其他内容的前提下编辑它。
这篇长文从最基础的线性代数讲起，把 DeltaNet、Gated DeltaNet、KDA 一直到最新的 Gated DeltaNet-2 串成同一条主线：如何让对压缩记忆的「写」变得像手术刀一样精准。

我们说的到底是哪种记忆
在语言模型里，「记忆」一词至少指三件不同的事。本文只关心其中一种。
其一是权重。即查询/键/值投影矩阵与各个门控，在训练中习得、之后固定。这是长期知识，只有通过继续训练才能改变，不是本文讨论的对象。
其二是 KV 缓存(softmax)。它是所有历史键与值的完整列表，任何查询都能精确回看过去。无损、随上下文增长、每个序列重置。线性注意力正是要移除这一层。
其三是循环状态(线性注意力)。一个固定尺寸的矩阵，汇总了截至目前每个 token 的信息。有损、尺寸固定、每个序列重置。这才是我们所说的记忆。
所以这是上下文内记忆：在单次前向传播中容纳当前输入，让第 5000 个 token 能用上第 3 个 token 说过的东西。新 prompt 进来，状态清空，什么都不保留。它不是检索/RAG，不是持续学习，也不是「跨会话记住你」；它就是普通注意力用 KV 缓存干的活，只不过被压缩进一个固定矩阵，而非不断增长的列表。
状态从何而来
每个 token 都有一个表示向量，三个固定的习得矩阵把它变成查询(query)、键(key)和值(value)。
键是 token 的「地址」，代表它关于什么；值是存放在那里的「内容」；查询是当前 token 在「要什么」，拿它去和各个键匹配，决定取出什么。一个 token 以键-值对的形式写进记忆，之后用查询来读。这些向量取决于输入，但三个投影矩阵是固定权重，在所有位置和所有序列间共享。
普通注意力把每个输出算成过去所有键-值对的 softmax 加权和。
正是那个指数强制你保留缓存。打分 exp(查询·键) 无法拆成「只依赖查询的部分」乘以「只依赖键的部分」，所以每个值的权重都和它那个特定的键绑死，归一化项要对每个历史键求和。不存在可以替代的「运行摘要」：你必须存下每个键-值对，并对每个新查询重新访问它们。这就是 KV 缓存：记忆随序列长度线性增长，算出所有输出的复杂度随它平方上升。
线性注意力丢掉 softmax，改用可分解的打分，最简单的情况就是查询与键的点积。一旦可分解，求和就可以重排。
全部历史塌缩进一个固定尺寸(键维度 × 值维度)的矩阵，查询用它一次矩阵乘就能读出。记忆不再随上下文增长，每个 token 的成本是常数。这个固定状态就是本文其余部分的主角；它之所以存在，恰恰是因为 softmax 消失了。
固定尺寸既是吸引力，也是问题。把无限历史塞进一个矩阵很便宜，但也意味着许多事实共享同一片有限空间。下一节看看这对「读」意味着什么。
为什么固定尺寸记忆会互相干扰
我们已经有了固定状态。在往里写之前，先看看读它能得到什么。读，就是把一个查询作用到记忆上。
每个被存的值，按它的键与查询的对齐程度(两者的点积)加权。这就是「按内容寻址」的回忆：键和你问的相匹配的值，按匹配度被加权取出。
为了暴露问题，取最干净的一种查询：它恰好等于你已存下的某个键。这本来应该完美返回它的值，所以任何混乱都是记忆的错，不是查询不匹配。把那一项单独拆出来。
如果存下的键彼此正交，每个交叉项都是零，读就是干净的。但事实并非如此。每一个非零重叠都会从别的某个值里漏进一小份到答案里。而它们无法全部正交的结构性原因在于：状态只是一个矩阵，所以键空间的维度最多只有键向量那么宽，而这个维度的空间最多容纳同样多个互相正交的方向。要存的关联数超过它，就必然有些键要共享方向；即便没到上限，随机的单位键之间也有虽小却非零的重叠，会累积起来。
随着上下文承载的关联越来越多，你想要的那一项大小基本不变，而泄漏项是所有其他项的求和，所以它在增长。信噪比随上下文长度下降：长文档迫使许多不同事实共享同一个固定盒子，于是它们糊在一起。这正是整个家族在长文本、多针检索上吃力，而下面的各种改进都瞄准这个压力点的原因。
为什么 softmax 没有这个问题
泄漏并不是把求和折进状态矩阵造成的。求和形式与矩阵形式算出来是同一个数；折叠只固定了尺寸和成本，不改变数值。泄漏在原始的点积打分里就已经在了。
softmax 把同样的点积送进指数再归一化。指数把它们「 sharpen」：匹配的键饱和到接近 1，不匹配的键被压向 0，于是即便键有重叠，错误的值也基本从读里掉了出去。同样的重叠，干净的答案。
但那恰恰是无法被摘要的性质。点积的指数拆不成「查询部分 × 键部分」，所以没什么可以预计算：你被迫保留每个键，并对每个键重新算指数，这就是那个不断增长的缓存。所以这是二选一：锐利的打分读得干净，却无法折进固定状态；而可折叠的打分给了你固定状态，却会泄漏。干扰不是压缩的代价，而是使用「弱到能被压缩」的打分的代价。
当某个键回来，要更新它的值
模型读序列时，后面的 token 有时会产出一个键，接近前面某个 token 已写过的键，却带着不同的值。状态在那个方向上已经有一个绑定，新值应该取而代之。这就是「更新」情形，也是普通外积记忆搞错的地方。
举例：一段文字设 x = 5，后面又设 x = 7。两个 token 产出的键几乎相同(代表「x 的值」这个方向)，但值不同。当后面的 token 读 x，答案应该是 7。普通加法做不到：它从没移除旧绑定，于是这个槽同时装着 5 和 7，读出来是一团混合。只要一个键带着新值重现，就是同样的形状：状态变化的实体(「Alice 在巴黎……现在到了东京」)、更正(「蓝色……其实是绿色」)、被修改的表单字段。
两点澄清，因为「更新」可能误导。prompt 本身是固定的；前向传播只从左到右读它，「更新」指的是更靠后的位置的绑定应当胜过更靠前的。文字里的「x = 5」依然在那里；只是它不该赢得这次读。而且键不是按名字匹配的：两个 token 是「同一个键」，当且仅当它们的键向量指向大致相同的方向，于是它们的写落在状态的同一处。一次重复提及产生一个相近的键，后面的写命中那个槽，之后的读应该反映新值。
所以每次写都是两种情形之一。Add(新增)：键指向某处全新的地方，一条新事实，大多数 token 都是如此；普通累加就够了，这也是 vanilla 线性注意力做的。Overwrite(覆盖)：键落在状态里已有的方向上，这个槽必须被更新成新值，而不是堆在旧值上面。
为什么不直接替换整个矩阵
因为状态被所有关联同时共享。下面用三种方式，把一个键的更新写进一个同时还存着第二条事实的记忆。
用新的键-值外积替换整个矩阵：目标键修得完美，却删掉了其他所有人。之后读第二个键，你得到接近零。你想改一个槽，却把整个笔记本擦了。
把新的外积加上去：保住了第二条事实，却把旧绑定留在原地，于是读目标键会返回「旧+新」，陈旧的值被抹进了新鲜的值里。
Delta(增量)：先读这个键当前指向什么，只减去那个，再写新值。只有目标槽变了；另一条事实毫发无损。
Add 保住另一条事实却把目标弄糊；Replace 修好目标却抹掉另一条事实。只有第三种(读、减、写)两者都对。这第三种就是 delta 规则。

读一个已存的键，返回它的值，外加从每个其他键漏进来的一小份。想要的那一项大小不变，而泄漏是对其他所有项的求和，所以随着更多事实共享固定状态而增长。
delta 规则
做到这一点的更新就是 delta 规则(Widrow & Hoff, 1960)，在 DeltaNet(Yang et al., 2024)里被用于线性注意力。它写新值是相对于已存内容，而不是绝对地写。先读记忆当前对这个键返回什么。
这就是此刻坐在那个键方向上的任何东西。我们不必预先知道这个键以前是否被用过；只需把它读回来。然后把这个槽从旧值朝目标移动一个比例 β(写入强度)。
方括号里是新值与旧值之间的差，把它加回去，就把该键处存的值推向目标。一次更新无需分支就覆盖了两种情形：若键指向某处新地方，读出来约为零，差就只是新值，于是退化成普通 add；若键落在已经存了值的方向上，读返回那个旧值，更新就减去它、把新值写进它的位置。是记忆自己告诉规则它处在哪种情形。
把修正项乘开，看它对整个状态做了什么。
第二项沿着键写入新值。第一项移除状态沿该键所存内容的 β 比例，而且只沿该键：向键方向的投影，让一切与之正交的部分原封不动。这正是上一节那个 widget 里，替换整个矩阵会抹掉旁观者、而 delta 更新不会的原因；它只编辑那一个键在状态里的那一行。
为什么 β 不干脆等于 1
写入强度为 1 就是硬覆盖：彻底擦掉旧绑定，写入新值。那为什么不处处都用它？β 由模型按 token 产生，有两件事反对把它钉死在 1。真实的键并非严格正交，所以沿一个键硬擦，也会扰动部分共享其方向的邻居，更小的 β 带来更温和的编辑、更小的连带损伤。而且并非每次写都该完全替换：有时正确的做法是轻推一个值、累积证据，或在不确定时弱写。所以 β 在 0 到 1 之间是一个旋钮：1 是覆盖，0 是留着不动，中间是部分移动。(在在线学习视角下，它是每步的学习率，而处处为 1 的速率很少是你想要的。)
有一点要注意，下一节那个 widget 会讲具体：干净的覆盖只在键与其他键正交时才精确。当键重叠时，沿一个键编辑会拖拽任何共享其方向的东西，还是之前那种干扰，现在出现在了「写」里。
并行地训练它
训练需要整条序列上每个输出一次性拿到，然后才求梯度。普通线性注意力很便宜地给出它们，因为状态是个运行求和，所以输出塌缩成两次矩阵乘(配合把未来清零的因果掩码)。
为什么快：全是稠密 matmul，GPU 在它的张量核上把一次 matmul 跑成成千上万个乘加并行，每个输出位置同时计算。没有谁等谁。
delta 规则打破了这一点。它的擦除因子(就是上面算子形式里的那个)让每个状态真正依赖前一个，所以你没法把答案写成独立项的一次求和。照字面做，你就得一个 token 一个 token 地处理，每次都是一次微小的秩一更新，只用上 GPU 的一小条，其余都空闲。
DeltaNet 的贡献(Yang et al., 2024)是用分块(chunk)恢复 matmul 形式。一个 chunk 是 C 个连续 token 组成的一段；长度 L 的序列被切成 L/C 段。昂贵的工作发生在一个 chunk 内部，全是 matmul，只有一小份摘要状态从一段传往下一段。

两种记住序列的方式。Softmax 保留一个不断增长的 KV 缓存，每个 token 一行键-值；线性注意力保留一个固定尺寸的矩阵，每个 token 都写入其中。缓存随长度扩展；矩阵不会。

用三种方式更新一个键。Add 让旧值混进新值；替换整个矩阵修好了目标却毁掉了其他所有事实；delta 规则只编辑目标槽，其余原封不动。
诀窍：解出那些真正被写入的值
每一步都加一个秩一项，其左因子是键，所以状态永远是起始状态加上每个 token 一项这样的项。
这里被写入的值不是原始值，而是 delta 规则的修正(目标减旧值，乘 β)。键是已知的；这些被写入的值才是未知量。关键在于：如果我们可以一次性拿到一个 chunk 里所有的它们，用一次矩阵求解而非逐 token 地走，整个 chunk 就变成并行 matmul。所以我们联合求解它们。
每一步的被写入值依赖于当前的读，而那个读可以展开成已知键和更早的被写入值。
换句话说：拿状态到目前为止对一个键的读，等于起始状态读，加上每个更早的被写入值乘上它的键与当前键的重叠度。代入后，得到只关于被写入值自身的关系。
每个被写入值只依赖更早的那些，这就成了一个三角系统。把被写入值堆成一个矩阵，把两两键重叠收进矩阵 T，整组方程就变成一次求解。
因为被求逆的矩阵是单位下三角的，其逆就是在一个小的 C×C 矩阵上做一次前向代入。其余全是稠密 matmul：从两两键点积建出重叠矩阵，再形成传递状态和输出。
那个串行的 token 循环消失了，取而代之的是 matmul 加上一次小的三角求解。把秩一因子的乘积写成单个低秩更新，是数值线性代数里的经典手法，即 WY 表示(Bischof & Van Loan, 1985)及其 UT 变换变体(Joffrain et al., 2006)；DeltaNet 借用它把 chunk 折进矩阵运算。
为什么 chunk 尺寸很小
chunk 尺寸决定了状态交接的频率：共有 L/C 个 chunk，也就是那么多次串行状态更新。两个极端让这点很具体。一个 chunk 只有一个 token，就是原本完全串行的递归。一个 chunk 覆盖整条序列，就是一次交接，在一个并行块里完成。(这和听起来的相反：更大的 chunk 意味着更少、更大的步，而不是更多。)
那为什么不用一个巨型 chunk、全并行？因为 chunk 要建并求解一个 C×C 矩阵，所以成本和显存随 chunk 尺寸平方增长。到了全长，你又回到了全注意力的平方成本，而那个矩阵也不再装得进 matmul 引擎读取的片上高速内存。太小，则你要付太多串行步、且每个 matmul 都喂不饱。内核实际用 64。
加入衰减：Gated DeltaNet
到这里为止都是 DeltaNet：一个固定尺寸的关联记忆，由 delta 规则编辑，并行训练。最后三节是精炼，每个都加一点表达力，却保持分块算法不变。
delta 规则一次只覆盖一个槽，却无法让旧上下文自己淡去。Gated DeltaNet(Yang, Kautz & Hatamizadeh, 2025, arXiv:2412.06464)在每次编辑前，把状态乘上一个标量衰减。

两种记住序列的方式。Softmax 保留一个不断增长的 KV 缓存，每个 token 一个键-值行；线性注意力保留一个固定尺寸的矩阵，每个 token 都写入其中。缓存随长度扩展；矩阵不会。
追着衰减的累积乘积，一个更早的写对更晚的读的贡献，会按中间累积了多少衰减来缩放。在分块算法里，这只是对同一批矩阵做一次按行重加权，再加上因果掩码里的一个额外因子；三角求解不变。衰减加进来近乎免费。它做不到的，是以不同速率遗忘不同特征，因为它只是「一个数」。
逐通道衰减：KDA
KDA，即 Kimi Linear(Kimi Team, 2025, arXiv:2510.26692)里的线性注意力层，把那个单一衰减换成一个逐通道衰减向量，给每个键通道一个不同的遗忘率。
现在每个通道在每一步被不同地缩放，看起来应该会打破分块形式。并没有，因为一次变量替换：把累积的逐通道衰减从状态里提出来，它就在递归里消掉了，剩下一个在重加权键和擦除因子上的纯 delta 乘积。
这次替换之后，分块方程和之前形状相同；只是各项带上了衰减因子。KDA 以零结构代价换来了更丰富的遗忘。
逐通道的速率不是人手设的超参；它们是习得且依赖数据的，由一个小投影从每个 token 产生(Gated DeltaNet 的参数化：一个习得线性映射过 softplus 再过指数)。一个逐头项和一个逐通道偏置设定每个通道的基线遗忘率，逐 token 投影再把那个速率往上或往下推，于是模型既学到了典型的衰减轮廓，也学到了如何随时调制它。不过，真正的编辑仍然是一个写入强度标量，它同时缩放擦除和写入。
拆分编辑：Gated DeltaNet-2
擦除作用在键这一侧：要移除旧读的哪些坐标。写入作用在值这一侧：要保留新值的哪些坐标。这是状态的两个不同轴，所以 GDN-2(Hatamizadeh, Choi & Kautz, 2026, arXiv:2605.22791)给各自配了独立的逐通道门：键上的擦除门，和值上的写入门。
与 KDA 相比，写入方向不变(左因子仍是键)，但它所减去的读现在由擦除门做通道选择，它写入的值由写入门做通道选择。
前向：同一台机器
跑同样的变量替换，这次把擦除门折进重加权因子，递归又变成一个纯(现在是非对称)的 delta 乘积。分块流水线保持同样的形状：同样的重叠矩阵，同样的三角逆，同样的状态与输出方程。唯一的不同是填进去的东西：擦除门进入键侧的行，写入门进入值侧的行，重叠矩阵现在由一个非对称对而非对称对建出。
反向：唯一真正的区别
训练把一个损失梯度沿分块反传回去。把求解写成作用在写入值上的三角逆。反向传播需要关于那个逆的梯度，它累积成 incoming 梯度与被写入值的乘积。
整个问题就是：那个门能不能从内积里提出来。在 KDA 里，被写入值是标量乘值，所以它直接滑出来，你可以把无门的乘积当作一次 matmul 先算好、之后再缩放。
在 GDN-2 里，被写入值是逐通道的乘积，于是门坐在对通道求和的内部，没什么能提出来。
没有任何一个数乘在整个内积上；门在求和前对每个通道重新加权，所以没有任何行或列的缩放能从「无门版本」恢复出它。擦除侧也是同样的问题。于是门必须折进 matmul 自身，而不是作为之后的缩放来施加。前向几乎就是 KDA 的；反向核才是必须重写、把两个门都带进累加里面的部分，而那个「门感知的反向」就是这次拆分真正的实现成本。
把两个门都设成同一个标量，就精确退回 KDA；再把衰减也钉成标量，就得到 Gated DeltaNet；去掉衰减，就得到 delta 规则。每个模型都是「下一个、把某个门保持为标量」的版本。

并行地训练一个 chunk。在一个 chunk 内部，一切都是稠密 matmul 加一次小的三角求解；只有传递状态流向下一个 chunk，那是唯一串行的步。
这一切最终意味着什么
退一步看，这全是一个想法，分阶段展开。线性注意力把无限历史压进一个固定矩阵，快却有损。delta 规则像手术刀一样编辑那个矩阵，而不是往上堆。分块的三角求解让这个编辑能在大规模下被训练。衰减、逐通道衰减、解耦的擦除/写入门，各自给编辑更细的控制：决定保留什么、移除什么，却不放弃固定尺寸状态，也不放弃并行训练。它们没有一个能恢复 softmax 缓存的完美回忆；它们只是让压缩变得更聪明。
测出来的收益也落在这里。在 Gated DeltaNet-2 的论文里，相对 KDA 的提升在语言建模上 modest，但在长上下文、多键检索上很清楚，那正是许多关联被迫共享一个固定状态、干扰最严重的地方。消融实验对这次拆分很诚实：一个逐通道擦除门配标量写入，就恢复了大部分增益，所以擦除侧比写入侧干得更卖力。
这也是为什么纯线性注意力很少彻底替换 softmax。精确回忆往往值得那个不断增长的缓存的代价，所以大多数生产模型仍留在 softmax，而这些层出现在内存和吞吐占主导的地方：长上下文、高吞吐服务、受限硬件。常见部署是混合的：插几层全注意力或滑动窗口注意力来做精确回忆，中间夹许多便宜的线性层。近期的开源权重模型把这点讲得很具体。Qwen3-Next 和 Kimi Linear 都在每个全注意力块后叠三个线性块(一种 Gated DeltaNet 变体)，比例 3:1；MiniMax-01 也用类似模式混合 lightning(线性)与 softmax 注意力。

结语

一句话收束：线性注意力用固定矩阵换来了常数级的内存与算力，代价是干扰；从 delta 规则到 GDN-2 的一整条演进，都是在「不放弃固定状态、不放弃并行训练」的前提下，让那次对压缩记忆的写入越来越精准。对工程者的启发很直接：如果你的场景是长上下文、高吞吐或受限硬件，线性注意力层值得认真考虑；但别指望它单独替代 softmax，混合架构(少量精确注意力 + 大量线性层)才是当下最稳的落地形态。
