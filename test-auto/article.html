使用降低的精度运行推理

在 Diffusers 中运行 SDXL 只需几行代码：

from diffusers import StableDiffusionXLPipeline

## Load the pipeline in full-precision and place its model components on CUDA.
pipe = StableDiffusionXLPipeline.from_pretrained("stabilityai/stable-diffusion-xl-base-1.0").to("cuda")

## Run the attention ops without efficiency.
pipe.unet.set_default_attn_processor()
pipe.vae.set_default_attn_processor()

prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"
image = pipe(prompt, num_inference_steps=30).images[0]

但这并不实用，因为生成一张 30 步的图像需要 7.36 秒。这是我们的基线，我们将逐步尝试优化。

这里，我们以全精度运行 pipeline。通过使用降低的精度（如 bfloat16），我们可以立即缩短推理时间。此外，现代 GPU 配备专用内核，可利用降低的精度加速计算。要在 bfloat16 精度下运行 pipeline 的计算，我们只需在初始化 pipeline 时指定数据类型：

from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
	"stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.bfloat16
).to("cuda")

## Run the attention ops without efficiency.
pipe.unet.set_default_attn_processor()
pipe.vae.set_default_attn_processor()
prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"
image = pipe(prompt, num_inference_steps=30).images[0]

通过使用降低的精度，我们能够将推理延迟从 7.36 秒缩短至 4.63 秒。

关于使用 bfloat16 的一些说明

使用降低的数值精度（如 float16、bfloat16）运行推理不会影响生成质量，但能显著改善延迟。

与 float16 相比，使用 bfloat16 数值精度的优势取决于硬件。现代 GPU 代次倾向于支持 bfloat16。

此外，在我们的实验中，与 float16 相比，bfloat16 在与量化结合使用时表现出更强的鲁棒性。

（我们后来在 float16 下运行了实验，发现最新版本的 torchao 不会因 float16 引发数值问题。）

使用 SDPA 执行注意力计算

默认情况下，当使用 PyTorch 2 时，Diffusers 使用 scaled_dot_product_attention (SDPA) 执行与注意力相关的计算。SDPA 提供了更快、更高效的内核来运行密集的注意力相关操作。要运行 SDPA 流水线，我们只需不设置任何注意力处理器，如下所示：

from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
	"stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.bfloat16
).to("cuda")

prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"
image = pipe(prompt, num_inference_steps=30).images[0]

SDPA 带来了显著的性能提升，从 4.63 秒降至 3.31 秒。

编译 UNet 和 VAE

我们可以通过使用 torch.compile 让 PyTorch 执行一些底层优化（例如算子融合和通过 CUDA graphs 启动更快的内核）。对于 StableDiffusionXLPipeline，我们编译去噪器 (UNet) 和 VAE：

from diffusers import StableDiffusionXLPipeline
import torch

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.bfloat16
).to("cuda")

## Compile the UNet and VAE.
pipe.unet = torch.compile(pipe.unet, mode="max-autotune", fullgraph=True)
pipe.vae.decode = torch.compile(pipe.vae.decode, mode="max-autotune", fullgraph=True)

prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"

## First call to `pipe` will be slow, subsequent ones will be faster.
image = pipe(prompt, num_inference_steps=30).images[0]

使用 SDPA 注意力并同时编译 UNet 和 VAE 可将延迟从 3.31 秒降低至 2.54 秒。

关于 torch.compile 的说明

torch.compile 提供不同的后端和模式。由于我们追求最大推理速度，因此选择使用“max-autotune”的 inductor 后端。“max-autotune”使用 CUDA graphs 并专门针对延迟优化编译图。使用 CUDA graphs 可大幅减少启动 GPU 操作的开销。它通过一种机制，用单个 CPU 操作启动多个 GPU 操作，从而节省时间。

将 fullgraph 设置为 True 可确保底层模型中没有图断裂，从而充分发挥 torch.compile 的潜力。在我们的案例中，以下编译器标志也需要显式设置：

torch._inductor.config.conv_1x1_as_mm = True
torch._inductor.config.coordinate_descent_tuning = True
torch._inductor.config.epilogue_fusion = False
torch._inductor.config.coordinate_descent_check_all_directions = True

完整的编译器标志列表，请参考此文件。

在编译 UNet 和 VAE 时，我们还将它们的内存布局更改为“channels_last”，以确保最高速度：

pipe.unet.to(memory_format=torch.channels_last)
pipe.vae.to(memory_format=torch.channels_last)

在下一节中，我们将展示如何进一步降低延迟。

额外优化

torch.compile 期间无图断裂

确保底层模型/方法能够被完全编译对于性能至关重要（使用 fullgraph=True 的 torch.compile）。这意味着不能有图断裂。我们通过改变访问返回变量的方式，对 UNet 和 VAE 实现了这一点。请参考以下示例：

消除编译后的 GPU 同步

在迭代式反向扩散过程中，每次去噪器预测出噪声更少的潜在嵌入后，我们都会调用调度器上的 `step()`。在 `step()` 内部，会对 `sigmas` 变量进行索引操作。如果 `sigmas` 数组位于 GPU 上，索引操作会导致 CPU 与 GPU 之间产生通信同步。这会造成延迟，当去噪器已被编译时，该问题会变得更加明显。

但如果 `sigmas` 数组始终保留在 CPU 上（参见此代码行），则不会发生这种同步，从而改善延迟。通常来说，任何 CPU <-> GPU 通信同步都应避免或保持在最低限度，因为它会影响推理延迟。

对注意力操作使用组合投影

SDXL 中使用的 UNet 和 VAE 都采用了类似 Transformer 的模块。一个 Transformer 模块由注意力模块和前馈模块组成。

在注意力模块中，输入通过三个不同的投影矩阵（Q、K 和 V）被投影到三个子空间。在朴素实现中，这些投影是对输入分别执行的。但我们可以将投影矩阵水平组合成一个单一矩阵，并一次性完成投影。这会增大输入投影的矩阵乘法规模，并提升量化效果（将在下文讨论）。

在 Diffusers 中启用这种计算只需一行代码：

pipe.fuse_qkv_projections()

这将使 UNet 和 VAE 的注意力操作都利用组合投影。对于交叉注意力层，我们仅组合键矩阵和值矩阵。要了解更多信息，可参考此处的官方文档。值得注意的是，我们在内部利用了 PyTorch 的 `scaled_dot_product_attention`。

这些额外技术将推理延迟从 2.54 秒降低到 2.52 秒。

动态 int8 量化

我们选择性地对 UNet 和 VAE 应用动态 int8 量化。这是因为量化会给模型增加额外的转换开销，但希望更快的矩阵乘法（动态量化）能够弥补这一开销。如果矩阵乘法规模太小，这些技术可能会降低性能。

通过实验，我们发现 UNet 和 VAE 中的某些线性层并未从动态 int8 量化中受益。你可以在此处查看过滤这些层的完整代码（下文称为 dynamic_quant_filter_fn）。

我们利用超轻量级的纯 PyTorch 库 torchao，使用其用户友好的 API 进行量化：

from torchao.quantization import apply_dynamic_quant

apply_dynamic_quant(pipe.unet, dynamic_quant_filter_fn)
apply_dynamic_quant(pipe.vae, dynamic_quant_filter_fn)

由于此量化支持仅限于线性层，我们还将合适的逐点卷积层转换为线性层，以最大化收益。使用此选项时，我们还指定了以下编译器标志：

torch._inductor.config.force_fuse_int_mm_with_mul = True
torch._inductor.config.use_mixed_mm = True

为防止量化导致的任何数值问题，我们以 bfloat16 格式运行所有内容。

通过这种方式应用量化，延迟从 2.52 秒降低到 2.43 秒。

结论与后续步骤

在本文中，我们介绍了一系列简单而有效的技术，可帮助在纯 PyTorch 中改善文生图 Diffusion 模型的推理延迟。总结如下：

使用降低精度进行计算

使用 Scaled-dot product attention 高效运行注意力模块

使用 torch.compile 配合“max-autotune”优化延迟

合并不同的投影以计算注意力

动态 int8 量化

我们认为，在如何将量化应用于文本到图像扩散系统方面，还有很多值得探索的空间。我们并未详尽研究 UNet 和 VAE 中哪些层更倾向于从动态量化中受益。通过更好地组合目标量化层，或许还有进一步提升速度的机会。

除了以 bfloat16 精度运行外，我们未对 SDXL 的文本编码器做任何改动。优化这些编码器也可能带来延迟方面的改进。
