关于 bfloat16 使用的一些说明

from diffusers import StableDiffusionXLPipeline

## Load the pipeline in full-precision and place its model components on CUDA.
pipe = StableDiffusionXLPipeline.from_pretrained("stabilityai/stable-diffusion-xl-base-1.0").to("cuda")

## Run the attention ops without efficiency.
pipe.unet.set_default_attn_processor()
pipe.vae.set_default_attn_processor()

prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"
image = pipe(prompt, num_inference_steps=30).images[0]

但这并不太实用，因为生成一张 30 步的图片需要 7.36 秒。这是我们的基线，我们将尝试逐步对其进行优化。

此处，我们以全精度运行 pipeline。通过使用 bfloat16 等降低精度，可以立即缩短推理时间。此外，现代 GPU 配备专用核心，可利用降低精度来加速计算。要在 bfloat16 精度下运行 pipeline 的计算，只需在初始化 pipeline 时指定数据类型即可：

from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
	"stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.bfloat16
).to("cuda")

## Run the attention ops without efficiency.
pipe.unet.set_default_attn_processor()
pipe.vae.set_default_attn_processor()
prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"
image = pipe(prompt, num_inference_steps=30).images[0]

通过使用降低精度，我们能够将推理延迟从 7.36 秒缩短至 4.63 秒。

使用 SDPA 执行注意力计算

使用降低数值精度（如 float16、bfloat16）运行推理不会影响生成质量，但能显著改善延迟。

使用 bfloat16 数值精度相比 float16 的优势取决于硬件。现代 GPU 代际更倾向于支持 bfloat16。

此外，在我们的实验中，与 float16 相比，bfloat16 在配合量化使用时表现出更强的鲁棒性。

（我们随后在 float16 下进行了实验，发现最新版本的 torchao 不会因 float16 引发数值问题。）

编译 UNet 和 VAE

默认情况下，使用 PyTorch 2 时，Diffusers 采用 scaled_dot_product_attention（SDPA）执行注意力相关计算。SDPA 提供更快、更高效的 kernel 来运行密集的注意力相关操作。要运行 SDPA 的 pipeline，我们只需不设置任何注意力处理器，如下所示：

from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
	"stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.bfloat16
).to("cuda")

prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"
image = pipe(prompt, num_inference_steps=30).images[0]

SDPA 带来了显著的性能提升，从 4.63 秒降至 3.31 秒。

torch.compile 使用说明

我们可以通过使用 `torch.compile` 让 PyTorch 执行一些底层优化（例如算子融合和通过 CUDA graphs 启动更快的 kernel）。对于 `StableDiffusionXLPipeline`，我们编译了去噪器（UNet）和 VAE：

from diffusers import StableDiffusionXLPipeline
import torch

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.bfloat16
).to("cuda")

## Compile the UNet and VAE.
pipe.unet = torch.compile(pipe.unet, mode="max-autotune", fullgraph=True)
pipe.vae.decode = torch.compile(pipe.vae.decode, mode="max-autotune", fullgraph=True)

prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"

## First call to `pipe` will be slow, subsequent ones will be faster.
image = pipe(prompt, num_inference_steps=30).images[0]

使用 SDPA attention 并同时编译 UNet 和 VAE 可将延迟从 3.31 秒降低至 2.54 秒。

额外的优化

`torch.compile` 提供不同的后端和模式。由于我们的目标是最大化推理速度，因此我们选择使用“max-autotune”的 inductor 后端。“max-autotune”使用 CUDA graphs 并专门针对延迟优化编译图。使用 CUDA graphs 可大幅减少启动 GPU 操作的开销。它通过一种机制来节省时间，即通过单个 CPU 操作启动多个 GPU 操作。

将 `fullgraph` 指定为 `True` 可确保底层模型中没有图断裂，从而充分发挥 `torch.compile` 的潜力。在我们的案例中，以下编译器标志也需要显式设置：

torch._inductor.config.conv_1x1_as_mm = True
torch._inductor.config.coordinate_descent_tuning = True
torch._inductor.config.epilogue_fusion = False
torch._inductor.config.coordinate_descent_check_all_directions = True

有关编译器标志的完整列表，请参阅此文件。

在编译 UNet 和 VAE 时，我们还将它们的内存布局更改为“channels_last”，以确保最大速度：

pipe.unet.to(memory_format=torch.channels_last)
pipe.vae.to(memory_format=torch.channels_last)

在下一节中，我们将展示如何进一步降低延迟。

消除编译后的GPU同步

确保底层模型/方法能够被完全编译对于性能至关重要（`torch.compile` 配合 `fullgraph=True`）。这意味着不能有图断裂。我们通过改变访问返回变量的方式来实现 UNet 和 VAE 的这一点。考虑以下示例：

在注意力操作中使用组合投影

在迭代式反向扩散过程中，每次去噪器预测出噪声更少的潜在嵌入后，我们都会调用调度器上的 `step()`。在 `step()` 内部，会对 `sigmas` 变量进行索引。如果 `sigmas` 数组位于 GPU 上，索引操作会导致 CPU 与 GPU 之间产生通信同步。这会造成延迟，并且当去噪器已被编译时，这种延迟会更加明显。

但如果 `sigmas` 数组始终保留在 CPU 上（参见此代码行），则不会发生这种同步，从而改善了延迟。通常，任何 CPU <-> GPU 通信同步都应避免或保持在最低限度，因为它会影响推理延迟。

动态 int8 量化

SDXL 中使用的 UNet 和 VAE 都采用了类似 Transformer 的模块。一个 Transformer 模块由注意力模块和前馈模块组成。

在注意力模块中，输入通过三个不同的投影矩阵（Q、K 和 V）被投影到三个子空间。在朴素实现中，这些投影是对输入分别执行的。但我们可以将投影矩阵水平合并为一个矩阵，并一次性完成投影。这会增大输入投影的矩阵乘法规模，并提升量化效果（将在下文讨论）。

在 Diffusers 中启用这种计算只需一行代码：

pipe.fuse_qkv_projections()

这将使 UNet 和 VAE 的注意力操作都能利用合并后的投影。对于交叉注意力层，我们只合并键矩阵和值矩阵。要了解更多信息，可参阅官方文档。值得注意的是，我们在内部利用了 PyTorch 的 `scaled_dot_product_attention`。

这些额外的技术将推理延迟从 2.54 秒降低到了 2.52 秒。

Diffusers 库

我们有选择地对 UNet 和 VAE 应用动态 int8 量化。这是因为量化会给模型增加额外的转换开销，而更快的矩阵乘法（动态量化）有望弥补这一开销。如果矩阵乘法规模太小，这些技术可能会降低性能。

通过实验，我们发现 UNet 和 VAE 中的某些线性层并未从动态 int8 量化中受益。你可以在此处查看过滤这些层的完整代码（下文称为 dynamic_quant_filter_fn）。

我们利用超轻量级的纯 PyTorch 库 torchao，使用其用户友好的 API 进行量化：

from torchao.quantization import apply_dynamic_quant

apply_dynamic_quant(pipe.unet, dynamic_quant_filter_fn)
apply_dynamic_quant(pipe.vae, dynamic_quant_filter_fn)

由于此量化支持仅限于线性层，我们还将合适的逐点卷积层转换为线性层，以最大化收益。使用此选项时，我们还指定了以下编译器标志：

torch._inductor.config.force_fuse_int_mm_with_mul = True
torch._inductor.config.use_mixed_mm = True

为防止量化带来的任何数值问题，我们以 bfloat16 格式运行所有操作。

以这种方式应用量化将延迟从 2.52 秒降低到 2.43 秒。
