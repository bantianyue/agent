生成式AI加速 第三部分：高速扩散

本文是系列博客的第三部分，主题为如何使用纯原生PyTorch加速生成式AI模型。我们很高兴分享大量最新发布的PyTorch性能特性，并结合实际示例，探索原生PyTorch的性能极限。在第一部分中，我们展示了如何仅使用纯原生PyTorch将Segment Anything的速度提升8倍以上。在第二部分中，我们展示了如何仅使用原生PyTorch优化将Llama-7B的速度提升近10倍。在本篇博客中，我们将重点介绍如何将文生图扩散模型的速度最高提升3倍。

我们将采用一系列优化手段，包括：

使用bfloat16精度运行

scaled_dot_product_attention (SPDA)

torch.compile

合并注意力计算的q、k、v投影

动态int8量化

我们将主要聚焦于Stable Diffusion XL (SDXL)，展示3倍的延迟提升。这些技术是PyTorch原生的，这意味着你无需依赖任何第三方库或任何C++代码即可利用它们。

借助Diffusers库启用这些优化仅需几行代码。如果你已感到兴奋且迫不及待想要上手代码，可查看此处的配套代码库：https://github.com/huggingface/diffusion-fast

（如后文所示，所讨论的技术并非SDXL专属，可用于加速其他文本到图像的扩散系统。）

使用降低的精度运行推理

在Diffusers中运行SDXL仅需几行代码：

from diffusers import StableDiffusionXLPipeline

## Load the pipeline in full-precision and place its model components on CUDA.
pipe = StableDiffusionXLPipeline.from_pretrained("stabilityai/stable-diffusion-xl-base-1.0").to("cuda")

## Run the attention ops without efficiency.
pipe.unet.set_default_attn_processor()
pipe.vae.set_default_attn_processor()

prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"
image = pipe(prompt, num_inference_steps=30).images[0]

但这种方式实用性不强，因为30步生成单张图像需要7.36秒。这是我们的基线性能，后续将逐步对其进行优化。

此处我们以全精度运行该pipeline。通过使用低精度格式（如bfloat16）可以立即缩短推理时间。此外，现代GPU配备了专用核心，能够利用低精度实现计算加速。要以bfloat16精度运行pipeline的计算，只需在初始化pipeline时指定数据类型即可：

from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
	"stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.bfloat16
).to("cuda")

## Run the attention ops without efficiency.
pipe.unet.set_default_attn_processor()
pipe.vae.set_default_attn_processor()
prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"
image = pipe(prompt, num_inference_steps=30).images[0]

通过使用低精度，我们将推理延迟从7.36秒缩短至4.63秒。

关于bfloat16使用的注意事项

使用低数值精度（如float16、bfloat16）运行推理不会影响生成质量，但能显著降低延迟。

与float16相比，使用bfloat16数值精度的收益取决于硬件。新一代GPU通常更适配bfloat16。

此外，在我们的实验中，与float16相比，bfloat16结合量化使用时的数值鲁棒性更强。

（我们后续在float16下运行了实验，发现最新版本的torchao不会因float16产生数值问题。）

使用SDPA执行注意力计算

默认情况下，使用PyTorch 2时，Diffusers会采用scaled_dot_product_attention（SDPA）执行注意力相关计算。SDPA提供了更快、更高效的内核来运行密集的注意力相关操作。要使用SDPA运行管道，我们只需不设置任何注意力处理器即可，如下所示：

from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
	"stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.bfloat16
).to("cuda")

prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"
image = pipe(prompt, num_inference_steps=30).images[0]

SDPA带来了显著的性能提升，耗时从4.63秒缩短至3.31秒。

编译UNet与VAE

我们可以通过torch.compile让PyTorch执行一些底层优化（例如算子融合，以及通过CUDA graphs启动更快的内核）。对于StableDiffusionXLPipeline，我们编译去噪器（UNet）和VAE：

from diffusers import StableDiffusionXLPipeline
import torch

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0", torch_dtype=torch.bfloat16
).to("cuda")

## Compile the UNet and VAE.
pipe.unet = torch.compile(pipe.unet, mode="max-autotune", fullgraph=True)
pipe.vae.decode = torch.compile(pipe.vae.decode, mode="max-autotune", fullgraph=True)

prompt = "Astronaut in a jungle, cold color palette, muted colors, detailed, 8k"

## First call to `pipe` will be slow, subsequent ones will be faster.
image = pipe(prompt, num_inference_steps=30).images[0]

同时使用SDPA注意力并编译UNet与VAE，可将延迟从3.31秒降低至2.54秒。

torch.compile注意事项

torch.compile提供多种后端与模式。由于我们的目标是最大化推理速度，因此选择inductor后端并使用“max-autotune”模式。“max-autotune”会使用CUDA graphs，并专门针对延迟优化编译图。使用CUDA graphs可大幅降低启动GPU操作的开销。它通过一种机制，仅需一次CPU操作即可启动多个GPU操作，从而节省时间。

将fullgraph指定为True可确保底层模型不存在计算图断裂，从而充分发挥torch.compile的最大潜力。在我们的场景中，还需要显式设置以下重要的编译器标志：

torch._inductor.config.conv_1x1_as_mm = True
torch._inductor.config.coordinate_descent_tuning = True
torch._inductor.config.epilogue_fusion = False
torch._inductor.config.coordinate_descent_check_all_directions = True

完整的编译器标志列表，请参考此文件。

编译UNet和VAE时，我们还将二者的内存布局设置为“channels_last”，以确保达到最高运行速度：

pipe.unet.to(memory_format=torch.channels_last)
pipe.vae.to(memory_format=torch.channels_last)

在下一节中，我们将展示如何进一步优化延迟。

额外优化

torch.compile过程中无计算图断裂

确保底层模型/方法可被完整编译对性能至关重要（即搭配fullgraph=True参数的torch.compile），这意味着不存在计算图断裂。我们通过修改返回变量的访问方式，为UNet和VAE实现了这一点。参考以下示例：

消除编译后的GPU同步操作

在迭代反向扩散过程中，每次去噪器预测出噪声更低的潜在嵌入后，我们都会对调度器调用step()。在step()内部，会对sigmas变量进行索引。如果sigmas数组放置在GPU上，索引操作会引发CPU与GPU之间的通信同步。这会产生延迟，且在去噪器已完成编译的情况下该问题会更加明显。

但如果sigmas数组始终存放在CPU上（参考这行代码），则不会发生该同步，从而改善延迟。通常而言，应完全避免或尽可能减少任何CPU与GPU之间的通信同步，因为这类操作会影响推理延迟。

对注意力运算使用组合投影

SDXL中使用的UNet和VAE均采用了类Transformer模块。Transformer模块由注意力模块和前馈模块组成。

在注意力模块中，输入会通过三个不同的投影矩阵Q、K、V投影到三个子空间。在朴素实现中，这些投影会分别对输入执行。但我们可以将这些投影矩阵横向合并为单个矩阵，一次性完成投影操作。这会增大输入投影的矩阵乘法规模，并提升量化效果（后续将展开讨论）。

在Diffusers中启用此类计算仅需一行代码：

pipe.fuse_qkv_projections()

这会使UNet和VAE的注意力运算都利用组合投影的优势。对于交叉注意力层，我们仅合并key和value矩阵。如需了解更多内容，可参考此处的官方文档。值得注意的是，我们在内部利用了PyTorch的scaled_dot_product_attention。

这些额外技术将推理延迟从2.54秒优化至2.52秒。

动态int8量化

我们对UNet和VAE均选择性应用动态int8量化。这是因为量化会给模型带来额外的转换开销，期望通过速度更快的matmuls（动态量化）来弥补这部分开销。如果matmuls的规模过小，这些技术可能会降低性能。

经过实验，我们发现UNet和VAE中的部分线性层无法从动态int8量化中获益。你可以在此处查看用于过滤这些层的完整代码（下文称其为dynamic_quant_filter_fn）。

我们利用超轻量级纯PyTorch库torchao，通过其易用的API实现量化：

from torchao.quantization import apply_dynamic_quant

apply_dynamic_quant(pipe.unet, dynamic_quant_filter_fn)
apply_dynamic_quant(pipe.vae, dynamic_quant_filter_fn)

由于该量化特性仅支持线性层，我们还将符合条件的逐点卷积层转换为线性层，以最大化收益。使用该选项时，我们还会指定以下编译器标志：

torch._inductor.config.force_fuse_int_mm_with_mul = True
torch._inductor.config.use_mixed_mm = True

为避免量化带来的数值问题，所有运算均采用bfloat16格式执行。

采用这种方式应用量化后，延迟从2.52秒优化至2.43秒。

结论与后续步骤

在本文中，我们介绍了一组简单而有效的技术，可帮助改善纯 PyTorch 中文本到图像 Diffusion 模型的推理延迟。总结如下：

使用降低精度进行计算

使用 scaled-dot product attention 高效运行注意力模块

使用 torch.compile 配合“max-autotune”优化延迟

合并不同的投影以计算注意力

动态 int8 量化

我们相信，在如何将量化应用于文本到图像扩散系统方面，还有很多值得探索的空间。我们并未详尽研究 UNet 和 VAE 中哪些层更受益于动态量化。通过更好地组合待量化的层，可能有机会进一步加速。

我们仅以 bfloat16 运行 SDXL 的文本编码器，未做其他改动。优化它们也可能带来延迟方面的改进。
