# 用 Fusion 超越前沿性能

Brian Thomas · 2026年6月12日

我们发现，将多个模型的结果进行综合处理，可以显著超越单个模型的能力。在此介绍 Fusion：一个让你像调用单个模型一样轻松获得这些综合结果的工具。它允许你选择一个参与模型小组（panel）和一个负责融合各个结果的裁判模型。

为了理解 Fusion 的优势，我们使用了一个测试推理、工具使用和知识组合能力的深度研究基准。我们发现：

1. 小组一致优于单个模型
2. 前沿模型小组可以实现超越前沿的性能
3. 廉价模型小组可以超越前沿模型，并接近前沿小组的性能

现在在聊天室试用 Fusion，或查看 API 文档将其集成到你的应用中。

## 模型小组在深度研究上持续胜出

我们在 DRACO 基准的 100 个深度研究任务上测试了 Fusion。主要发现：

- Fable 5 + GPT-5.5 融合后得分 69.0%，超越了所有单个模型，包括单独 Fable 5 的 65.3%。
- 一个廉价小组（Gemini 3 Flash、Kimi K2.6 和 DeepSeek V4 Pro）击败了 GPT-5.5 和 Opus 4.8。它的得分比 Fable 5 仅低 1%，但成本仅为 50%。

我们相信这证明了模型多样性的优势，类似于人类团队协作的效益。为复杂问题引入多个不同视角能产生更优的结果。

## 一次 API 调用融合多个模型的最佳输出

当你向 Fusion 发送 prompt 时，我们会将其并行分发给一个模型小组，每个模型都启用了网络搜索和网页抓取。一个裁判模型读取每个小组响应并生成结构化分析：共识点、矛盾点、部分覆盖、独特洞见、盲区。然后调用模型基于该分析写出最终答案。

整个流水线在服务端运行，因此可以像调用单个模型一样调用它。

## 我们选择 DRACO 来测试推理、工具调用和简洁性

我们需要一个能区分"听起来很全面"和"实际很全面"的基准。标准基准测试事实回忆或推理谜题。它们不测试 Fusion 所擅长的：研究复杂问题、综合多个来源、生成全面且有良好引用的分析。

DRACO（由 Perplexity AI 开发）正是为此设计的。它包含 100 个深度研究任务，覆盖 10 个领域：学术研究、金融、法律、医学、技术、UX 设计、通用知识、大海捞针式检索、个性化辅助和产品对比。

每个任务都有一个包含约 39 个加权标准的评分表，分为四类：
- 事实准确性（约 20 个标准）：回答必须正确陈述的可验证主张
- 广度与深度（约 9 个标准）：综合质量、权衡分析、可操作指导
- 呈现质量（约 6 个标准）：术语、格式、可读性
- 引用质量（约 5 个标准）：带有可用引用的主要来源

标准可以带有负权重。满足负权重标准意味着回答包含错误。

每个回答由裁判模型逐标准评分，独立进行三次。

DRACO 有其局限性：它只评估纯文本、纯英文交互，其静态任务集可能无法完全泛化到未来的深度研究应用。

## 防止模型作弊

当我们给小组模型开放网络搜索时，发现了一个令人担忧的问题：它们在网络上找到了 DRACO 评分表。我们通过在网络搜索和网页抓取中排除评分结果所在位置来解决这个问题。

## 模型与自身融合带来的显著提升

我们让 Opus 4.8 与自己配对组成双模型小组，同时由 Opus 4.8 担任合成器。结果：65.5%，比单独 Opus 4.8（58.8%）提升了 6.7 分。这表明 Fusion 的提升有很大一部分来自合成步骤本身。

## 关于我们的 DRACO 实现的说明

我们仔细复现了 DRACO 论文中描述的方法，只是使用了 Gemini 3.1 Pro Preview 作为裁判而非论文选择的 Gemini 3 Pro。我们的目标是展示 Fusion 与单个模型之间的相对差异。

## 6月14日更新：发布后的常见问题

Fusion 是 Fable 的直接替代品吗？不是。DRACO 不包含长周期任务，而这正是 Fable 的强项。

如何在编码中使用 Fusion？Fusion 让你的编码模型可以访问一个服务端工具。基础模型直接处理常规编码，在架构决策或研究问题时选择性调用 Fusion。

基准模型有哪些工具可用？openrouter:web_search、openrouter:web_fetch、openrouter:bash。

DeepSeek V4 Pro 的表现令人惊讶。准确吗？在 60.3% 的水平上，它的表现与 Opus 4.8 和 GPT-5.5 相似。

速度慢吗？当 Fusion 被调用时，它会启动一个多步骤流程，通常比标准调用长 2-3 倍。

有哪些使用 Fusion 的方式？四种：聊天室、模型 slug、服务端工具、插件。
