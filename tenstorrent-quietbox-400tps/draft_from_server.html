要点速览
-结果：Marco-Nano-Instruct（8B MoE，每token激活约6亿参数）在1.2万美元的Tenstorrent QuietBox上完成全自回归解码，交付路径397.7 token/s，不含最终token日志交付的trace重放402.6 token/s。

-方法：绕开外部内存天花板的关键是把循环复用的关键张量驻留（residency）在720MB片上SRAM，只让选定的冷专家权重从GDDR6流式加载，而不是每个token都往返外部内存。

-对比：项目记录中最强的全DRAM端到端约260 token/s，把交付路径改为SRAM驻留后提升约53%；同层驻留A/B在2048上下文实测1.248倍，四芯片结果成为Galaxy 32芯片扩展的架构证明。

我们拿Marco-Nano-Instruct（80亿参数的混合专家模型，每个token激活约6亿参数），把完整的自回归解码流水线，在一台放在桌边的1.2万美元Tenstorrent QuietBox（Blackhole）上推到了397.7 token/s。

这个数字不是靠投机解码、草稿模型或跳层换来的：token完整穿过全部28层、最终归一化和语言模型头，再通过设备端反馈回到下一步。真正的杠杆是SRAM驻留，把每个token都要用到的关键数据留在芯片上，而不是反复去外部内存取。

把关键路径压进720MB片上SRAM

这条trace本身已经越过400：不交付最终token日志时，trace重放到402.6 token/s；而项目记录里最强的全DRAM端到端结果大约260 token/s。围绕Blackhole的片上SRAM做优化，把系统推进了另一个性能档位。

这里是batch one。没有投机解码，没有草稿模型，没有跳层，每个用户的数字里也没有藏着第二条流。一个token要穿过全部28层、最终归一化、语言模型头、全局argmax与设备端反馈，下一个token才开始。

我们用了与高性能NVIDIA代码同一族的优化：kernel融合、异步预取与双缓冲、精细分片的数据流、设备端状态、trace图重放，对应CUDA里的自定义kernel、TMA式搬运与CUDA Graphs。DRAM路径和SRAM路径都做了这套处理。

SRAM是额外的杠杆。与其每个token都把关键数据重新取一遍，不如把它放在使用它的Tensix核心旁边。

但Marco Nano按当代基础模型的标准看很小。这正是重点。我们手上只有四颗Blackhole，于是把模型缩小到关键解码路径能装进可用片上内存。Tenstorrent的扩展方向相反：加芯片、加SRAM、加内存带宽、加算力，同时保持编程模型不变。几周后我们会拿到32芯片的Galaxy Blackhole，开始把同样的思路用到基础模型上。

Tenstorrent已经公布过DeepSeek-R1-0528在100K上下文下跑到350 token/s，跑在Galaxy超集群上。Marco Nano是那个结果为什么在架构上成立的桌边证明。

这正是Tenstorrent能把性能推向NVIDIA以HBM为中心的系统未曾针对过的方向：把机器放大到关键路径能装进分布式SRAM，然后不再做那趟昂贵的外部内存往返。

Tenstorrent构建了什么

大多数做AI的人了解NVIDIA，但很少有人知道Tenstorrent处理器内部是什么样，所以值得从硬件讲起。

Blackhole是由两套片上网络连接起来的Tensix核心网格，每个Tensix核心由五部分组成：

● 基于tile的矩阵引擎，负责矩阵运算。

● 向量引擎，负责向量运算。

● 可编程RISC-V核心，既做计算，也负责数据搬运。

● 本地SRAM，即每颗核心自己的一小块高速内存。

● 硬件管理的环形缓冲流控，让数据在核心之间顺畅流动。

两个用户可编程的数据搬运kernel可以发起异步读写、寻址SRAM与DRAM存储体、通过信号量协调，并在计算kernel工作的同时搬运数据。

以太网控制器与额外的RISC-V核心属于同一套架构，而不是围在周围的附属外设。

Hot Chips 2024的Blackhole与TT-Metalium演讲把芯片称作「独立AI计算机」。这是个有用的说法：Blackhole不只是等主机投喂的矩阵引擎，计算、数据搬运、本地存储、DRAM控制与网络都是这台机器里可编程的部分。

当前的Blackhole p150产品提供120个Tensix核心、180MB SRAM、32GB GDDR6（512 GB/s）、Block FP8下664 TFLOPS，还有四个800GbE端口用于Blackhole之间直连。

QuietBox把四颗Blackhole处理器与一颗AMD EPYC主机、512GB系统内存、4TB NVMe存储，以及把板卡连成高带宽网格所需的线缆装在一起，定价11,999美元。

四颗处理器聚合起来大约是：480个Tensix核心、720MB片上SRAM、128GB GDDR6（2.05 TB/s）、2.66 PFLOPS Block FP8算力。这些都归本地所有，并且可以通过Tenstorrent的开源软件栈完全编程。

为什么LLM解码通常是内存问题

运行LLM有两个阶段。预填充处理输入提示，许多token可以一起评估；解码一次生成一个token，每个新token依赖前一个token，所以在batch one时跨token的并行工作很少。

这改变了机器的平衡。

解码时，每个transformer层都要把激活的权重应用到一个token上。矩阵引擎可以极快地完成所需算术，但矩阵-向量运算对每个取来的权重复用很少。如果这些权重来自外部内存，处理器等待字节的时间会超过做数学的时间。给一条计算引擎正等着被投喂的流水线加算力，没有用。

混合专家模型有帮助，因为每个token只有一部分专家权重是激活的。但这没有消除问题：共享的注意力权重、被选中的专家、不断增长的KV缓存以及其它循环状态，在每一个解码步都必须到达核心。

这就是高性能推理软件使用融合、预取、双缓冲、分片与图重放的原因：这些技术减少流量，并让搬运与有用的计算重叠。但只要同样的关键数据每个token仍要穿过外部内存接口，那个接口就仍然是天花板。

所以硬件问题不只是芯片每秒能执行多少次运算，还有芯片能以多快的速度把下一批操作数摆到计算引擎面前。这就是Tenstorrent内存赌注的背景。

内存赌注

现代AI处理器大部分时间在搬张量而不是乘张量。算术单元变快的速度，超过了外部内存投喂它们的速度。

NVIDIA用HBM应对：通过先进封装把昂贵、极高带宽的内存放在GPU旁边。例如H100 SXM提供80GB HBM（3.35 TB/s）。这是巨大的片外投喂能力，背后还有成熟的CUDA软件栈。

Tenstorrent做了不同的取舍：Blackhole用成本更低的GDDR6换取大容量，并把少量极快的SRAM分散到计算核心之间。Hot Chips的演讲让这个差别变得可见：

这些是完整Blackhole设计的架构级聚合数字，不是承诺每个kernel都能看到94 TB/s。SRAM带宽随参与的核心数与数据搬运模式扩展：一个只用八个核心的kernel只能看到芯片总量的一小部分，一次正确分片、铺满网格的操作则能释放远高于此的带宽。

这个限定正是全部要义。Tenstorrent不会自动把SRAM变成缓存：由程序员或编译器决定张量放在哪里、如何分片、哪些核心消费它、何时可以被覆盖，以及走哪条网络路径搬运。软件承担了更多责任，但也获得了多得多的控制权。

好处是，已经在SRAM里的张量根本不需要穿过HBM或GDDR接口。

The highest-bandwidth memory transaction is the one you stop issuing.
译注：带宽最高的那次内存事务，是你不再发起的那次。

缩小版Galaxy实验

Marco Nano提供了合适的实验形态：真实的28层MoE，每层232个专家，每个token选8个。它覆盖了注意力、不断增长的KV缓存、路由、专家执行、张量并行集合通信与自回归反馈，这些正是大得多的MoE也必须做的工作类别。

整个模型80亿参数，但每个token只有约6亿参数激活。这让我们可以在四颗芯片上复现内存策略：把关键的循环注意力与解码状态留在SRAM，同时从GDDR6流式加载被选中的专家权重。

我们确实用了Blackhole的原生低精度格式：选定的注意力与语言模型权重用Block FP4，精度门槛允许的地方用Block FP8。这些格式是硬件主张的一部分，不是临时拼出来的benchmark技巧。同一套模型架构、全部28层、同样的自回归依赖都留在路径里，也没有用投机解码去虚增报告的token速率。

重要的结果不是这份摆放配方，而是内存层级可以随模型一起扩展。四颗芯片足以在Marco Nano上证明这一点，一套Galaxy提供32颗芯片，多个Galaxy再次扩展SRAM与算力的规模。

实际改变了什么

项目记录里最好的全DRAM端到端路径大约260 token/s。围绕常驻SRAM数据优化流水线之后，交付路径达到397.7 token/s，吞吐提升约53%；不含最终token日志交付的原始trace重放达到402.6。

这是最佳流水线之间的对比，而不是说改一个环境变量就能拿到53%。两条路径都用了融合、预取、trace重放、分片与设备端执行；差别在于做完这些常规优化之后，各自的访存架构还允许什么。DRAM路径仍然必须把循环复用的数据搬过外部内存，SRAM路径可以不再搬它。

一个更窄的同层驻留A/B实验在2048上下文下测到1.248倍的吞吐提升，这是对内存摆放的干净隔离；397.7 token/s是围绕它设计完其余数据流之后的整机结果。

这改变了模型的手感：长答案几乎立刻到达。编程agent可以检查、提议、测试、修改，而不必把大半个循环花在等推理上；一次评估可以探索更多提示；研究者可以试更多消融；agent可以在选定一个分支之前考虑更多分支。

高token吞吐不只是一个服务benchmark，它是迭代速度。而迭代速度会复利：如果一个人一小时内能完成两倍有用的模型交互，价值不只是省下的那几秒，而是那些变得足够便宜、因而敢于尝试的额外实验。

为什么SRAM不只是带宽

区别在于staging（暂存）与residency（驻留）。

每个加速器都在暂存数据。NVIDIA开发者用异步拷贝、TMA、双缓冲、kernel融合、CUDA Graphs以及越来越复杂的运行时，把HBM流量藏在计算后面。我们在TT-Metal里用了对应的技术：异步NoC读、预取、融合kernel、分片布局、环形缓冲与trace重放。

但暂存仍然要搬字节，驻留消除了重复的往返。

Blackhole的SRAM是显式管理的，所以程序决定哪些循环张量留在片上、哪些消费者直接读它们。一旦流水线围绕这个事实来安排，中间拷贝和主机同步就可以随着DRAM流量一起消失。

这就是Tenstorrent硬件背后的软件契约：芯片提供快速本地内存、可编程搬运、计算与网络宽度，程序把它们变成一条连续的流水线。

从四颗芯片到32颗

QuietBox是这套架构的桌面级版本，Galaxy才是扩展性论证变得有趣的地方。

一套Galaxy Blackhole在6U机箱里连接32颗Blackhole ASIC。Tenstorrent公布的数据是23 PFLOPS Block FP8算力、6.2GB SRAM（2.9 PB/s）、1TB GDDR6（16 TB/s）与32 TB/s的加速器互联，起价16万美元。四套Galaxy的超集群起价64万美元，更大的配置通过标准以太网扩展。

从QuietBox到Galaxy，价格上涨约9.2倍；处理器数量涨8倍，SRAM涨约8.6倍，DRAM容量涨7.8倍，算力涨约8.6倍。这是同一套编程模型一次非常直接的放大。

四Galaxy超集群把这个规模扩到128颗Blackhole处理器、24.8GB片上SRAM、4TB GDDR6与92 PFLOPS Block FP8算力，公布起价64万美元。这些是聚合资源，不是存在一个平坦内存空间的意思；模型看到的性能取决于它的切分方式、通信模式与摆放。

多个Galaxy继续扩展这个思路。系统不会变成一个神奇的平坦SRAM缓存，而是在更多算力旁边提供更多分布式SRAM、在SRAM旁边提供更多DRAM，以及更多可以搬运规则张量分片的网络链路。

对大MoE来说，原则和Marco Nano一样：把关键的循环路径留在分布式SRAM，把更冷的容量从GDDR6流式加载，当常驻路径需要更多内存或更大算力宽度时再加Galaxy。

这就是Tenstorrent的DeepSeek结果为什么重要。它不只是一个挂在大机器上的大数字，而是证明同一套内存层级可以一直扩展，直到一个6710亿参数模型的重要工作集拥有足够的片上容量与足够多的并行消费者。

与NVIDIA的对比

NVIDIA和Tenstorrent下的是不同的赌注。

NVIDIA围绕HBM、NVLink与极其成熟的专有软件生态构建了异常强大的加速器。策略是让外部内存尽可能快，然后用缓存、预取、融合与调度把它的搬运藏起来。这做得非常好，但HBM、先进封装与专有scale-up基础设施都很贵。

Tenstorrent用标准GDDR6提供容量、用计算旁的SRAM存放最热的数据、用RISC-V做控制、用以太网做scale-out。p150板卡目前标价1399美元，四芯片整机QuietBox定价11,999美元，Galaxy起价16万美元。

如果一个工作负载必须持续从外部内存流式加载工作集，HBM的带宽是巨大优势；但当关键路径留在SRAM里，比赛的性质就变了。Blackhole公布的local/sharded SRAM数字是94 TB/s，对比它自己的GDDR6 512 GB/s和H100 HBM的3.35 TB/s。这些数字描述的是不同的访问模式，但它们展示了Tenstorrent正在构建的作业区域。

完美的HBM预取仍然要把数据搬过HBM接口，常驻SRAM的流水线不会发起那次事务。NVIDIA没法靠再来一轮融合解决这个差别，它要么把更稀缺的片上内存分给工作集，要么继续买外部带宽。Tenstorrent从一大块可编程的SRAM起步，并通过增加相对便宜的联网芯片来扩展这块容量。

这不是说QuietBox在所有工作负载上取代H100，而是说存在一个性能区域：可以分散到SRAM的循环工作集，Tenstorrent的架构能以HBM中心系统难以匹敌、也很难负担的方式参与竞争。

Marco Nano说明这件事在个人开发者或小团队买得起的硬件上可达、可测。

每美元性能，也是每美元自由

这种所有权以云benchmark常常忽略的方式改变经济性：没有按token计费的账单，没有API提供方施加的速率限制，私有数据不离开这台机器。模型可以整夜跑，生成合成数据、评估提示、搜索kernel变体或支撑agent，没有人需要判断下100万token是否还在本月预算里。

成本并没有消失：硬件、电费、散热、工程时间与维护都是真实的，利用率与模型质量也一样重要。但边际决策从「这次调用值不值得付钱」变成了「这个实验值不值得跑」。对研究与产品开发来说，这种自由很可观。

AI基础设施讨论常把经济性简化成每百万token成本。这对一门服务生意有用，但对用模型做东西的人不完整。快速、自有的推理一次买到好几样东西：

● 交互延迟低到长输出仍然显得即时。

● 吞吐足够跑宽评估，而不是抽查。

● 可以在本地生成训练与合成数据。

● 为agent与内部工具提供可预测的容量。

● 专有代码、文档与客户数据的隐私。

● 能修改完整软件栈，直到kernel层。

● 不依赖提供方的模型可用性、定价或使用政策。

在约400 token/s下，一条连续流的理论上限约为每小时144万token。真实利用率会更低，真实工作负载还包含预填充、批处理与编排，但这个数字仍然大到足以改变行为：小团队不再需要配给推理，可以把它当成一种本地资源。

这也许是Tenstorrent最有意思的每美元性能论点：硬件便宜到可以拥有，快到足以改变开发循环，并且当工作负载超出桌面时，扩展不需要替换编程模型。

下一个规模

QuietBox实验回答了问题的小版本：循环工作集可以留在Blackhole SRAM，选定的冷权重可以从GDDR6流式加载，由此得到的全token流水线能在小MoE上接近400 token/s。

Galaxy让我们问大版本的问题：基础模型的共享工作集有多少能常驻在32颗芯片上？上下文增长时KV应该如何分布？专家预取应该在哪里与注意力重叠？多大的批处理能提升tile利用率而不牺牲每用户延迟？多套Galaxy互联时，哪些张量应该移动，哪些永远不该离开它们消费者旁边的SRAM？

这些是由硬件选择开启的软件问题。

以HBM为中心的系统问的是加速器能以多快从计算网格之外的内存继续取张量；Tenstorrent问的是这些取回能消掉多少，然后提供随系统增加而增长的SRAM与网络容量。

QuietBox让这套架构以1.2万美元变得可获得，Galaxy把同样的想法带到基础模型规模。

令人兴奋的不是SRAM本身，而是当快速内存、可编程数据搬运、便宜容量与scale-out被视为一台计算机，并且这台计算机便宜到可以拥有时，会发生什么。

结语
把循环复用的数据从外部内存搬到片上SRAM，是这次400 token/s的真正来源。Marco Nano的8B规模不大，但它包含大规模MoE必须做的全部工作类别：注意力、路由、专家执行、集合通信与自回归反馈。

机制上有三点值得记住：关键解码状态常驻SRAM，消除了每个token的重复往返；冷专家权重继续从GDDR6流式加载，保证容量不被模型规模卡住；而1.248倍的同层驻留A/B才是做完融合、预取、trace重放之后，内存摆放带来的干净收益。

对做推理的人来说，这个桌面级结果把一个方向性判断变成了可验证的路线：把芯片加到关键路径能装进分布式SRAM为止。当Galaxy把片上SRAM从720MB推到6.2GB、四Galaxy再堆到24.8GB，400 token/s这一档就不再只是桌面玩具。
