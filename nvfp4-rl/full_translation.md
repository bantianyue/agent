# 逐句对照完整翻译 — The 4-bitter Lesson: Balancing Stability and Performance in NVFP4 RL

## Introduction

RL 的本质是通过行动与后果来教模型；在 humans&，我们用 RL 训练能够理解其与人类互动长期影响的模型。在一个 RL 循环里，模型行动、获得奖励，然后更新各行动的概率。然而，在面向语言模型的真实世界 RL 训练中，我们希望在观察到样本后就尽快更新策略，哪怕其他 rollout 仍在采样中。对于我们使命核心的长程多人 rollout，一个模型完成一次 rollout 时，我们甚至可能已经做了几十步训练。

这就引出了 RL 中吞吐量与稳定性之间的拉锯。一方面，我们希望尽快在尽可能多的样本上训练。另一方面，大多数提升吞吐量的技术会让采样策略和训练策略发生偏离，可能拖慢学习并使训练失稳。量化正是这种权衡的典型代表：低精度格式在硬件上带来更快的通信与计算，却会损害稳定性。像 NVFP4 这样快速且准确的低精度格式，配合硬件支持，已经在模型训练和推理两端分别带来了巨大的吞吐提升。

然而，开源社区里至今没有一个稳定、硬件原生的 4-bit RL 配方，主要原因在于采样与训练的不稳定性会在 RL 中相互叠加放大。在与开源社区的一次长期协作中，我们开发并分享了一套低精度 RL 配方，它保留了更高精度训练时的动力学特性。在这套配方里，我们需要解决三类不稳定性：来自前向传播的策略量化误差、来自反向传播的梯度失配，以及两者交汇处一小部分特别敏感的权重。下面我们解释如何解决每一类问题，并验证最终配方。

请注意，这项工作离不开我们在 RadixArk 和 NVIDIA 的出色合作者，以及他们在训练、推理和 RL 全栈上的工作。

配方技术的二乘二网格。列：某项技术是否解决前向传播中的策略量化误差；行：是否解决反向传播中的梯度失配。左上：量化误差修复（逐 token 缩放、4/6、位精确契约）。右上：朴素量化，两者都不解决。左下：选择性高精度。右下：梯度失配修复（反量化反向传播）。三个技术单元链接到各自章节。

## Baseline: A starting recipe with stable training dynamics

为了保持一致可比，除非另有说明，本报告所有实验均使用 Qwen3-30B-A3B 模型，在 DAPO-math-17k 数据集上以 8k 序列长度训练。

我们从一个使用 NVFP4 格式的基线配方开始。NVFP4 是一种 4-bit 浮点格式，在新一代 NVIDIA GPU 架构上提升吞吐与内存效率。它采用分层块缩放：每 16 个值组成一个块，块内用 FP8 E4M3 的缩放因子，而整个张量有一个全局 FP32 缩放因子。两者结合可以还原出更高精度的值。

### 为什么 NVFP4 预训练配方不足以用于 RL？

NVIDIA 的 NVFP4 预训练配方是本工作的自然起点。它采用混合精度策略：大多数操作以 FP4 精度执行，而对数值敏感的组件保留更高精度。

然而，预训练和 RL 的失败模式不同。

在预训练中，梯度信号是稠密的，并在大量 token 上反复取平均。主要目标是避免量化偏置扰动优化方向。随机舍入通过让梯度量化近似无偏来提供帮助。

RL 场景有着不同的偏差-方差权衡。策略梯度本身就是一个有噪声的估计器，因为它依赖于被采样的 rollout、优势估计、奖励估计、KL 正则化和策略陈旧度。因此，量化方法仅仅无偏是不够的。量化噪声必须足够小，才不会劣化每次更新中真实的策略梯度信号。

因此，我们优先采取能够降低策略中量化误差、并提升梯度计算准确性的干预手段。

### 基线配方

在基线配方中，我们只量化 MoE 层，其余所有层保留更高精度的 BF16。在 DeepSeek-V3 式架构中，MoE 专家占总参数的 97%，因此激进地量化 MoE 层就能获得绝大部分内存收益。

前向传播在 NVFP4 下运行，反向传播则保留 BF16 精度。这是一个保守的起点：既获得 FP4 在 rollout 和内存上的收益，又避免反向传播走 FP4。

对于权重，我们使用标准 NVFP4 格式，带 FP8 逐块缩放和单一 FP32 全局缩放。

对于激活，我们不使用在整个张量上计算的全局 FP32 缩放因子。正如 Cursor Composer 2 技术报告所指出的，全局缩放会带来两个问题：同一个 token 可能因 batch 中其他 token 的存在而被量化得不同；如果张量包含同一序列的多个位置，靠后的 token 会影响靠前 token 使用的共享缩放，形成从未来 token 泄露到过去 token 的路径。

为解决这个问题，我们与 Cursor Composer 2 类似，采用逐 token 激活缩放：每个 token 在自己隐藏维度上计算自己的 FP32 激活缩放。这让量化对单个 token 局部化，也省去了单独的校准步骤，因为缩放可直接从正向传播观测到的激活中算出。而且这种细粒度 FP32 缩放相比逐张量 FP32 缩放降低了量化误差。

在 rollout 阶段，这个逐 token 缩放计算被融合进激活量化 kernel。对每一行 token，kernel 计算 FP32 缩放、16 值块的 FP8 E4M3 缩放，并将这些量化值打包进 FP4。这种融合实现减少了额外的内存搬运和 kernel 启动开销。

## Improving Gradient Stability

我们观察到，在使用开源逐 token NVFP4 配方训练时出现了梯度范数尖峰。这个配方在反向传播精度上刻意保守：尽管前向传播使用 NVFP4 操作数，反向传播却把权重和激活保留在 BF16 精度。这比让完整反向路径走粗粒度的 NVFP4 稳定得多，但也引入了前向与反向之间的失配，导致偶发的梯度尖峰。

问题在于反向传播不再对前向传播所用函数求导。例如，在一个简单线性层中，前向传播计算 y = x · Q(w_bf16)，其中 Q(.) 表示量化。反向传播表现得就像在对 y = x · w_bf16 求导。这个决定让反向传播更稳定，但也意味着反向传播意识不到量化函数中的截断和舍入决策。

为了在保留 BF16 反向传播稳定性的同时缓解这种链式法则不一致，我们采用反量化反向传播（dequantized backward）。反向传播不使用 BF16 精度，而是使用前向传播所用精确量化张量的 BF16 反量化值。以线性层为例，即 y = x · DQ(Q(w_bf16))，其中 DQ 表示反量化。

这里反向传播仍使用 BF16 操作数，但这些操作数反映了前向传播中使用的相同 NVFP4 量化决策。注意我们的配方对权重和激活都施加了反量化反向操作。

### 结果

用 MXFP8 验证：为了验证我们的改动，我们先在 MXFP8 配方上测试这一修复。下图展示了梯度范数在三种不同配方下的表现：a) 量化的前向与反向，记为 mxfp8-mxfp8；b) 量化的前向与 BF16 反向，记为 mxfp8-high-precision-bf16；c) 量化的前向、并用反量化权重修正链式求导违规的反向，记为 mxfp8-dequantized-bf16。与 MXFP8 反向相比，我们的方法在训练各阶段都带来更干净、噪声更少的梯度。与高精度 BF16 反向相比，我们的方法有助于阻止梯度范数上升，并始终保持稳定。

用 NVFP4 验证：与 MXFP8 相比，NVFP4 使训练动力学更复杂。一方面，我们的方法因反向匹配量化前向而提供更少偏置的梯度，从而帮助稳定；另一方面，NVFP4 量化因其更粗的表示网格而增加梯度方差。

为了从经验上理解这一点，我们的第一个设置使用 SGD 优化器而非 Adam，因为 SGD 更容易隔离我们方法对真实梯度的影响。我们观察到，与更高精度反向的基线相比，我们的方法学习更快。这可以用梯度与所训练的真实量化函数对齐更好来解释。

然而，我们也观察到这个配方稳定性较差，可能发散。如前所述，这很可能是因为 NVFP4 更粗的表示使梯度方差更高。

为了复现真实 RL 运行的设置，我们切回 Adam 优化器，检查动量和自适应二阶矩等性质是否降低了我们的方法引入的额外方差。我们观察到，与反向使用更高精度的基线方法相比，我们的方法产生的大梯度尖峰要少得多。

## Four-Over-Six for RL Weights and Activations

另一个挑战与 NVFP4 本身有关。通常，我们可以把参数表示为 0、±0.5、±1、±1.5、±2、±3、±4、±6 的倍数。然而这意味着，当表示一个接近范围 5/6 处的值时，误差可能高达范围的 1/6！如果我们改为把最大值映射到 ±4，最大可能误差就变成范围的 1/8。这种方法被称为 four-over-six，或 4/6，来自论文《Four Over Six: More Accurate NVFP4 Quantization with Adaptive Block Scaling》。关键在于，引入缩小范围仅当它降低量化误差时才采用。在该论文中，这项技术只应用于预训练、且只用于激活；而我们把它也用到了权重上。这对 RL 更重要，因为我们从已经训练好的权重出发，其量化误差的影响被不成比例地放大。

对于自适应缩放，我们需要计算调整后的权重，并逐块判断误差是否降低。

然而，计算调整后权重最朴素直接的方法代价很高：candidate = fp4_value * fp8_scale * amax / (E2M1_MAXVAL * E4M3_4OVER6_MAXVAL)。要选择我们想要的最大 FP4 值（4 还是 6），需要：把每个存储的 FP4 值转成 FP32；用块缩放值和张量/token 最大值相乘；除以最大 FP4/FP8 值做归一化；计算 4 和 6 各自的块量化误差；比较块量化误差以选择 4 或 6。

问题在于所有这些操作都是标量 FP32 算术，在当前硬件上吞吐有限，导致停滞。

我们改为用硬件原生的 PTX 操作，以无损的 FP16 完成数据类型转换和 FP4*FP8 计算。此外，我们不是对每个候选用 amax / (E2M1_MAXVAL * E4M3_4OVER6_MAXVAL) 放大两次，而是用其倒数把目标缩小，从而把计算保留在 FP16。当然，我们也可以通过有损近似误差来进一步加速，但我们出于高稳定性的考虑，把误差累加保留在 FP32，并且在切换到 BF16 或 FP16 时未观察到 kernel 提速。我们发现，在量化基准中，无论使用哪种误差类型或量化模式，所得缩放因子选择超过 99.97% 的情况下都一致，同时相比朴素/严格方法在实际中带来约 2.8 倍加速。最后，为避免任何训练器-采样器不匹配，我们需要 RL 全栈两侧的契约：我们确保 4/6 实现在训练和采样两侧逐位精确匹配。

对于这个位精确契约，我们需要确保量化值和缩放因子每次都跨训练器和采样器逐位相同。首先，我们的 kernel 每次都要产生逐位确定的输出。其次，训练与推理实现的 kernel 必须遵循完全相同的数值契约。对于 4/6，误差的计算、累加和比较也必须如此。误差累加的归约尤其困难，因为无论权重布局和 swizzle 如何都必须保持一致。

如图 15 所示，加入 4/6 不会明显增加 rollout 时间。新增操作被融合进量化 kernel，把额外计算藏在已有的内存访问延迟之下。我们在 FlashInfer 和 TransformerEngine 这两个 NVIDIA 维护的 kernel 库上都实现了这个契约。

如图 17 所示，相比没有 4/6 的 NVFP4 RL，加入 4/6 显著稳定了参考 KL。

## Selective Layer Precisions: Spending Where It Matters

在实践中，没有哪个低精度配方对所有权重和激活都用同一精度。与 NVIDIA NVFP4 预训练论文一样，我们关注两类权重：第一，把一小部分最终层保留在高精度；第二，许多 MoE 架构包含一个始终激活的专家（"共享"专家），把这个专家保留在更高精度代价相对较小却很有影响，因为它对每个 token 都激活。我们在下方用 MXFP8 可视化了内存与 logprob 的权衡；注意这里的最优权衡通常取决于模型和可用内存。

此外，当我们决定某些权重应保持更高精度时，它应在检查点、训练、rollout 和权重更新中都保持该精度。在每个上下文中写定制的逐模型量化处理这种朴素做法容易出错，因此我们引入了基础设施来最小化复杂度。

## Putting it all together: Final Recipe

在落实并集成这些优化之后，我们需要让自己确信组合配方是稳定的。为公平起见，我们没有为任何量化运行调整超参数，而是把我们的方法作为 BF16 的即插即用替代。即便用了三项优化中的两项，我们仍会看到梯度范数尖峰。然而，三项优化全部用上时，梯度范数异常稳定（图中为五次运行）。

此外，所有这些运行的奖励曲线都紧贴 BF16 奖励曲线。

## A Pleasant side effect: Online NVFP4 Serving

同一条 rollout 量化路径可以用在线训练后量化来服务模型检查点。在运维上，这帮我们高效部署训练好的检查点，无需运行校准、QAT 或单独的模型转换流程，并能利用我们在量化模型上的质量改进，如 4/6 和选择性高精度。

例如，在一个内部基准中，我们用 GLM 5.1 作裁判，对使用多种工具的多轮 rollout 打分。FP8 部署与我们的 NVFP4 量化部署之间的相关性为 0.924。

我们已经开源了这个实现。在 SGLang 中使用此功能，只需在任意已有的 BF16/FP8 模型服务命令后加上 --quantization nvfp4_online。

## Final thoughts

### Future Improvements

使用 NVFP4 训练的一个难点是激活的实时量化。寻找缩放因子要么需要校准，要么需要找到动态的逐张量（我们这里是逐 token）最大值并重新缩放，这会因 kernel 内归约带来性能开销。一个解决方案是用 MXFP8 激活配 NVFP4 权重。这有双重好处，因为激活往往比权重更难量化，所以这套配方会在最有用之处提升精度。现有 NVIDIA GPU 已配备 MXFP8 x MXFP4 指令，但把权重量化到 MXFP4 会因它们使用的 UE8M0 缩放因子而降低精度。我们希望未来硬件世代能提供此能力。

我们把这项工作视为量化配置与训练环境的协同设计：随着我们在超长程、多智能体、更大模型的训练上扩展，我们也面临独特挑战，我们选择优先稳定性的量化配置而非快速训练。未来，训练配方的更多部分应针对与低精度的交互做定制。尤其是围绕低精度训练独有挑战来设计优化器，似乎是一个有前景的研究方向。

我们的全栈建立在开源代码之上，我们很高兴回馈社区。

在链接的实现中，你可以找到每个特性的定制选项。只要 TransformerEngine 与 FlashInfer 的 4/6 参数对齐，几乎所有这些都能独立配置。

## Conclusion

通常到这里，我们会借机把这项工作与公司及其目标强绑定。但这次，让我们分享一个隐喻。在这项工作中，有些挑战自然来自各个独立组件，但最关键的问题来自部件之间的交互。毋庸讳言，如果让 NVFP4 在 RL 中可用，就像把 NVFP4 预训练配方套用到训练器、把 NVFP4 推理套用到采样器那么简单，那就根本没必要写文章或开源任何东西。

大多数研究者都听过"苦涩的教训"；一篇较少被讨论但同样发人深省的小文提出了"单步陷阱"。用局部预测来建模复杂动力系统常常是个陷阱。在这项工作中，我们主要关注训练器与采样器之间的交互；而在我们公司，我们关注人与模型交互的动力学。如果我们只构建为孤立任务优化的模型，它们就永远学不会理解人与其目标、以及与他人交互所能带来的非局部长程价值。单步方法更容易，但几乎从来不是值得走的那条路。
