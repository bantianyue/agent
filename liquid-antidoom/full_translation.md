用 Final Token Preference Optimization 减少 Doom Loop（思维死循环）

重复退化是推理过程中一种常见的失败模式：模型吐出一段文本（常常类似"Wait, let me reconsider…"这样的内容），然后一遍又一遍地重复同一段文本，直到上下文窗口被耗尽。我们把这种现象称为"doom loop"（死亡循环）。小型推理模型更容易出现这种行为，尤其是在很长的思维链轨迹和困难问题上。

常见的推理期修复手段是施加 repetition_penalty（重复惩罚）来重新加权输出分布。然而这只是个创可贴式的解决方案，并且会损害性能。强化学习可以有针对性地解决重复循环问题，但它通常需要经过仔细校准的奖励函数，以及昂贵的在线 rollout。

我们的方法采取了更有针对性的思路。我们定位到开启循环的确切 token，训练模型在该单一位置上偏好连贯的替代 token，而让分布的其余部分基本不受影响。这个方法借鉴了 Antislop，在代表单个补全 token 的 chosen/rejected（被选中/被拒绝）配对上训练，使用的是 Final Token Preference Optimization（FTPO，末位 token 偏好优化）。我们把这种方法称为"Antidoom"。

在 LFM2.5-2.6B 的一个早期 checkpoint 上，困难数学和编程提示词下有 10.2% 的补全产生了重复循环。经过 Antidoom 训练后，这一比例降到了 1.4%，而评测分数也因为循环减少而全面提升。

doom loop 的内部构造

doom loop 在推理中由三种机制共同作用而产生：

机制一：被过度训练的 token 加不确定性

词表中的某些 token 总体上更容易被选中。真实世界中广为人知的例子包括"delve"和"testament"。这可能发生在模型的训练集中使用了合成数据，从而制造出比人类正常写作中更高的这些词的分布。在推理模型中，高先验的续写常常包含话语标记和自我反思 token，例如"Wait"或"Alternatively"。这些 token 未必是坏的，它们可能标志着一次有用的策略转换、一个验证步骤，或者推理轨迹中的一个分支。然而，当模型不确定或卡住时，它们会变成诱人的兜底续写，重新启动同样的局部推理模式，而不是帮助模型取得进展。

在 LFM2.5-2.6B 的早期 checkpoint 上，最常用于开启 doom loop 的 token 如下：

| 数量 | 占比 | token |
|------|------|-------|
| 2277 | 11.39% | ' the' |
| 902 | 4.51% | ' So' |
| 644 | 3.22% | 'Alternatively' |
| 511 | 2.56% | 'Wait' |
| 493 | 2.46% | ' But' |

当模型不确定时，这些被过度训练的 token 会主导下一 token 的分布，这似乎解释了为什么循环最常出现在困难数学和编程问题的推理轨迹内部。先前的工作给出了类似的退化解释：基于似然训练的模型会给重复和常见词过度分配概率，而推理模型在低温解码、无法找到有用的下一步时会陷入循环，转而退化为重复。

机制二：先前的上下文强化了循环

较早的序列会让同样的序列在之后更可能出现。每重复一次，循环片段中每个 token 的概率都爬升到接近 1。

Duan 等人在他们关于循环推理的研究中探讨了这种循环。他们将其与一种"V 形"注意力模式联系起来，并发现语义重复（模型卡在某个想法上）先于文本重复（同样的词出现在输出中）。

机制三：贪婪采样

推理模型通常以低温运行，以保持轨迹稳定且可复现。在温度为 0 时，最可能的 token 总是被选中，而一个被局部强化的循环没有出口。理论上更高的温度有帮助，但是一旦机制二已经把循环 token 的概率推到接近 1，剩余词表几乎分配不到任何概率，所以即使在更高温度下采样仍可能卡在循环里（我们的结果显示在 temp=0.67 时仍有显著循环）。温度越低，循环越严重。

定位失败

为了构建有针对性的训练集，我们在一个旨在诱发循环的提示词混合（LiquidAI/antidoom-mix-v1.0）上以低温生成补全，然后从中挖掘失败样本。

如果一个片段至少重复四次、且长度至少 60 个字符，就判定该样本中出现了循环。实践中，这些约束有助于避免假阳性和假阴性。一旦识别出循环序列，我们就锁定第一次重复的首个 token。

在那个位置上，我们取基础模型 top-k 的 log-prob 替代项，过滤掉过短或非字母数字的噪声，保留最多 20 个合理的替代 token 作为 chosen token。每一行训练数据由一个 [prompt 前缀, 一个 rejected token, 一个或多个 chosen token] 元组组成。然后我们在训练前对 rejected 和 chosen 分布做正则化：一小撮元凶（Wait、So、the）否则会主导分布，而过度抑制它们又会损害推理。

Final Token Preference Optimization（末位 token 偏好优化）

Final Token Preference Optimization（FTPO）是一种类似于 Direct Preference Optimization（DPO，直接偏好优化）的偏好优化算法。一个训练样本由 prompt、被选择的续写、被拒绝的续写组成。它从一开始就被设计成只针对分布中少数几个 token 做精准修改，对模型其余部分干扰最小。

FTPO 与 DPO 的区别如下：

末位 token 训练：只训练处于生成中途的序列的最后一个 token。

每个样本有多个被选择的补全 token：这把概率分散到一组替代 token 上，这样我们不是简单地用另一个被过度训练的 token 替换原先那个。

在 logit 空间实现的类 KL 损失项：通过省略 softmax、改为在 logit 上与参考模型计算散度，避免对无关 token 施加梯度压力。

两部分正则化：我们要训练的 logit（chosen 和 rejected token）相对于参考模型可以更自由地移动，而剩余的词表则受到更紧的约束。这带来了更好的可学习性，同时又能贴近参考模型。

在我们的 Antidoom 实现中，模型通常用 LoRA 训练一个 epoch。我们发现较高的 LoRA 秩（rank=128-256）能产生最好的结果：可学习性更高，同时退化更少。我们在所有 attention 和 MLP 投影层以及 lm_head 上训练，发现最优学习率在 4e-6 到 2e-5 附近。

过训练很容易发生。我们以 chosen_win（chosen token 胜过 rejected token 的样本比例）为条件触发早停。在 chosen_win=0.35 处停止通常能把 doom loop 比例从 20-30% 降到 1-2%，且退化极小。训练更久往往会损害模型，常常制造出新的 doom loop 问题。

对我们的 LFM2.5-2.6B 早期 checkpoint 来说，训练集生成在 8 块 MI325 GPU 上大约需要一小时，随后的训练在 1 块 MI325 GPU 上大约需要一到两小时。训练集生成时间由模型的 doom loop 比例决定，因为它在收集到 2 万对配对后停止。

结果

为了衡量 doom loop 比例，我们对一组多样化的推理密集提示词生成回复，并统计出现退化重复的样本。

训练后，我们的 LFM2.5-2.6B 早期 checkpoint 上的 doom loop 比例从 10.2% 降到了 1.4%。评测分数全面改善，而这完全可以归因于循环减少。训练集没有教会模型任何关于数学或代码的新东西；它只是移除了那个阻碍模型给出它本来就能给出的答案的失败模式。

我们也在 Qwen3.5-4B 上用 Antidoom 流程做了训练，该模型在推理时已知会产生重复循环。在贪婪采样下，它的 doom loop 比例从 22.9% 降到了 1%，评测分数显著提升。

LFM2.5-2.6B 早期 checkpoint：

对于基线 checkpoint（LFM2.5-2.6B-early-ckpt），评测分数的变化与 doom loop 比例随温度升高呈反向关系。可以推断 doom loop 正在直接拉低基准分数，因为在 antidoom 训练之后分数大幅升高。

antidoom 训练后暴露出一个次要效应：该 checkpoint 在 temp=1.0 时性能下降。这是意料之中的：一般认为更高的温度采样会损害性能，因为模型更可能选中不那么偏好的 token。过去有一种主流观点，认为更高温对推理模型可能更有利，能让它们探索解空间。然而这种直觉可能是错置的，它和 doom loop 的主导效应混在了一起。一旦消除了 doom loop，至少在本文测试的这些模型中，近贪婪采样下能看到更强的评测表现。

Qwen3.5-4B：

Qwen-3.5-4B 在 antidoom 训练后展现了更大的性能提升。模式与 LFM2.5-2.6B 相同，在低温采样下收益最大，并且在循环不再是影响因素后，暴露出在接近 temp=1 处性能退化的模式。

在实践中，我们发现应用多轮 Antidoom 会有帮助。第一轮之后，doom loop 比例下降，因为导致循环的 token 被拒绝，概率被重新加权到该位置上的 chosen 替代项。然而，这可能暴露出新的失败点，此时分布中其他位置的 token 会触发新的循环。再施加一轮 Antidoom 针对这些新浮现的循环，能进一步降低 doom loop 比例。

结论

Antidoom 修复了训练后常见的退化重复行为，尤其是在思考型模型上。它选择性地瞄准开启循环的那些问题 token，对剩余分布的附带损害最小。迄今为止的结果表明，在 Liquid 内部的 LFM checkpoint 以及 Qwen3.5-4B 上，都近乎完全消除了重复循环。
