## Abstract

混合专家模型（MoE）已成为许多最先进开源和闭源大语言模型的核心组件。尽管它们被广泛采用，但现有 MoE 架构在推理成本方面——以每浮点运算精度和每参数精度衡量——距离最优还有多远仍然不清楚。在这项工作中，我们从硬件-软件协同设计角度重新审视 MoE 设计，基于经验和理论考量。我们刻画了跨不同部署场景的关键性能瓶颈，涵盖离线高吞吐执行和在线延迟关键推理。在这些洞察指导下，我们引入了 LatentMoE，一种通过系统设计探索得出、针对单位计算量最大化精度的新模型架构。在高达 95B 参数和超过 1T token 训练范围的实证设计空间探索中，结合支持性理论分析表明，LatentMoE 在每 FLOP 精度和每参数精度方面始终优于标准 MoE 架构。鉴于其强劲表现，LatentMoE 架构已被旗舰级 Nemotron-3 Super 和 Ultra 模型采用，并扩展到更大的规模，包括更长的 token 周期和更大的模型尺寸。

## 1 Introduction

基于 Transformer 的大语言模型支撑着从对话代理到代码生成和科学推理的广泛现代 AI 系统。随着这些模型持续扩展，实际部署日益受到推理成本的约束，包括计算和内存两方面。因此，现代模型设计的一个核心目标是在固定推理成本约束下最大化可达到的精度。

混合专家模型已成为实现这一目标的有前景的方法，使模型能够扩展参数量，同时保持每 token 的浮点运算次数不变。尽管它们在经验上取得了成功，MoE 的设计空间仍然理解不足。现有的 MoE 架构主要基于高层次稀疏性论点驱动，主要针对离线吞吐场景优化，对施加严格延迟、内存带宽和通信约束的在线部署考虑有限。

我们认为，有效的 MoE 设计必须沿着两个互补维度评估：每 FLOP 精度和每参数精度。每 FLOP 精度捕获计算效率，而每参数精度反映内存占用、内存带宽需求、路由引起的通信和分片开销——这些因素通常是交互式、低延迟推理中的主导瓶颈。忽视这些因素可能导致看起来在总计算量上高效、但在实际部署中产生大量低效的架构。

**Figure 1a: 标准 MoE 架构。** **Figure 1b: LatentMoE 架构。**

**Figure 1: 标准 MoE vs. LatentMoE 架构。** 在 LatentMoE 中，token 从模型隐藏维度 d 投影到更小的潜在维度 ℓ，用于专家路由和计算，这使路由参数负载和 all-to-all 通信减少了 d/ℓ 倍。我们利用这一效率来增加专家总数和每 token 的 top-k 活跃专家数（同样增加 d/ℓ 倍），这提高了模型精度同时保持总体推理成本大致不变。

在这项工作中，我们从硬件-软件协同设计角度重新审视 MoE 架构设计。通过跨吞吐-延迟帕累托前沿对现有 MoE 系统的系统分析，我们识别了由专家参数化、路由引起的 all-to-all 通信和内存访问模式产生的关键结构性瓶颈。结合精确的精度测量和理论分析，我们的研究指出了当前 MoE 设计中限制了单位推理成本可达到精度的结构性低效。

在这些洞察指导下，我们引入了 LatentMoE，一种专门针对每 FLOP 精度和每参数精度优化了的混合专家新架构。LatentMoE 通过在专家处理之前将传入激活投影到共享的低维潜在空间，将专家路由和计算与模型隐藏维度解耦（Figure 1）。潜在维度作为计算成本、通信量和专家参数大小的直接控制旋钮。在等 FLOP 和等参数量下，将传入激活投影到更低维度的潜在空间，使得专家数量和路由 top-k 可以成比例增加，同时保持推理成本不变。

正如我们在理论和经验上都证明的那样，同时增加专家数量和组合稀疏多样性提高了模型的有效表达能力，从而带来更高的可达到精度。关键的是，这些增益没有增加内存带宽需求或通信开销，使 LatentMoE 既适用于延迟关键场景也适用于吞吐导向部署。我们通过在高达 95B 参数和超过 1T token 规模下的预训练实验验证了 LatentMoE 概念。在所有评估场景中，LatentMoE 一致地改进了标准 MoE 架构，在固定推理成本下实现更高精度，或在固定精度下显著降低推理成本。鉴于其强劲表现，LatentMoE 架构已被旗舰级 Nemotron-3 Super 和 Ultra 模型采用，并扩展到更大的规模。

## 2 LatentMoE Core Design Principles

在深入 LatentMoE 的具体细节之前，我们首先从系统层面来看部署一个既精确又成本高效的 MoE 模型需要什么。

在本节中，我们以 **Qwen3-235B-A22B** 作为运行示例进行建模，其中 N=128 个专家，K=8 个每 token 活跃专家，隐藏维度 d=4096，中间前馈维度 m=1536。具体来说，我们考虑在由高带宽 NVLink 网络互联的 NVIDIA GB200 GPU 上部署，它提供每 GPU 约 1800 GB/s 的双向带宽。为了确保专家通信保持在单个 NVLink 域内，专家通过专家并行分布在 EP=64 个 GPU 上。注意力层使用数据并行在同一组 GPU 上执行。每个 GB200 GPU 提供峰值 FP4 Tensor Core 吞吐 F=10 PFLOPs 和 HBM 内存带宽 BWHBM=8 TB/s。

### 2.1 Memory Bandwidth Bottleneck

在高交互性（即低延迟）场景中，通常使用小批量，MoE 计算主要受内存带宽瓶颈限制。Figure 2 提供了性能与运算强度的屋顶线分析。

**Figure 2: 服务 Qwen3-235B-A22B 的屋顶线分析。** 工作点对应不同的每专家 token 数 t_exp（即 MoE 路由后的有效专家批量大小），映射到运算强度 I。在延迟关键批量大小（低 I）下，MoE 专家计算受 HBM 带宽而非计算能力约束，工作点位于带宽受限区域。

对于 GB200 系统，计算变得受计算约束（compute-bound）仅当运算强度超过 1250 FLOPs/byte。在典型的延迟关键部署中，有效批量很小，导致 t_exp 大约只有几百个 token——远低于 1418 的阈值。因此，MoE 专家在屋顶线曲线的内存受限区域运行，性能受权重加载而非计算能力限制。

**设计原则 I：** 在低延迟服务场景中，MoE 推理通常受加载模型权重的内存带宽成本主导。因此，最大化每参数精度对于高交互性应用至关重要。

### 2.2 Communication Bottleneck

在吞吐导向场景中，一旦专家变得受计算约束，通信就成为分布式环境中端到端执行时间的重要贡献者。专家并行需要在设备间进行 all-to-all token 路由，这施加了可能主导端到端执行时间的开销。

在我们的示例配置中，每个 GPU 承载 2 个专家。假设 token 均匀分布，每 GPU 每 MoE 层的 all-to-all 通信量为 M_comm = 5·t_exp·d。计算时间与通信时间的比约为 9。这意味着在吞吐导向场景中，MoE 层严重受 all-to-all 通信开销主导。

**设计原则 II：** 改善吞吐导向 MoE 部署的性能需要最小化 all-to-all 操作的数据量。该数据量与路由隐藏维度 d 和活跃专家数 K 成正比。因此，可以通过减小路由隐藏维度 d 或活跃专家数 K 来缓解通信开销。

### 2.3 Model Quality

除了优化推理速度，保持模型质量至关重要。为此，我们借鉴神经网络表达能力和组合稀疏性的理论洞察。

根据 Barron 函数的经典结果，一个具有 u 个非线性单元的单隐藏层网络达到 𝒪(1/u) 的均方误差，与输入维度 d 无关。在 MoE 层中，每 token 的有效非线性预算与所选专家的总宽度成正比：U_eff ∝ K·m。这意味着减少活跃专家 K 或中间维度 m 会直接损害有效容量，有损模型质量。

**设计原则 III：** 保持模型质量需要保留有效非线性预算 K·m。因此，要缓解内存和通信瓶颈而不牺牲模型质量，我们应保持活跃专家数和中间维度不变。

每个推理任务都有一个内在特征秩 r_eff，对应于保持任务相关信息所需的最小自由度。将隐藏维度 d 减少到低于此阈值必然丢弃这些信息，导致精度下降。因此，r_eff 作为 d 的任务相关下限。

**设计原则 IV：** 存在一个任务特定的特征秩 r_eff，它设定了 d 的下限。将 d 降低到这一限制以下会引发模型质量崩溃。

此外，MoE 架构受益于组合稀疏性，每 token 有 (N choose K) 种可能的专家组合。增加总专家数 N 可以扩展这一特化空间。此外，同时将 N 和 K 缩放 α 倍会指数级增加专家组合的多样性。

**设计原则 V：** 同时缩放专家数 N 和每 token top-k K 可以通过指数级扩展专家组合空间来提升模型质量。

**综合起来：** 设计原则 I 和 II 表明改善推理速度需要降低内存带宽和通信成本。内存带宽成本随 d 和 m 扩展，通信成本随 K 和 d 扩展。但原则 III 警告不要减少 K 或 m，因为那将可能降低模型质量。这使得 d 成为最有希望缩减的维度，可以在吞吐和延迟场景中都实现性能提升，而不会显著损失精度。原则 IV 进一步确立了 d 的下界 r_eff。此外，原则 V 表明增加 N 和 K 可以改善模型质量。由于内存带宽和通信成本与 K 线性相关，我们可以同时将 K 增加 α 倍并将 d 减少同倍数，只要 d/α ≥ r_eff。我们假设（并在后续部分实证验证）这种变换保持了内存带宽和通信成本，同时提升了网络表达能力和组合稀疏性，从而产生更高的每 FLOP 和每参数精度。

## 3 LatentMoE Architecture

根据第 2 节提出的设计原则，我们引入 LatentMoE，一种专为高效缩放设计的新型 MoE 架构。LatentMoE 首先将每个输入 token x ∈ ℝ^d 通过可学习的下投影矩阵 W↓ ∈ ℝ^{ℓ×d} 投影到低维潜在空间 ℝ^ℓ。然后，压缩后的表示被路由到选定的专家。每个专家 E_i(·;ℓ) 完全在潜在空间内运作，参数为权重 W_FC1^(i), W_gate^(i) ∈ ℝ^{m×ℓ} 和 W_FC2^(i) ∈ ℝ^{ℓ×m}。专家计算完成后，输出被聚合，并通过可学习的上投影矩阵 W↑ ∈ ℝ^{d×ℓ} 投影回原始输入维度。

由于我们只将输入维度 d 压缩到 ℓ，而保持中间维度 m 不变，有效非线性预算 U_eff 保持不变。虽然设计原则 III 表明这理论上应保持精度，但实践中更大模型往往更易训练。为了避免压缩模型的大量超参数调优，我们利用设计原则 V，将总专家数 N 扩展 α = d/ℓ 倍，从而扩展组合特化空间。

关键的是，由于内存带宽成本（在延迟场景中）和通信成本（在吞吐场景中）都不依赖于 N，这种缩放遵守设计原则 I 和 II，不引入额外推理开销。以下我们称此架构修改为 ℓ-MoE_eff，正式定义为：

ℓ-MoE_eff(x) := W↑ · (∑_{i∈𝒯_{K,N'}} p'_i · E_i(W↓·x; ℓ)) + ∑_{j=N'+1}^{N'+S} E_j(x; d)

这里 N' = α·N 是扩展后的路由专家集。路由专家 E_i(·;ℓ) 在潜在空间内运作，而共享专家 E_j(·;d) 在原始输入空间运作。路由权重 p' = Softmax(W'_r · x) 从原始 token x 计算，使用可学习权重矩阵 W'_r ∈ ℝ^{N'×d}。𝒯_{K,N'} 表示选中的 top-K 专家索引。

下投影 W↓ 之后，token 分发和聚合在潜在空间 ℝ^ℓ 中进行。这使通信量比标准 MoE 减少了 α 倍。同样，由于专家权重位于潜在空间（ℝ^{m×ℓ} 和 ℝ^{ℓ×m}），权重加载的内存带宽成本也减少了 α 倍。

设计原则 V 进一步表明，将 N 和 K 同时缩放 α 倍会指数级增加专家多样性，从而提升模型质量。遵循这一原则，默认的 LatentMoE 配置（即 ℓ-MoE_acc）定义为：

ℓ-MoE_acc(x) := W↑ · (∑_{i∈𝒯_{K',N'}} p'_i · E_i(W↓·x; ℓ)) + ∑_{j=N'+1}^{N'+S} E_j(x; d)

其中 K' = α·K。此公式与 ℓ-MoE_eff 仅在活跃专家数上有所不同。

由于 K 增加了 α = d/ℓ 倍，此变体保持通信成本和内存带宽需求与标准 MoE 大致不变。但每 token 增加的专家多样性和非线性预算，在等推理成本下带来了更优的模型精度，从而将模型的帕累托前沿推向新水平。

**Table 1: 各架构每 GPU 渐进通信和内存带宽成本对比。** ℓ-MoE_eff 降低通信和权重加载内存成本（→ 保持精度，↑ 提升推理效率）；ℓ-MoE_acc（推荐）保持成本不变但提升精度（↑ 精度，→ 推理效率）。

## 5 Related Work

混合专家模型已成为最先进大语言模型服务的基石。在这项工作中，我们首次挑战了原始 MoE 设计范式，引入了在等参数和等 FLOP 约束下都能达到更高精度的替代架构。

MoLAE 是最近的类似工作，是一种基于专家权重低秩近似的后训练压缩方法。虽然两者表面相似，但 LatentMoE 做出了根本不同的设计权衡——将专家压缩与增加网络表达能力和组合稀疏性相结合。相反，MoLAE 为补偿精度损失引入了分组潜在投影并限制只压缩部分专家，这反过来放弃了 token 分发时的通信节省，限制了可达到的效率增益。

并行的工作通过修改残差连接而非专家路径来提升等计算下的模型质量。mHC（Manifold-Constrained Hyper-Connections）通过加宽残差流和增加残差路径连接来提升质量。我们认为 LatentMoE 和 mHC 是互补的，可以叠加使用。

## 6 Conclusion

我们提出了 LatentMoE，一种改进的混合专家架构，通过明确考虑现代推理系统中的主导性内存带宽和通信瓶颈，最大化每 FLOP 精度和每参数精度。通过将 token 投影到低维潜在空间，LatentMoE 减少了路由 all-to-all 通信以及每专家所需的内存带宽和计算。这些节省被再投资到扩展专家数和路由多样性上，而不增加推理成本。在高达 95B 参数的广泛实验、混合架构和投影的万亿参数服务场景中，LatentMoE 在精度-效率帕累托前沿上一致优于标准 MoE。
