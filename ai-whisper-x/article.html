要点速览
- 核心问题：大模型每写一个字都要重读全部上下文，KV cache 越滚越大。2024 年起各家公司给出了三条不同的省算力路线

- 三条路线：压缩（把每行 KV 变窄，MLA）、线性（换成固定 d×d 状态矩阵，KDA）、稀疏（只挑最相关的 k 个格子，DSA）

- 巨头选择：Kimi K3 用 KDA+MLA 兜底、DeepSeek V4 换掉一半 MLA、GLM-5 公开否决线性、MiniMax M3 转向块稀疏

大模型每写一个字，都要回头把已读的全部内容重扫一遍；上下文越长，这笔账越算不起。2026 年，各大公司在“该省在哪儿”这个问题上，分别给出了三种不同的解法：压缩（Compression）、线性（Linear）、稀疏（Sparse）。 它们到底在动哪张矩阵？为什么 Kimi 死守线性、DeepSeek 却扔了一半 MLA、智谱还专程发文否决了对手的路线？这篇科普把三家巨头的选择一次讲透。

先搞明白：注意力到底在干什么

大模型是一个字一个字往外输出的。每输出一个字之前，它要回头看一遍已经写过的全部内容，这个“回头看”的动作就叫注意力（attention）。具体怎么看？模型给每个已处理过的字算出两个向量：K（key）是这字挂出的标签（“我是个人名”“我是个否定词”），V（value）是这字真正携带的内容；而正在生成的新字也算出一个 Q（query，查询）——“我想找什么样的字”。然后拿 Q 去和前面每个 K 做点积，谁的标签越匹配分数越高，就从谁那里多取一点 V。

举个具体例子：句子是“小明打开冰箱，发现它空了”。处理到“它”时，它的 Q 大致在表达“我在指代前面某个东西”，而“冰箱”的 K 在表达“我是个可被指代的物体”，两者点积很大，于是“它”大量取走了“冰箱”的 V，模型就知道这里的“它”说的是冰箱。一个模型有很多层（GPT-2 small 有 12 层，K3 有 93 层），每层都要完整做一遍，而且每层还同时开几十路并行查询（多头），一路盯语法、一路盯指代、一路盯主题。

KV cache：解药变成了毒药

这里有个巨大浪费：模型每写完一个字再写下一个时，前面所有字的 K 和 V 若从头重算一遍，而这些值其实一点没变。解决办法很直接——把算过的 K 和 V 存起来，这就是 KV cache（键值缓存），大模型推理里最重要的一个优化，避免了反复计算前缀、大幅加速自回归生成，是今天所有大模型服务的基石。

但缓存自己成了瓶颈。上下文每多一个字，缓存就多一份，而且每一层、每一个头都要存一份。更要命的是它的瓶颈类型：生成每个字，GPU 都要把整份缓存从显存读进计算核心过一遍（旧缓存只读不改，只在末尾追加新一个字的 K/V）。上下文越长这份搬运越久——最后模型不是算不动，是搬不动。 这句话是理解后面一切的钥匙。接下来所有架构创新，本质上都在跟这份不断膨胀的缓存较劲。

先摆出三张数据结构

编码：大模型的注意力计算里只有三张数据结构：① KV cache——一张 N×d 的表（N 是已读字数、d 是每向量维度，每读一个字多一行，沿 N 方向无限长高）；② 注意力分数矩阵——一张 N×N 的方阵（第 i 行 j 列=第 i 个字对第 j 个字的关注度，因不能偷看后文只用下三角；这张表随长度平方膨胀，完整方阵主要出现在训练和 prefill 阶段，逐字解码不物化，但总工作量仍随长度平方增长）；③ 状态矩阵——d×d 固定不变（只有线性注意力才有）。

三条路线分别动这三张表：压缩动① 的宽度，线性干掉①② 换③，稀疏动② 只算部分格子。理解了这一点，再看各家方案就一目了然。

解法一：压缩（Compression）—把 KV cache 变窄

动的是 KV cache 那张 N×d 的表：行数（N）不动，但每行变窄——把向量投影到更低维度存起来，用的时候再投影回来。具体数字最直观：GLM-5 每个 token 每层的 KV cache 只存 576 维，而论文里对照的 GQA-8 要存 2048 维，每行窄了 3.5 倍。 关键在于那张 N×N 分数表一格没少——每个字仍参与计算、仍能被精确回看。压缩只发生在“怎么存”，不发生在“看不看”。

性质：省的是常数倍，不管多长都压到 1/3.5，增长阶没变。代价：投影有损，压缩比越高丢得越多，且不是免费午餐——智谱一开始试纯 MLA 打不过 GQA-8，靠额外训练技巧才把差距拉回来。代表作是 DeepSeek 发明的 MLA（Multi-head Latent Attention，多头潜在注意力）：KV cache 不按原样存，先压成低维潜向量再存，用时再解压，但注意力本身仍完整、能精确回看任意一个词。

解法二：线性（Linear）—换成固定状态矩阵

最激进的一条：那张 N×N 分数表根本不造，那张 N×d 缓存也不留，换成 d×d 的状态矩阵（形状两个维度都是 d，跟 N 无关）。做法是把每个字的 K 和 V 累加进方块里，读时拿 Q 一乘就把相关内容取回来。这就是「读书笔记卡片」：读一页更新一次卡片然后扔掉那页。卡片永远是 d×d，读 500 页还是 50 万页都一样。「线性」指开销增长方式：原来长度翻倍开销翻四倍（N×N），现在翻倍就翻倍——线性增长。

性质：唯一让缓存与长度彻底脱钩的方案，这是它的杀手锏。 代价：d×d 容量有限而内容无限，写到一定程度不同关联开始互相干扰——想查的那条摸出来混着别的残影，这是线性路线始终要对付的死穴。代表作是 Moonshot 的 KDA（Kimi Delta Attention）：不存 KV cache，把读过的内容折进固定大小状态矩阵，读一个字更新一次然后扔掉原文。Qwen 在用的 Gated DeltaNet 是它的前身。

解法三：稀疏（Sparse）—分数表大部分格子不算

动的是 N×N 分数表：表的形状和 KV cache 一行都不变，变的是每一行只挑最相关的 k 个格子认真算，其余直接当零。GLM-5 的 k=2048，上下文上限约 20 万 token：一行 20 万个格子只算 2048 个，填充率约 1%。 性质：历史一个字没删，这次没挑中第 37 个字它仍躺在缓存里，下次照样能被挑到。代价：这一次可能挑漏。

稀疏还分两种，连省不省显存都不一样：静态稀疏是固定规则挑格子（最常见是滑动窗口，永远只算最近 128 格，更早的直接扔掉所以显存有上限，但远处信息一律丢失）；动态稀疏看内容临时决定挑哪些（每次实际打分，下次可能完全不同，正因为谁都可能被选中，所有 K/V 都得留、显存一分不省）。

代表作为 DeepSeek 的 DSA（DeepSeek Sparse Attention），智谱也用了： 一个叫 lightning indexer（闪电索引器）的极轻量小网络先给每个历史 token 快速打分，再挑分数最高的 top-k 只对这 k 个算真正注意力。关键是打分看内容而非按位置固定，这就是它比滑动窗口强的根本原因。但要清楚：主注意力确实降到与 k 成正比，可索引器本身仍要扫全部历史，论文写的还是平方级——只是它足够便宜。另一个值得注意的工程事实：稀疏化可以“后装”——智谱不是从头训，而是在已训好的稠密注意力模型上续训（GLM-5 本身是 MoE），算力远小于 DeepSeek 打通这条路的投入，意味着可在现有模型上低成本改造、不必推倒重来。

2026 各家巨头的实际选择

Kimi K3：KDA 打底、MLA 兜底。 K3 共 93 层，其中 69 层用 KDA、24 层用 Gated MLA，大致按「3 层 KDA + 1 层 MLA」循环 23 轮，最末尾额外挂一层 MLA（所以是 93 不是 92），保证最后一层一定能全局回看。KDA 层是固定大小的记忆板，省显存、跑得快但注定丢细节；MLA 层保留每个字都能精确回看的全局注意力能力。KDA 管「记住大意」，MLA 管「翻回原文」。 K3 还有叫 AttnRes 的新机制，把注意力从「横着看前文」搬到「竖着看前面的层」，让靠后层主动取前面没被稀释的干净表示（按块工作）。同路人阿里的 Qwen3-Next 用 Gated DeltaNet + 完整注意力，官方比例正好也是 3:1。

DeepSeek V4-Pro：换掉了 MLA 的一半。 V4 在 KV 侧不再用 MLA——官方配置里 MLA 的定义性字段全不存在，128 个注意力头共用同一份 KV，论文管这叫 Shared Key-Value MQA；但 query 侧的低秩压缩原封不动留着，那份共用 KV 本身也是把几千维隐状态压窄的结果，只是不再还原回每个头各自的 K/V。在此之上 V4 又沿另一方向压了一道（正交：一个压每个字存多宽，一个压多少个字合并成一条），具体是两种注意力逐层交错：CSA（压缩稀疏注意力）每 4 个 token 的 KV 压成 1 个再用 indexer 在压缩块里挑 top-1024；HCA（重压缩注意力）每 128 个 token 压成 1 个然后不挑了全看——因为已经够小，100 万 token 压完只剩 8192 个。两者都额外挂一条 128 宽的滑动窗口补局部细节。V4 干的是“先做缩略图，再在缩略图上挑重点”。61 层里前 2 层用 HCA，之后两种交错各占一半。收益（100 万上下文）：V4-Pro 只需上一代 27% 算力、10% 缓存（这是算力和缓存的账，官方没给端到端提速倍数）。

GLM-5：做了完整实验，然后公开否决了线性。 GLM-5 的选择是 MLA + 全层 DSA（压缩 + 动态稀疏）。智谱还公开了“为什么不选另一条”的实验：在一个 90 亿参数模型上续训 1900 亿 token，把几种方案正面对撞，包括 Qwen 在用、Kimi KDA 由此改进而来的 Gated DeltaNet。RULER@128K 成绩里，Gated DeltaNet 明显落后；另一项 RepoQA@128K（在长代码里找目标函数）完整注意力 65.83、Gated DeltaNet 掉到 56.17。智谱结论：这些高效注意力方案在精确检索类任务上都有难以避免的损失，即便保留一半层做完整注意力也补不回来。 但最耐人寻味的是表里那两栏滑动窗口：随便交错的那个只有 44.93 全场垫底，而智谱自己搜出来的层配置是 69.59、反过来是所有高效方案里最好的、比线性的 64.00 还高——同一种机制垫底和第一都是它，怎么配可能比用哪种机制更要紧。 线性派自己也承认短板：Kimi Linear 论文里写着长上下文检索仍是纯线性注意力的主要瓶颈。分歧从不在“线性有没有短板”，而在“这个短板要用多少完整注意力层去补”。

MiniMax：走过两条路，中间退回原点。 M1（2025）混合 Lightning Attention，线性层与完整注意力约 7:1，比 Kimi/Qwen 的 3:1 激进得多；M2（2025 年 10 月）退回完整注意力，还专门发文解释；M3（2026 年 6 月）转向 block 稀疏——跟 DSA 同类但粒度更粗，先算每个 token 分数再按 128 个一组压成“块分数”整块整块挑，每次选 16 块合计 2048 预算。为什么整块挑？因为 GPU 读显存喜欢连续大块：挑 2048 个散落 token 和挑 16 个连续大块算力一样，但后者搬运效率高得多——省计算量从来不等于跑得快。 论文报告的加速是预填充 14.2 倍、解码 7.6 倍（对照基线是密集 GQA 实验模型，不是 M2 本身）。而 M2 那篇退回说明才是最该记住的：他们点出的头号问题根本不是架构，而是评测本身的局限——指标一旦成为目标就不再是好指标，benchmark 永远是现实的漏抽象，判断架构好坏的认知成本高到离谱，且所有变量纠缠在一起。之后才谈工程顾虑：基础设施不成熟、线性架构连训练时都卡内存带宽、规模化后混合注意力在多跳推理有短板。但这些他们都认为是可解的，不是判死刑。要做一个真能上线的模型，看的是质量、速度、价格三件事，而完整注意力背后有多年算子和推理工程积累。

结语
三种解法，本质上是同一个古老问题的三种回答：一块容量有限的记忆，该怎么决定留下什么。有人选择把每一页缩印——行数不变但每行变窄；有人选择做笔记然后扔掉原文——赌自己的笔记做得够聪明；有人选择留着全部原文但学会跳读——赌自己每次都能挑对。

到 2026 年为止，稀疏和压缩这一侧人多势众：DeepSeek、智谱、MiniMax 都在这条路上；Kimi 和 Qwen 守着线性路线，且都靠「每隔几层塞一个完整注意力层」来兜底。而这远不是终局——下一次架构拐点，大概就藏在「评测本身也在演化」这一点上。
