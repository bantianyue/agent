# Mach-Mind-4-Flash 技术报告 — 全文翻译基线

## 摘要

我们提出 Mach-Mind-4-Flash，一个 350 亿参数（35B）的专家混合（MoE）Agent 模型，激活参数仅 30 亿（3B）。仅靠训练后优化、不扩大预训练算力，模型取得了与 1000 亿参数级别模型相当或超越的性能。通过为大规模强化学习引入可扩展的 Agent 交互环境，模型在真实应用场景任务上获得显著提升。我们的流水线包含三个阶段：(1) 统一的 RL/OPD 训练基础设施，具备动态多教师调度与算子级加速，带来 17% 的端到端训练提速；(2) 在推理（Reasoning）、通用（General）、Agent 三条轨道上并行训练多个领域专用 RL 专家，再通过多教师在线策略蒸馏（MOPD）融合为单个通才模型——这是一种带路由的反向 KL 目标，消除了混合奖励 RL 的跷跷板退化；(3) 混合中值长度策略优化（HMPO），一种单阶段 token 效率方法，将推理链压缩 19%–46%，精度损失不超过 0.7 个百分点。Mach-Mind-4-Flash 在 AIME'26 上得分 92.70，IFBench 82.82，Behavioral-SafetyBench 80.74，BFCL-v4 75.80，BrowseComp-zh 72.31，ClawBench 84.20——以极低的推理成本领先或追平激活参数规模为其 10–30 倍的模型。

## 1 引言

扩展语言模型一直是能力提升的主导配方，但其伴随的推理成本使万亿参数模型无法用于延迟敏感型部署。一个新兴的替代方案是扩展训练后流水线，通过强化学习、专家融合和推理时效率优化，把一个紧凑的基础模型推向前沿性能，而不是仅靠扩大预训练算力。Mach-Mind-4-Flash 就是我们在这条路上的贡献：一个 35B MoE 模型（激活 3B），其训练后技术栈把它提升到了激活参数多 10–30 倍的模型的性能层级。三大技术支柱支撑了这一结果：

(1) 具备算子级加速的可扩展训练基础设施。训练一个通才模型需要编排多条 RL 专家轨道、一个多教师蒸馏阶段和一个 token 效率阶段，它们共享同一套分布式基础设施。我们构建了统一的强化学习 / 在线策略蒸馏（RL/OPD）训练范式，通过一个加权损失在纯 RL、纯蒸馏和联合模式间无缝切换。在此之上，我们设计了动态多教师架构，新增一个专家对训练核心零侵入。在算子层面，我们深度集成了 SonicMoE 索引式分组广义矩阵乘（GEMM）核，以及一种将通信与计算重叠的分段共享专家融合策略，在 Qwen3.5-35B-A3B 训练上带来最高 17% 的端到端加速。

(2) 先专精、后融合：多个专家，一个通才。我们不为异构奖励混合物训练单一模型（这 inevitably 会遭遇能力跷跷板），而是在三条轨道上独立训练多个 RL 专家：推理（数学、代码、STEM）、通用（指令遵循、写作、安全）、Agent（工具调用、DeepSearch、代码 Agent、Claw Agent）。每个专家用领域适配的数据合成、可验证奖励信号和定制化训练策略（例如稀疏结果域的两阶段奖励课程、Agent 域的可执行多轮环境）进行优化。这些专家随后通过多教师在线策略蒸馏（MOPD）整合，MOPD 将每个训练样本路由到对应的冻结教师，并通过 token 级反向 KL 目标在学生自己的 rollout 上监督学生。该设计并行化了专家开发，消除了顺序依赖，产出一个保留、甚至偶尔超越单个专家性能的统一模型。

(3) 不牺牲精度的 token 效率。强推理模型倾向于过度思考，产生冗长的推理链，在不成比例的精度提升之外推高了服务成本。我们用 HMPO（混合中值长度策略优化）来解决，这是一种作为流水线最后一步应用的单阶段 RL 方法。HMPO 从正确 rollout 的中值导出一组自适应长度预算，并施加一个乘性的"正确性优先"奖励，从数学上防止对"短但错误"输出的奖励作弊。仅在数学上训练，压缩能力就能泛化到代码、科学和指令遵循，将生成长度减少 19%–46%，精度损失最多 0.7 个百分点。

结果。最终模型 Mach-Mind-4-Flash 证明，激进的训练后优化可以缩小一个紧凑 35B MoE 与明显更大的前沿模型之间的差距。在竞赛数学（AIME'26：92.70）、代码生成（LiveCodeBench-V6：80.91）、指令遵循（IFEval：94.64；IFBench：82.82）、安全（Content-SafetyBench：98.20；Behavioral-SafetyBench：80.74）和自主 Agent 任务（ClawBench：84.20；BFCL-v4：75.80）上，Mach-Mind-4-Flash 持续追平或超越 120B 级别模型，并与万亿参数系统保持竞争力——而推理时仅需 3B 激活参数。

## 2 相关工作

2.1 Agent 基础模型与基准。早期语言 Agent 工作表明 LLM 可以通过外部工具和环境行动。ReAct 交错推理与行动；Toolformer、Gorilla、ToolBench、API-Bank 研究工具学习、API 选择与工具增强的指令遵循。近期技术报告进一步把基础模型框定为 Agent 系统：Kimi K2 强调开放 Agent 智能；GLM-5 描述从"氛围编程"到 Agent 工程的转变；Step-3.5-Flash 与 MiMo-V2-Flash 突出高效稀疏激活；Qwen3-Coder-Next 聚焦用可执行环境训练的编码 Agent。Agent 基准也从静态 QA 走向真实任务完成：BFCL 评估函数调用，τ2-bench 评估工具-代理-用户交互，ToolSandbox 研究有状态工具使用，SWE-bench 评估真实软件问题求解。

2.2 Agent 训练后强化学习。训练后已成为模型能力的主要驱动力。InstructGPT 确立了 SFT 与 RLHF 对指令遵循的有效性。DeepSeek-R1 表明 RL 可以诱导长链推理、验证与自我反思。多轮工具调用 Agent 的 RL 研究中间工具动作的奖励校准；长上下文软件工程 Agent 训练展示交互式 RL 的价值。DPO、ORPO、SimPO 和多目标 DPO 提供偏好优化替代方案，与 OPD/MOPD 式训练密切相关。

2.3 高效且安全的 Agent 部署。生产 Agent 需要强推理与高效安全执行。Agent 工作流常含工具 schema、检索文档、执行轨迹、对话历史与中间观测，使长上下文推理与 prefill 成本成为主要瓶颈。Prompt 压缩方法减少 token 使用；DeepSeek-V4 瞄准百万 token 上下文效率；MiniMax-M1 用闪电注意力扩展测试时算力。服务层 vLLM、DistServe、多 token 预测改善 KV-cache 管理。安全同样重要，因为 Agent 可以执行动作而非仅输出文本。Constitutional AI 与 Rule-Based Rewards 提供基于原则与规则的机制；Llama Guard 支持安全分类。

## 3 基础设施

3.1 基于 RL 框架的统一 OPD 训练范式。传统知识蒸馏通常独立于 RL 训练流水线，难以充分利用 RL 框架在分布式调度、经验采样和策略优化上的系统优势。为此，我们将 OPD 深度集成进 RL 框架，构建统一联合训练范式。该范式通过一个统一加权损失实现全局优化控制，损失包含蒸馏路径的 ℒ_OPD（支持 MSE、Forward_kl_TopK 等蒸馏目标）与策略梯度路径的 ℒ_RL。通过动态调整权重 α 与 β，可灵活切换三种训练模式：纯 RL 模式（α=0,β>0）、纯 OPD 模式（α>0,β=0）、联合 RL+OPD 模式（α>0,β>0）。该统一范式直接继承了 RL 框架的系统级能力：复用成熟的分布式训练与调度机制；继承异步奖励路由机制，支持 20 多种任务的并行奖励计算；在单一框架内实现在线采样、奖励评估、策略优化与蒸馏监督的闭环。

3.2 动态多教师可扩展架构。单一教师模型往往难以全面覆盖所有任务域；为不同任务构建独立训练流水线则易导致资源浪费与工程碎片化。我们设计动态多教师架构，支持教师模型的灵活按需集成，实现"积木式"组合训练能力。架构设计与路由机制：多教师架构的核心设计原则是新增一个教师对框架核心逻辑零侵入，对学生模型训练过程完全透明。每个教师实例注册为蒸馏配置树中的一个独立配置节点；Rollout 阶段完成后，框架根据每条数据的路由标识异步分发样本到对应教师实例，获取目标 logits 后统一聚合计算蒸馏损失，该过程与学生模型的训练更新完全解耦。弹性资源调度：该架构依赖 Ray 集群实现透明的多节点资源调度，学生模型（Actor）节点与教师节点的 GPU 分配由框架根据张量并行（TP）规模与副本数自动绑定。

3.3 训练加速与极致优化。系统框架级加速：多维混合并行（TP、PP、EP），结合 MoE 分组 GEMM 算子融合；细粒度算子级重计算（仅对轻量算子如 RMSNorm 重算）；多 token 预测（MTP）加速，在 vLLM 采样阶段用 MTP head 做投机解码。底层算子级优化：SonicMoE 深度集成——针对 Transformer 层中最计算密集的 MoE MLP 模块，将 SonicMoE 深度集成进 Megatron 框架，利用 Hopper 架构 GPU 的硬件特性（TMA 拷贝引擎、Warp 专门化、多阶段生产者-消费者流水线）实现高效的索引式分组 GEMM 算子及其 Gate-Up 融合变体，消除 token 重排步骤，降低全局内存访问延迟；反向传播阶段引入局部重计算策略减少内存访问开销，并用 DeepEP 替代传统 All-to-All 集合通信。共享专家的分段融合：引入多流机制，把共享专家的计算拆成 AllGather、专家计算、ReduceScatter 三阶段，与标准专家在 EP 模式下的计算阶段（Dispatch、专家计算、Combine）交错融合，实现通信-计算重叠；并强制在共享专家模块设 TP=1，减少通信导致的计算资源空闲浪费。

## 4 训练后

如图 4 所示，Mach-Mind-4-Flash 的训练后流水线采用分层的"先专精、后融合"方法。基于 Qwen3.5-35B-A3B，先进行监督微调（SFT）建立基础对齐，再把训练分叉为三条并行的强化学习（RL）轨道，各自产出多个专家检查点：推理 RL（数学、代码、STEM）、通用 RL（指令遵循、写作、安全）、Agent RL（工具调用、DeepSearch、代码 Agent、Claw Agent）。为在不退化的情况下把这些多样化专家整合进单一模型，我们引入多教师在线策略蒸馏（MOPD）做无缝专家融合。最后，一个 token 效率 RL 阶段在保留精度的同时压缩生成长度，得到部署版 Mach-Mind-4-Flash。

4.1 监督微调。从 Qwen3.5-35B-A3B 出发进行大规模多领域 SFT。数据构成覆盖七个领域：数学与 STEM（可验证问题，经强教师模型拒绝采样合成推理链，按难度过滤）、代码（长代码生成与竞赛编程轨迹）、通用（指令遵循、创意写作、开放式 QA）、工具使用/代码 Agent/DeepSearch（构建超过 1 万种多样环境用于 Agent 轨迹合成）。数据策略优先质量与推理密度而非体量。训练配置：全局 batch size 32，学习率 1×10⁻⁵ 余弦衰减，最大序列长度 131072 token，训练 2 个 epoch；对 Agent 轨迹采用错误屏蔽——含错误动作的轨迹段保留为输入上下文，但在损失计算中被屏蔽，使模型观察并学习错误恢复行为而不强化错误动作；采用样本打包将多个样本拼接至上下文上限，用注意力掩码防止跨样本污染。

4.2 推理与通用 RL。训练两条并行 RL 专家轨道——推理（数学、代码、STEM）与通用（指令遵循、写作），都用 GRPO 以领域特定超参独立训练。数据合成与难度剪枝：推理域使用正确性可确定性验证的任务，采用 LLM 辅助问题合成；指令遵循任务借鉴 LexInstructEval 的形式化约束语法，分解为可组合的 ⟨过程, 关系, 值⟩ 三元组。统一难度剪枝：对每个候选查询用当前 SFT 模型做 8 次独立推理，丢弃过易（8/8 通过）或过难（0/8 通过）的样本。奖励设计：对稀疏结果信号域（如结构化推理任务 Table QA）采用两阶段奖励课程——阶段 1 用密集过程奖励 ℛ_proc 提供中间推理步骤的部分得分，实现稳定的冷启动；越过预定阈值后切换到阶段 2 的严格结果奖励 ℛ_out。对结果信号已具信息量的域（代码多测试用例通过率、指令遵循逐约束合规）直接采用结果奖励。写作任务用 RubricHub 的自动化粗到细 rubric 生成框架提供细粒度、准则级奖励信号。

4.3 安全 RL。构建面向安全的教师模型，针对两个互补维度：内容安全（防止不安全或违规响应）与行为安全（防止未授权、不可逆或与指令不一致的工具有效调用）。数据流水线结合内容安全数据与行为安全数据。训练流水线：内容安全训练专用安全奖励模型，RL 中对不安全响应给低奖励并优化安全响应的有用性；行为安全用基于规则的奖励评估工具调用轨迹的安全性。最终内容奖励与行为奖励结合训练安全教师模型，其安全能力可通过 MOPD 蒸馏到下游模型。

4.4 工具调用 RL。工具调用在生产 Agent 中是长程交互问题而非孤立的函数调用格式化问题。EnvScaling 是主要数据策略——扩展 Agent 决策被执行、观测与验证的环境，而非扩展静态工具调用轨迹。环境池含三个互补家族：文件系统执行环境（沙盒工作区、shell、文件 I/O、代码执行、测试、评分器）、程序可验证环境（Python 模拟的有状态环境，带类型化工具 API、确定性转移规则与基于状态的验证器）、模型模拟环境（用 LLM 或世界模型模拟器提供用户反馈与开放交互信号）。保留的环境池覆盖超过 190 个有状态域、超过 3.5K 个工具接口，每个环境通常暴露 10–30 个工具。奖励设计与训练流水线：工具调用 RL 用轨迹级奖励，因为动作质量往往要几轮之后才显现；每个 prompt 采样 K=8 条可执行轨迹，优化其轨迹级奖励上的组相对裁剪策略目标，采用非对称裁剪范围 ε_low=0.20、ε_high=0.28，每条轨迹最多 T_max=40 个助手/工具调用轮次，禁用显式 KL 正则；仅优化助手生成的决策 token，其余上下文屏蔽。

4.5 DeepSearch RL。DeepSearch 瞄准长程、多跳开放域检索 QA。数据流水线通过两条互补管线合成高难度多跳 QA：管线 I 从不显眼的 Wikipedia 实体播种，沿实体内超链接做广度优先搜索构建有向无环图（DAG），其深度设定推理跳数；管线 II 用 ReAct Agent 实时探索网络，链接共享关键属性的跨域实体，从由属性重合边连接的双约束链合成。训练流水线用在线 RL，在实时检索环境中 rollout 搜索/浏览轨迹，用 GRPO 配合基于结果的奖励模型（ORM），从中等到高难度样本的课程式推进；上下文管理通过四种机制实现：滑动窗口观测过滤、通过进度摘要的上下文重启、动态自适应阈值、答案自检。

4.6 代码 Agent RL。建立以仓库级软件工程任务为中心的端到端编码 Agent 训练后流水线。基础设施：构建容器化执行环境的自动化生命周期管理系统，覆盖环境供给、健康监控与基于自动重试的恢复，支持数千并发任务实例。数据策展流水线（图 9）：收集大量带可执行环境的仓库级实例，仅保留可失败转通过的；用多个代码 LLM 跨多种 scaffold 自动生成轨迹，每条 rollout 最多 300 轮、256K 上下文预算，仅保留成功解决问题、通过所有测试、满足严格轨迹级质量标准的轨迹。进一步用 Agent 友好模板（采用 XML 而非 JSON 的工具调用模板，减少格式不匹配）与错误屏蔽（规则化屏蔽管线，错误屏蔽轨迹比未屏蔽提升近 3%）增强。Agent 强化学习：将内部 Agent Harness 与执行环境集成进 Slime，构建完全异步解耦的 RL 基础设施；按当前模型 pass@8 做难度过滤，排除 pass@8 高于 0.9 的过易实例与低于 0.1 的过难实例；采用标准二元可验证任务完成奖励，在 GRPO 基础上融入 TIS 与动态采样等策略。

4.7 Claw Agent RL。Claw Agent 在隔离沙盒环境中训练复杂多步任务的自主 Agent 专家，强调长程决策与端到端任务完成。每个任务建模为部分可观测多轮决策过程，轨迹由交错的模型生成 token、工具调用、harness 响应与可选最终答案组成，接收来自任务验证的标量奖励。数据流水线来自真实世界分析任务与沙盒验证环境的策展集合，含难度混合集与简单案例集。Claw Agent 用 GRPO 配合组级优势归一化训练，引入 token 级信用分配机制，按交互序列中的结构角色（动作生成、工具选择、中间推理、最终答案合成）重新加权梯度贡献。

4.8 多教师在线策略蒸馏（MOPD）。将多个能力融合进单一通才仍是个难题。异构奖励混合物上的 RL 容易产生明显的跷跷板效应，且代价高昂（顺序依赖或巨大的奖励栈）。MOPD 让每个训练样本路由到已掌握它的领域专家，并通过 token 级反向 KL 目标在学生自己的 rollout 上直接监督学生。相对于混合奖励 RL，这用同质的、密集的蒸馏信号替代了异构奖励栈。目标：设 π_θ 为学生，π_Tk 为领域 k 的冻结专家，每个训练样本带路由键 teacher_route 确定性选择其监督教师；MOPD 最小化在学生自己 rollout 上计算的、带路由的 token 级反向 KL 蒸馏损失混合。为可解，用单样本 k1 估计器估计反向 KL，并在其上优化裁剪策略梯度代理以纠正 vLLM 推理引擎引入的异步 rollout-to-training 漂移。训练配置：生产 MOPD 运行融合超过十个跨三类的专家（推理 RL、通用 RL、Agent RL），域按严格 1:1 比例混合；遵循 Early Stopping Rollout 策略，即便长表单数学、代码、DeepSearch 也把 max_response_length 上限设为 8K token。收敛与结果：监控教师-学生 top-K token 重叠率（从初始化 0.73 单调升至 0.84）与损失量 ℒ_abs（≈0.05）和 ℒ_distill（≈0.01），约 60 步内稳定收敛；关键观察：教师参数量与学生匹配时重叠率明显高于大得多的教师，且在教师自身见过的 prompt 上训练进一步提升重叠率。

4.9 混合中值长度策略优化（HMPO）。MOPD 阶段融合所有领域专家，但继承了强 CoT 推理模型的已知副作用——过度思考（overthinking），即融合模型产生远超任务所需的推理链，推高推理延迟与服务成本而不带来相应精度提升。HMPO 是一种高性价比的单阶段 RL 框架，动态地从正确 rollout 的中值导出一组自适应预算 b，并施加长度感知的 token 奖励。方法三组件：(1) 自适应中值预算 b=median({n_i|i∈C})，隔离了失败轨迹的长度信号，难度感知且随策略改进自我收紧；(2) 余弦衰减 token 奖励，仅奖励短于 b 的正确轨迹，平滑着陆，避免朴素惩罚导致的奖励作弊；(3) 乘性组合 R_final=R_acc·R_token，强制严格的"正确性优先、长度次之"层级——错误或超预算轨迹获得精确零奖励，拒绝为错误答案付出效率梯度。单遍运行比多阶段基线少用 1.5×–2.5× GPU 小时。训练配置：在约 6.5K 高质量数学问题子集上运行，组大小 G=10，奖励偏移 λ=0.8；尽管仅在数学上训练，学到的长度控制行为泛化到未见域（代码生成、科学 QA、指令遵循）。

## 5 实验结果

5.1 总体结果。在广泛的开源与闭源基线间评估，覆盖从万亿级 MoE（Kimi-K2.5-1T-A32B）到约 120B 模型（Qwen3.5-122B-A10B、Nemotron-3-Super-120B-A12B）到紧凑 ≤35B 模型（Qwen3.5-35B-A3B、GLM-4.7-Flash-30B-A3B）。基准套件覆盖八个能力轴：推理与知识、指令遵循、写作、安全、工具使用、代码 Agent 能力、DeepSearch 与 OpenClaw。

推理与知识：竞赛数学上 Mach-Mind-4-Flash 在 AIME'26 得 92.70、AIME'25 得 92.08，追平约 120B 的 Qwen3.5-122B-A10B（91.67），与万亿级 Kimi-K2.5（93.30）差距缩至不到 1 分；代码生成 LiveCodeBench-V6 达 80.91，领先所有同规模模型；GPQA-Diamond（83.08）与 120B 级别基线相当，尽管激活参数少 30 倍。

指令遵循与写作：IFEval 94.64、IFBench 82.82、LexInstructEval 74.63 三项均居首；IFBench 领先尤其说明问题——许多在 IFEval 上高分的基线在留出约束上大幅下滑，显示其对已知模板过拟合而非真正理解约束。WritingBench 达 74.61，与 Qwen3.5-122B（74.80）相当。

安全：自研 Content-SafetyBench 与 Behavioral-SafetyBench；Mach-Mind-4-Flash 两项均居首，Content-SafetyBench 98.20、Behavioral-SafetyBench 80.74；后者领先亚军（Kimi-K2.5 67.75）约 13 分，多数基线落在 20–35 分区间，揭示 Agent 设置下的行为级安全仍是未解挑战。

工具使用与代码 Agent：BFCL-v4 得分 75.80，超越所有同规模 35B 模型并追平当前 SOTA MiMo-V2-Flash（76.30），同时超过大得多的 Qwen3.5-122B（72.20）与 Kimi-K2.5（74.50）；τ2-bench 达 80.04，大幅领先 Kimi-K2.5（72.82）与 Qwen3.5-122B（79.50）；SWE-bench Verified 70.60，与 Qwen3.5-122B（72.00）相当。

DeepSearch：BrowseComp-zh 居首 72.31，领先 Qwen3.5-122B（70.30）与 Kimi-K2.5（71.28）；英文 BrowseComp（61.70）与 X-Bench（65.00）保持竞争力。这一轴在所有基线间分化最剧烈，弱模型跌破 45 分。

Claw Agent：ClawBench（pass@3）84.20、ClawEval 69.49、PinchBench 74.90；ClawBench 超越 Kimi-K2.5（82.20）与 Step-3.5-Flash（83.97），仅次于 Qwen3.5-122B（85.11）。

5.2 专家训练与 MOPD 融合的效果。推理：推理 RL 专家把 LiveCodeBench-V6 从 79.39（SFT 基础）提升到 80.23，MOPD 融合后达 80.12，与专家相当；消融显示从 MOPD 教师池中移除推理专家导致推理基准下降 2%–4%。通用：通用 RL 专家带来显著提升，IFBench 从 72.79 升至 82.65（+9.86），IFEval 从 92.42 升至 94.64；融合后完全保留增益。Agent：代码 Agent 专家在 SWE-bench Verified 达 73.80（+4.80），Claw Agent 专家在 PinchBench 达 77.10（+2.79）；融合后 SWE-bench 保留大部分增益（71.10），ClawBench（83.20 vs 80.30）与 ClawEval（70.35 vs 67.23）反而超越单个 Agent 专家，归因于跨域迁移。总结：三种融合结果——推理的能力锚定、通用的完全保留、Agent 的混合结果，验证了 MOPD 设计：路由专家的在线策略蒸馏以最小干扰、偶发协同整合多样能力，而非混合 RL 训练典型的跷跷板退化。

5.3 token 效率（HMPO）。图 14 在 AIME'26 上绘制精度 vs 每轨迹平均 token 数。Mach-Mind-4-Flash 决定性超越 Nemotron-3-Super-120B-A12B（89.90% @ 13.4K），并与 Kimi-K2.5-1T-A32B（93.30% @ 16.6K）高度竞争，证明其以极小的前沿推理成本提供顶级数学性能。

## 6 局限与未来工作

Mach-Mind-4-Flash 的能力主要来自三处：Qwen3.5-35B-A3B 提供的强初始化、支持并行专家开发与算子级加速的可扩展训练基础设施、以及把异构专家能力整合进单一可部署模型而无混合奖励 RL 跷跷板退化的多教师在线策略蒸馏。剩余挑战：第一，MOPD 融合在极长程任务（如仓库级软件工程）上引入小而一致的差距，脚手架特定行为在蒸馏中被部分抹平；第二，token 效率方法（HMPO）目前针对单轮推理，把预算感知压缩扩展到多轮 Agent 轨迹仍是开放问题；第三，持久多约束网络浏览（DeepSearch）与长上下文理解仍是紧凑模型最弱的轴。未来工作将聚焦 Agent 设置的轮次感知 token 效率、更好保留长程专家行为的蒸馏策略，以及在同一训练后框架内实现视觉定位与 GUI 交互的多模态扩展。
