# 全文翻译基线（供覆盖率参考）

## 标题
Harness 效应：编排设计如何设定企业级 Agentic AI 的 Token 经济学

## 摘要
Agentic AI 开发中的主导模式是我们所称的 token maxing（代币最大化）：用 token 购买能力——更长的推理轨迹、更多的 Agent 轮次、更宽的工具载荷、更大的重放上下文——使得每任务的 token 增长快于任务价值的增长。不断下降的每 token 价格掩盖了这个模式却没修复它；总支出仍在上升。我们认为，对抗 token maxing 的决定性杠杆是 harness：那个组装上下文、暴露工具、编排轮次、委派工作、并承载企业部署所依赖的可观测性与治理面的编排层。为隔离这一层，我们做了一次受控替换：在相同的六个基础模型（Claude Sonnet 4.6、Gemini 3.1、Gemini Flash 3.5、Qwen 3.6、GLM 5.1、Palmyra X6）上跑相同的 22 个锁定评测任务，只改变编排层：一个常规的生产 Agent 循环（冻结基线）对比 Writer Agent Harness。在模型保持不变的情况下，把 harness 放在执行核心，使每任务混合成本下降 41%（0.21 美元→0.12 美元）、中位墙钟时间下降 44%（48 秒→27 秒）、每任务 token 下降 38%（14.2k→8.8k），而标题级任务完成质量保持在平价（0.78→0.81，在此样本量下为方向性）。效率收益与模型无关——每个模型都变便宜了，降幅 33% 到 61%——而质量收益取决于能力：一个模型从 harness 中提取的改进与其基线强度几乎完美相关（r=0.99，n=6），我们将此现象称为 harness leverage（harness 杠杆率）。每美元质量上升 82%，每百万 token 的任务完成数从 54.9 升到 92.0。在此工作负载上，编排层比在最便宜和最贵模型之间切换更能移动每任务成本。我们在编排层形式化了 token 经济学，包括在提示缓存下的有效输入价格模型；定义了 token maxing；详述了这一效应背后的六类机制家族，从缓存形态纪律到失败支出治理；在同一组轴上比较了六种广泛使用的 Agent 系统；并论证 harness 是唯一一个效率会乘到组织运行的每一个模型（现在和未来）之上的组件。

## 1 引言
一个 Agentic 任务不是一次模型调用。一个请求——"对这两份合同做对账并起草修订备忘录"——会展开成十几轮或更多：系统提示、工具模式、检索载荷、中间推理、工具输出，而在朴素实现里，后续每一轮都把上面全部内容完整重放一遍。任务的 token 账单是那个循环对所有轮次的求和，而那个循环不是由模型治理的，是由它周围的软件治理的。我们称那个软件为 harness：那个决定什么进入上下文窗口、哪些工具可见、何时检索、何时重试、何时委派、何时停止的编排层。

行业对不断上升的 Agent 能力需求的默认回应是花更多 token。推理模型每次回答放出数千个 deliberation token；Agent 框架按轮次数的平方重放对话历史；工具生态把每一个模式都注入每一次调用。每 token 价格稳步下降，下降的单位价格资助了这个习惯：团队把 token 当作边际上近乎免费的东西，并扩大消耗以匹配。这是教科书式的 Jevons 动态——资源效率提升降低了它的价格并抬高了总消耗——它产生了一个我们命名为 token maxing 的发展轨迹：质量是用单调增长的 token 强度购买的，而每 token 的边际质量在下降。Token maxing 在基准测试表里不可见（那里只报质量），在云账单里却痛彻心扉（那里报 token）。

大多数已发表的效率工作都在单次模型调用内部攻击这个问题——提示压缩、预算受限推理、简洁解码、推测解码、服务侧内存管理——或者在模型之间，通过路由和级联。这两类家族都接受编排层为给定。然而 harness 控制了 token 账单的每一项，除了模型自身的啰嗦程度：系统提示由 harness 重放或缓存；历史由 harness 重放或压缩；工具模式由 harness 广播或限定范围；检索载荷的大小由 harness 决定；重试由 harness 触发。如果 harness 是把模型调用组合成工作的那一层，它也是为工作定价的一层。

本文用分层架构使之成为可能的一次自然实验直接度量这个主张：保持任务和模型不变，只替换编排层。我们在六个跨越五个厂商和三个权重级别的基础模型上，用两种编排层评估 22 个锁定的、经能力审计的企业任务：一个常规的生产 Agent 循环（在 2026-06-07 冻结作为基线）和 Writer Agent Harness（一个模型无关的、带子 Agent 委派的编排层）。每个任务、提示、模型标识、评判者和价格表在两个 arm 间完全相同；唯一变量是编排代码。

标题结果（第 6 节）：
1. 效率移动很多，而且到处都移动。跨模型混合，每任务成本下降 41%（0.21→0.12 美元），中位墙钟下降 44%（48 秒→27 秒，快 1.8 倍），每任务 token 下降 38%（14.2k→8.8k）。逐模型成本降幅从 −33%（Gemini 3.1）到 −61%（Flash 3.5）：每个模型都大幅变便宜。在此工作负载上，harness 是比模型选择更大的成本杠杆：在基线下从最贵模型移到最便宜模型省 36%，而保持任意模型并采用 harness 省 33% 到 61%。
2. 质量持平——而它移动时，随模型移动。标题任务完成度 0.78→0.81（在 n=22 下是平局）。在 48 个能力×模型格子里，30 个提升，11 个持平，7 个回退；全部 7 个回退都发生在三个较小模型上，集中在重编排的能力（通过 MCP 的工具使用、多步 Playbooks）。一个模型从 harness 中提取的平均质量增益与其基线强度几乎完美相关（r=0.99）：更强的模型把 harness 结构转换成质量；更弱的模型可能被它压垮。我们称此为 harness leverage（第 6.4 节）。
3. 这次效率与能力不是权衡。每美元质量上升 82%；每百万 token 的任务完成数从 54.9 升到 92.0（+68%）。Harness 还新增了一项能力——委派的子 Agent——它只在两个最强模型上跨过可用可靠性阈值（0.85–0.86），这是 harness 特性所携带的能力地板的一个具体实例。

贡献：(1) 编排层 token 经济学的形式化框架，包括对每任务 token 支出分解为 harness 控制项、提示缓存下的有效输入价格模型、以及把 token maxing 定义为可度量的发展轨迹；(2) 一个隔离编排效应与模型效应的受控 harness 替换方法学，带锁定任务集、冻结基线和迹级记账；(3) 跨六个模型的实证发现：与模型无关的效率增益、取决于能力的质量增益（harness leverage）、以及高级编排特性的能力地板；(4) harness 的机制清单——缓存形态纪律、结构化压缩、上下文卸载、零 token 等待、失败支出治理、以及模型无关的地板——映射到成本分解，加上六种广泛使用 Agent 系统在同一组轴上的架构比较；(5) 为什么 harness 效率会复利的经济分析——它乘到每一个模型、每一次厂商迁移、每一个体量单位之上——以及对编排基础设施自建 versus 租赁决策的含义。

## 2 相关工作
模型侧与服务侧效率。大量文献降低给定 token 序列的成本：推测解码在不改变输出的前提下加速自回归生成；PagedAttention 及相关内存管理器提升服务吞吐。这些技术降低一个 token 的价格，但不减少一个 Agent 决定消费多少 token，而那正是本文针对的量。

提示侧 token 削减。LLMLingua 及其后继者在保持任务表现的同时压缩提示；token 预算感知推理约束 deliberation 长度；Chain-of-Draft 显示简洁的中间推理可以匹配啰嗦的 chain-of-thought。这些方法在单次调用内部运作。一个 Agent harness 每个任务调用这类调用几十次，并加上跨调用结构——历史重放、工具模式、检索——那是任何单次调用方法都看不到的。我们的结果表明跨调用结构才是更大节省所在：在不改变模型或提示的情况下实现每任务 token 下降 38%。

路由与级联。FrugalGPT 和 RouteLLM 通过把简单查询发给便宜模型来削减成本。路由选择哪个模型付账单；harness 决定无论选了哪个模型，账单有多大。二者互补。

Agent 架构。ReAct 交错推理与工具调用；Reflexion 加入言语自我纠正；Toolformer 把工具调用训练进模型；SWE-agent 表明 Agent-计算机接口实质性改变任务成功；MemGPT 引入 OS 风格的上下文分页；Model Context Protocol 标准化了工具连接。这一脉络确立了脚手架塑造能力。长上下文研究解释了一个机制：模型在长输入上注意力不均，所以臃肿的上下文会在抬高成本的同时降低准确率。我们用它的经济对偶——脚手架设定成本——扩展了脚手架塑造能力的结果，并在受控替换下同时量化两边。

评测与测试时计算。LLM-as-judge 协议和锁定基准套件支撑我们的度量设计。最优测试时计算分配的工作显示质量可以用推理 token 购买；我们的框架把那次购买当作一个边际率递减的经济决策，而 harness 是记录在案的买方。

推断经济学。Scaling law 为训练计算定价；Epoch AI 记录了推断价格多个数量级的下降。Jevons 在 1865 年观察到煤炭使用效率提升抬高了总煤炭消耗；第 3 节论证 agentic AI 正处于 Jevons 中段，而 harness 是消费纪律实际可以被实施的层。

Harness 作为一等对象。最接近我们框架的是近期一条把 harness 本身提升为研究对象的脉络：Gu 论证 agentic 进展现在既是系统缩放——上下文治理、记忆、技能路由——也是模型缩放；Harness-Bench 在 5194 条轨迹上度量了完成度、效率和失败行为在模型-harness 配置间差异显著。从业者证据指向同一方向：生产级上下文工程指南把 KV-cache 命中率当作 Agent 的第一个指标；厂商文档把缓存输入定价为大致列表价的十分之一；受控度量显示模型质量随输入增长而下降；Anthropic 报告 Agent 在约 4 倍、多 Agent 系统在约 15 倍的聊天级 token 消费。我们补上了缺失的经济层：harness 上的形式化 token 经济学框架、实现它的机制清单、以及一个为它定价的受控替换。

## 3 编排层的 Token 经济学
### 3.1 一个 Agentic 任务的账单
让一个任务作为 k 轮 Agent 循环执行。第 i 轮提交输入 token T_i^in 并接收输出 token T_i^out。输入价格 p_in、输出价格 p_out（每 token），任务成本为对 i 从 1 到 k 的求和 (p_in·T_i^in + p_out·T_i^out)。

输入侧分解为 harness 构造的项：T_i^in = S_i^system + H_i^history + Σ_i^tool schemas + R_i^retrieval + U_i^user turn。循环通过重试和死路分支把一切都乘上 k 倍，那也是 harness 治理的。一个朴素的 harness 重放完整转录：H_i = Σ_{j<i}(U_j + T_j^out + O_j)，其中 O_j 是第 j 轮的工具输出。总输入 token 于是随轮次数按平方增长，近似为 k·S + k(k−1)/2·M̄ + k·R̄ + ΣR_i，其中 M̄ 是每轮平均载荷。一个压缩历史、缓存不变前缀（含工具模式）、卸载庞大工具输出、并把检索截断到证据最小值的 harness，把平方项移到（近似）线性（图 1）。模型没有任何改变；账单变了。

图 1：Token maxing 从何而来。一个 k 轮 Agent 循环的累积输入 token 示意。完整历史重放按 k² 增长（式 3）；harness 管理的上下文——前缀缓存、历史压缩、卸载的工具输出——按 k 增长。阴影区是买了质量零提升的支出。示意；实测聚合见第 6 节。

两个进一步事实锐化了式 (1)。第一，Agent 工作负载是输入主导的：因为转录在每一轮都被重新提交，生产级 Agent 报告的输入输出 token 比接近 100:1，所以 p_in 项几乎是整张账单。第二，一个输入 token 的价格不是一个数。厂商以深度折扣提供重复先前见过的提示前缀的 token——大约列表价的 0.1 倍。如果输入 token 中有比例 φ 是缓存读、以乘数 κ 计费，有效输入价格是 p_in^eff = p_in·(1 − φ·(1 − κ))，κ≈0.1，所以一个把 φ 保持在接近 1 的 harness 为其式 (1) 的主导项支付大约列表价的十分之一。关键的是，φ 既不是模型属性也不是厂商恩惠：它是提示跨轮次的字节稳定性函数，完全由编排层如何组装上下文设定。因此 harness 控制着账单的两个因子——提交了多少 token（式 2）以及主导项以什么价格计费（式 4）。

### 3.2 Token 强度、效率与 token maxing
定义 token 强度 τ 为每完成任务的 token 总数，令 q∈[0,1] 为固定 judge 协议下的任务质量。我们用两个效率指标：η_$ = q/ℒ（每美元质量），CPM = q·10^6/τ（每百万 token 任务完成数）。

定义 1（Token maxing）。一个发展轨迹 {(q_t, τ_t)}_t 展现 token maxing，如果 token 强度增长 τ_{t+1} > τ_t，而每 token 的边际质量下降，(q_{t+1}−q_t)/(τ_{t+1}−τ_t) < (q_t−q_{t−1})/(τ_t−τ_{t−1})——即每次发布都以比系统运行均值更差的 token 交换率购买质量。

Token maxing 对按基准质量评判的团队是个体理性的，对按每 token 付费的组织是集体昂贵的。它在价格下降下也是自我强化的：当 p 下降，预算受限最优向更高 τ 偏移，总支出 N·ℒ 即便每任务 p·τ 下降也可能上升——Jevons 的煤炭，为 token 重述。出路不是更便宜的 token，而是更高的 CPM：用更少的 token 做同样的工作。式 (2) 说五个输入项里的四个，加上重试，是代码不是模型。那把出路正放在 harness 里。

### 3.3 为什么 harness 节省会复利
让一个舰队每月跨模型 c∈ℳ 以混合权重 w_c 跑 N 个任务。月支出为 Σ_c w_c·N·ℒ_c。一个模型侧优化改进一个 ℒ_c；一个路由策略改进混合 w_c；一个 harness 改进同时把每个 ℒ_c 乘上一个因子 (1−s_c)——并且当模型集变化时继续乘，因为它实现在模型 API 之上。实证上（第 6.2 节）s_c∈[0.33,0.61] 跨全部六个模型无一例外，这正是让 harness 成为技术栈中那个不寻常资产的原因：它的回报对哪个厂商赢得模型竞赛漠不关心。

## 4 Writer Agent Harness
### 4.1 Harness 是什么
在 Writer 的架构中，harness 是应用与任何基础模型之间的运行时：它拥有 (i) 上下文组装——系统提示、对话状态、来自文档和知识图谱 grounding 的检索载荷；(ii) 工具层——原生工具和通过 Model Context Protocol 的外部连接器，包括模式暴露和调用中介；(iii) 工作流执行——多步 Playbooks 端到端运行；(iv) 委派——生成有范围的子 Agent 并合并其结果（基线循环没有这个）；(v) 可观测性——一个迹衬层，为每次运行的每一轮记录提示 token、完成 token、工具事件和墙钟（duration_seconds）。那个迹衬层使本文的记账成为可能：成本在报告构建时通过对记录的 token 计数应用一个固定的公开价格表来计算，所以两个 arm 被完全一样地定价。同一层也是企业控制平面：计量 token 的迹衬层也是审计追踪，节省 token 的渐进式工具披露也是工具治理，确定性工作流执行也是让 Agent 行为可审查的东西——效率和控制在同一个组件上，这正是 harness 位于其他一切核心的原因。

Harness 在构造上是模型无关的：执行中的模型是一个配置值（model_name），这正允许第 5 节的受控替换——六个模型、两层编排、一个任务集、一个 judge 面板。它是 Writer 的 Action Agent 背后的运行时，其后者的公开结果（最难 GAIA 级别 61%；CUB 计算机使用基准总体最高分）标定了本评测所仪表化的生产系统。

### 4.2 Harness 对比常规 Agent 循环
基线是在生产中原先部署的常规 Agent 循环，在 2026-06-07 冻结。它的设计是行业默认，值得具体说明，因为每一元素都是一个由遗漏做出的 token 经济学决策：一个约 49KB 的单体系统提示在每一轮重放；工具调用用正则表达式从文本流里发出的 XML 中解析；上下文溢出时做破坏性中间截断；每模型提示调优；等待用轮询实现。Writer Agent Harness 在其预期通用可用配置下评估，用显式契约替换每一项：任意六个模型的一条执行路径；仅原生工具调用（XML 路径被删除而非移植）；替代截断的非破坏性结构化压缩；带实时工具调用状态的早流式；取消和重试作为一等状态；以及子 Agent——把子任务委派给一个或多个生成的 Agent，带范围化上下文并合并其结果——这是基线循环完全不具备的能力。

### 4.3 机制：harness 如何改写账单
把观测到的 delta 映射到式 (2) 和式 (4)，节省必须来自 harness 重写的那些项。设计目标可以用一句话陈述：最大化那些 (a) 被缓存、(b) 与决策相关、(c) 花在已提交、可恢复的工作内部的 token 的比例——并用结构而非模型行为来强制这三点。六类机制家族实现它。

图 2：双区提示。一个字节稳定的前缀（工具模式目录、稳定系统提示、仅追加转录）携带最多四个厂商缓存断点 [C1–C4]；每轮变化的一切都被限制在结构性排除在缓存之外的易变尾部。在一个前缀相同的调用上实测：99.9% 的提示 token（7876/7886）作为缓存读服务，把主导输入项定价在 ≈0.1× 列表价（式 4）。

(1) 缓存形态纪律：双区提示。Harness 发出的每个提示都有刻意物理形态（图 2）：一个字节稳定的前缀——完整的工具模式目录、稳定的系统提示、以及仅追加的持久转录——后接一个每轮重建的易变尾部（时钟、文件列表、计划状态、一次性提醒、语音和自定义指令）。这个切分作为正确性规则强制，而非优化：任何每轮变化的东西被结构性禁止进入前缀，缓存标记逻辑拒绝在第一个易变消息处或之后放置断点。最多四个厂商断点被钉住——在模式目录之后、稳定系统提示之后、以及沿两个最新持久轮次滑动——每会话锁定一小时保留，所以策略从不在运行中翻转。在一个前缀相同的 harness 仓库调用上实测，7886 个提示 token 中有 7876 个（99.9%）作为缓存读服务；由式 (4)，κ≈0.1，这样一个轮次为其主导项支付大约列表价的十分之一。因为 Agent 工作负载是输入主导的，缓存命中率是 harness 控制的单个最高杠杆成本变量——它活在 S_i、Σ_i、H_i 的放置处，而非模型里。

(2) 结构化、增量式、缓存感知的压缩。在模型输入预算的 80% 处，较老的历史被折叠进一个带类型的检查点，含四件产物：持久记忆（决策、约束、被拒方法）、一个为可恢复性写的八段执行摘要（当前状态、触碰过的文件、错误、下一步）、逐字保留的用户需求、以及技能引用。最近 4–12 条消息的实时尾部（≤预算的 30%）总是逐字存活；每个检查点把前一个向前折叠，所以压缩成本保持增量；摘要运行在一个更便宜的辅助模型上，脱离付费循环；空的或降级了的摘要会中止压缩而非持久化它。如果提示仍然装不下，一个确定性阶梯（先缩尾部，再带显式"重述要紧的"提示做中间截断）保证一个可发送的请求。压缩和缓存是共同设计的：一个每轮重写历史的摘要器会摧毁式 (4) 定价的正是那个前缀稳定性，所以检查点是持久行，而重建的提示成为新的可缓存前缀。这正是把式 (3) 从平方转线性的机制（图 1），且没有基线的破坏性截断。

(3) 上下文卸载：模型从不付费的 token。一个机制家族让信息可用而不把它留在上下文里，攻击 Σ_i 和 H_i 的工具输出份额。子 Agent 充当上下文防火墙：一个子 Agent 在它自己的上下文里做广泛阅读或搜索，返回一个上限 8KB 的摘要，引用挂在父模型从不读取的元数据侧车上；委派有深度上限且在重试下幂等，所以委派的探索不能膨胀父循环。技能用渐进式披露：提示只携带一个名称-描述表，完整技能文档安装在沙箱里，仅在被调用时读取（内联种子上限 20K 字符），之后压缩确定性丢弃技能体而保留引用。庞大的工具输出溢出到文件：超过 20K 字符的 shell 输出做头尾预览，完整输出写入工作区文件（带一个禁止模型从预览推断成功的横幅）；web 抓取内联 8K 字符并溢出完整页面；超大的文件读取被拒绝并给指引而非静默截断——文件系统是无界内存；上下文持有指针。计划和画布状态是事件溯源的，每轮投影一次为紧凑渲染，计划工具结果被替换为单行确认，所以状态从不在转录里重复；每轮重渲染兼作客观复述，对抗长程目标漂移。后台任务结果作为易变尾部提醒精确投递一次；加载的媒体有界（上下文里最多四张图或 2MB，更老的被驱逐并带重载桩）；以及侧工作——遥测、推理轨迹标题、交付物物化——在辅助模型上脱离付费循环运行。

(4) 零 token 等待；持久性即经济学。等待是一个延续而非循环：当一个运行需要人类答复、一个审批、或一个长后台作业时，它在零 token 成本下持久挂起，并在入口事件上恢复——没有轮询轮次。同一持久层给灾难性支出设界：每个事件在被流式传出之前被日志到写前日志；崩溃或抢占的运行在生成围栏下从恰好下一个序号恢复；工具结果在显示之前被持久化。一个丢失 40 轮运行的崩溃意味着重买 40 轮 token；这里意味着从持久状态恢复。

(5) 失败支出治理。每个失败在被做任何决策之前被分类进一个类型化类别（速率限制、停滞、超时、畸形流、厂商中断、永久），并且只有白名单类别落入路由计划里的下一个厂商。流中失败成为被丢弃的尝试：部分草稿被清除，且没有任何副作用——工具执行、持久写入——可以源自一个被丢弃的尝试，那正是通用库 fallback 遗漏的部分（编排库里的流式故障转移被记载为只在第一个 chunk 之前工作）。一个断路器在一个模型三次重发字节相同的失败工具调用时停下它，带感知原因的转向（改参数 vs 退避）；被截断的输出和输出长度上限作为类型化状态响亮地终止，从不静默；循环上限 50 次迭代，工具并行上限 4。重试、死路和厄运循环是式 (1) 上没有任何每 token 折扣能修复的乘数；harness 给那个乘数设界。

(6) 一个模型无关的地板。哪个模型运行、在哪些厂商上、以什么 fallback 顺序，是一个作为数据提供的类型化路由计划——循环从不在模型名上分支——并且每个厂商流在被循环看见之前被归一化进一个 chunk 契约。原生工具调用是唯一的调用路径，由针对较弱模型的模式卫生支撑：内联 $refs，恢复双重编码的 JSON 参数，从验证错误里擦掉框架内部件，以及当较弱模型误用超重工具模式时拆分它们。这些地板无论驱动的是什么模型都成立，那正是第 6.2 节模型无关性，以及为什么 harness leverage（第 6.4 节）表现为模型能力的干净函数的结构性解释：harness 修好地板；模型设定天花板。

所有六个家族的贯穿主线是：token 经济与输出质量是一次拉动的一个杠杆。长、干扰密集的上下文可度量地降低每个被测前沿模型；一个移除陈旧或庞大 token 的机制同时在削减账单和清理模型的工作集——那正是第 6.6 节 grounding 结果在微缩中展示的。

两条实现说明，为完整性陈述：子 Agent 委派当前作为阻塞调用执行，以及输出长度上限上的自动整轮重试已设计但尚未发布。上面的机制描述评估下的配置。

### 4.4 现有 harness 与框架中的 token 经济学
近期工作论证 harness 应当是一个设计与评测的一等对象，跨 harness 度量发现 Agent 能力是模型-harness 配置的属性而非模型单独的属性。我们这里的主张更窄且更经济：在广泛使用的 Agent 系统里，token 经济学 nowhere 是一等、已发表的契约。表 1 在同一组轴（第 4.3 节的机制家族）上总结了全景，从公开文档和在此 harness 设计期间进行的缓存行为源码级研究评估。

厂商集成客户端。Claude Code 和 Claude Cowork 是广泛部署中最精密的 harness 之二，它们的若干模式——缓存断点锁定、字节稳定前缀、子 Agent 任务拆分——在此 harness 设计期间从它们采纳或对照验证。差异在部署类别和契约：二者都是绑定单一厂商的单用户、客户端侧工具；它们的内部 token 管理不作为每任务记账面暴露；它们的经济学按构造不跨模型转移。它们为一个人优化一个会话。一个企业运行时必须为一个舰队计量。

编排库。LangGraph 提供图编排、检查点和中断作为优秀的底层原语——并刻意把提示缓存策略、压缩、上下文卸载和失败支出治理留给应用。Token 经济学于是成为应用团队未被预算的责任：框架里没有任何东西度量它、强制它、或报告它，而框架自己的文档承认了第 4.3 节提到的流式故障转移缺口。

多 Agent 对话框架。CrewAI 和 AutoGen 脉络（原框架，现维护模式，由 AG2 社区 fork 延续，并被 Agent Framework 为 Microsoft 栈接替）把工作组织为角色提示 Agent 之间共享转录的对话。共享转录多 Agent 制按构造是 token 乘数：每个参与的 Agent 重读不断增长的对话，每个都携带自己的角色前导。最好的公开度量是 Anthropic 自己的：Agent 消费约聊天 4 倍的 token，多 Agent 系统约 15 倍，token 量解释了它们研究评测上约 80% 的表现方差。那是定义 1 作为一个架构运作——用 token 乘法购买的质量。它可能值得付，正如 Anthropic 坦诚只有高价值、可并行化任务才证明它；但这些框架没有一个按任务计量那个乘数，也没有一个像有上限摘要的子 Agent 契约那样防火墙委派上下文。

开放个人 harness。Hermes Agent 是一个有能力的、真正模型无关的开源 harness，带隔离子 Agent。然而设计时源码研究发现，它不把工具模式放在缓存前缀内——放弃了输入主导工作负载上最大的单一折扣（式 4）——并且作为一个个人单用户 Agent，它不发布任何每任务 token 或成本契约。

比较展示了什么。表 1 的最后一列是本文的微缩。没有内建进编排层的每任务 token 记账，token maxing 是不可观测的——而不可观测的就无法被管理。Writer harness 的迹衬层使每任务成本和 CPM 每次发布都可度量，正是因为这只表活在同一层，也就是花 token 的那层；第 7.3 节的发布门姿态只在它之上才可能。我们强调认识论状态：表 1 比较的是公开设计和文档，不是实测运行；跨 harness 的配置级度量，以 Harness-Bench 的风格，是自然的未来工作。

## 5 实验设置
### 5.1 设计
实验是一次配对替换。两个 arm 在相同的 22 个任务、相同的六个模型、相同的 judge、相同的固定价格表上执行；只有编排层不同。基线 arm 是通过 model_name 覆盖调用的常规生产循环，在 2026-06-07 运行一次并冻结作为参考。Harness arm 是处于其预期通用可用配置的 Writer Agent Harness。因为提示、模型和 judge 被保持固定，token、成本、延迟或质量的任何系统性差异都可归因于 harness。

### 5.2 任务集
评测使用 n=22 个锁定基线提示，在任一 arm 运行之前就经审计以保证能力覆盖和可辩护的通过/失败标准。该集跨越九个映射企业 Agent 平台生产用法的能力领域：模型与系统意识（MSA：身份、范围、安全拒绝）、Grounding 与检索（GDR：文档与知识图谱 grounding、网页搜索、引用）、内容生成（CNG）、Playbooks（PLY：预定义多步工作流端到端执行）、MCP 工具使用（MCP：发现并调用外部连接器）、演示（PRN：幻灯片生成，早期能力）、语音（VOX：品牌语音和自定义指令）、图像分析与生成（IMG）、以及——仅在 harness 下——子 Agent（委派工作，全新）。任务包含多轮案例（例如一个三轮 Medicare grounding 对话）和长程案例（多步研究综合）。

### 5.3 模型
表 2 列出六个模型：两个前沿通才、一个快速档模型、两个开放权重候选，以及 Writer 的平台原生 Palmyra X6。这种分布是刻意的——核心主张是关于模型之上的一层，所以它必须跨权重级别和厂商测试，而非在单个旗舰上。

| 模型 | 厂商 | 级别 | 在分析中的角色 |
|------|------|------|------|
| Claude Sonnet 4.6 | Anthropic | 前沿 | 强通才 |
| Gemini 3.1 | Google DeepMind | 前沿 | 强通才 |

### 5.4 指标
质量。标题质量是由 LLM-judge 面板对照审计过的通过/失败标准评分的任务完成度。次要 judge 评分连贯性、沟通质量和幻觉；这些按提示报告，没有为任何决策做标题。Token。提示和完成 token 由迹衬层每轮记录；token 强度 τ 是每任务总计。成本。在报告构建时计算为（提示 token × p_in）+（完成 token × p_out），使用一个固定的 OpenRouter 价格表，两个 arm 完全相同。延迟。从第一个 token 到终止事件的墙钟（duration_seconds），跨运行取中位。UX。一个手工评分的定性量规（流式响应性、工具调用透明度、引用渲染、错误/取消处理、多轮连贯性）与自动化指标分开报告。

### 5.5 统计姿态
在 n=22，质量 delta 是方向性的而非统计显著的，我们全程如此对待：标题 +0.03 被报告为平价而非改进。成本、token 和延迟 delta 很大，在所有 22 个提示和全部六个模型上符号一致，因此在此样本量下是决定性的，而质量 delta 不是。候选模型在高级特性上的失败是预期并打分了的，不是排除的；模型无关主义是关于执行路径的主张，不是关于统一能力的承诺。

## 6 结果
### 6.1 标题：同样的工作，少 38% 的 token
图 3：跨六个模型和 22 个任务的混合效率。用 harness 替换基线循环，模型保持不变：每任务成本 −41%，中位墙钟 −44%，每任务 token −38%。

表 3：平价记分卡，跨模型混合。质量是在锁定 judge 协议下的任务完成度；派生行用式 (5)。

| 维度 | 基线 | Harness | Δ | 读法 |
|------|------|------|------|------|
| 质量（任务完成度） | 0.78 | 0.81 | +0.03 | 在 n=22 下平局 |
| 每任务成本 | 0.21 美元 | 0.12 美元 | −41% | 决定性 |
| 每任务墙钟（中位） | 48 秒 | 27 秒 | −44% | 决定性 |

| UI/UX（手工评分） | 基线 | 改进 | ↑ | 定性 |

表 3 和图 3 给出混合结果。用 harness 替换基线移除了 38% 的 token 强度和 41% 的成本，而质量保持在平价——那正是逃出 token maxing 的操作性定义：token 交换率改善了而非退化。在效率意义上，一美元多买了 82% 的已完成质量，一百万 token 多完成 68% 的任务。手工评分的 UX 量规朝同一方向移动，出于你会从架构预期到的机械原因：更早的流式、实时工具状态而非转圈、干净的取消。

表 4 和图 4 把效应按模型拆开。两个观察。第一，均匀性：六个模型、五个厂商、三个权重级别，没有一个例外——每个模型的成本至少下降三分之一。这是一个层级别效应的签名：如果节省来自任何模型特定行为，分布会显示它。第二，相对模型选择的大小：在基线下，从最贵模型（Palmyra X6，0.25 美元）移到最便宜（Qwen 3.6，0.16 美元）省 36%；保持任意模型并采用 harness 省 33% 到 61%。在此工作负载上，编排层是比模型菜单更大的成本杠杆——那反转了优化注意力通常的去向。

最大的相对增益落在快速档：Flash 3.5 成本降 61%、延迟降 55%。这与式 (2) 的分解一致：对于小、便宜的模型，harness 开销（重放的历史、广播的模式）占总账单的更大份额，所以移除它按比例移除更多。

### 6.3 质量：聚合平价，边缘取决于模型
图 5：跨 48 个能力×模型格子的质量平价。每个点是某个模型的一个能力分数，基线（x）vs harness（y）。对角线上方的点是在 harness 下提升的：30 个提升、11 个持平（|Δ|≤0.02）、7 个回退。所有回退都属于三个较小模型，集中在重编排的能力（MCP、Playbooks、演示）。

图 5 画出全部 48 个能力×模型格子（八个传统能力×六个模型；完整矩阵见附录 A）。质量坐落在对角线上或上方：30 格提升、11 格持平、7 格回退。回退不是随机的。每一个都发生在 Flash 3.5、Qwen 3.6 或 GLM 5.1 上，且七个里有六个落在最重锻炼编排的能力——MCP 工具使用（Qwen −0.15、GLM −0.06、Flash −0.04）、Playbooks 和演示。前沿模型和 Palmyra 在恰好那些类别提升最多（MCP：Sonnet +0.10、Palmyra +0.10；GDR：Sonnet +0.10、Palmyra +0.12）。同一个更丰富的 harness，强模型把它转换成质量，弱模型把它体验为负载。

### 6.4 Harness leverage
图 6：Harness leverage 随基线能力缩放。采用 harness 的平均质量增益（Δq̄，八个能力）对模型的基线强度。更强的模型从同一套编排升级中提取更多质量（r=0.99；n=6，提示性）。

把每个模型坍缩到它在八个评分能力上的均值，给出一个数字表示它从替换中提取了多少质量：Palmyra X6 +0.079、Sonnet 4.6 +0.073、Gemini 3.1 +0.050、GLM 5.1 +0.028、Flash 3.5 +0.010、Qwen 3.6 净负（−0.031）。对照基线画出（图 6），关系近乎线性（r=0.99；六个点，所以提示性而非结论性）。我们称那个斜率为 harness leverage：一个模型把编排结构转换成质量的速率。经济后果是不对称且有用的：效率增益是无条件的，质量增益由能力赚取。一个在 harness 下的弱模型仍然得到它的 44–61% 成本削减；它只是也得不到更好。这解耦了升级 harness 的两个理由，并让每一个按其自身定价。

表 5：子 Agent 委派（harness 下全新；不存在基线 arm）。分数是委派任务的任务完成度：生成一个或多个有范围的子 Agent 并合并其结果。

| | Sonnet 4.6 | Gemini 3.1 | Flash 3.5 | Qwen 3.6 | GLM 5.1 | Palmyra X6 |
|------|------|------|------|------|------|------|
| 子 Agent | 0.85 | 0.70 | 0.45 | 0.42 | 0.58 | 0.86 |

Harness 那一项真正全新的能力——把工作委派给生成的子 Agent——只在两个最强模型上跨过可用可靠性阈值（表 5：Palmyra X6 0.86、Sonnet 4.6 0.85），在 Gemini 3.1（0.70）和 GLM 5.1（0.58）上退化，而在快速档（0.42–0.45）尚不可靠。这是 harness-leverage 结果最尖锐的形式：一个编排特性携带一个能力地板，低于它暴露该特性产生的是失败而非功能。委派也有一个独特的 token 经济学剖面——子 Agent 上下文是有范围的，所以被委派的 token 花在一个有界的侧循环里，而非膨胀父上下文——第 4.3 节的上下文防火墙契约：一个上限摘要返回，引用挂在侧车上，父循环从不为子项的探索付费。

### 6.6 逐提示纹理：token 去了哪、换回了什么
四个示例提示展示了聚合背后的分布。三轮 Medicare grounding 对话从 0.60 提升到 0.90——集合里单一最大的质量跃升——在一个检索塑造发送更少、选择更好的证据的 harness 下，与长、噪上下文降级注意力的发现一致。身份/拒绝在 0.90/0.90 保持平价而成本减半（0.04 美元→0.02 美元）：半价的安全行为。合同 Q&A 移动 +0.07（0.75→0.82）。集合里最贵的任务，多步研究综合，从 0.61 美元降到 0.33 美元（−46%）但在质量上回退（0.80→0.60）——聚合平价藏起一个真实权衡的唯一地方，由较小模型驱动，以及为什么发布建议（第 7 节）把候选模型按住待修而非带着回退发布的原因。次要 judge 随标题移动：连贯性 0.85→0.88、沟通 0.79→0.80、幻觉两端都干净。

## 7 讨论
### 7.1 Harness 是定价者
结果沿第 3 节的框架干净地分离。式 (2) 里纯代码的那些项——历史、模式、检索大小、重试——为每个模型移动，因为代码无论哪个模型读它的输出都以相同方式执行。质量项由模型利用结构的能力中介，并随能力移动。一个层，两种货币：harness 无条件地设定工作的价格，并与模型共同设定工作的天花板。设定价格的层也是企业据以治理的层；效率和控制在同一个组件上集中。

这重构了一个常见的采购直觉。跨厂商比较 $/Mtok 的团队在比较 p；账单是 p×τ，而 τ 属于 harness。在此工作负载上，harness 移动账单胜过整个模型菜单的分布（第 6.2 节）。一个租赁其编排层的组织已经外包了它控制最多的变量。

### 7.2 舰队经济学：为什么节省会复利
图 7：舰队规模下的 Harness 节省。混合每任务成本应用到月度任务量。在每月一百万 Agent 任务时，harness 比基线每月值 9 万美元（年 108 万）；缺口随体量线性变宽，并乘到混合里的每一个模型。

每任务 delta 低估了兴趣对象，那是舰队支出。在此测得的混合率下，一个每月跑一百万 Agent 任务的组织在基线循环下付 21 万美元，在 harness 下付 12 万美元——单单一处编排变更就是每年 108 万美元（图 7）。三个属性让这个节省在 AI 优化中不同寻常。它是模型可移植的：实现在 API 之上，它在此存活了全部六个模型，并且按构造适用于尚不存在的模型。它是体量线性的：它随正是企业部署中增长最快的量——Agentic 任务量——精确增长。它叠加：每 token 价格下降、路由、和提示级压缩全都乘到它之上而非替代它。延迟以同样方式复利：每任务快 1.8 倍也是每单位编排基础设施吞吐量的 1.8 倍，并且更短的循环重试起来更便宜。

### 7.3 逃出 token maxing：改 KPI
定义 1 建议管理修复是一个度量修复。只报质量的团队会 token-max，因为 token 是别人的科目；报 CPM 或 η_$ 的团队不能。此处研究的替换把 CPM 从 54.9 移到 92.0 每百万 token 完成数——与行业轨迹相反的方向——而质量保持。我们建议 CPM 在每一个 Agent 发布门里紧挨质量，出于与性能-per-瓦特在芯片设计里紧挨性能相同的理由：它是预测账单的数字。

### 7.4 Harness-模型协同设计与按特性需求路由
回退模式（七个全在较小模型上，集中在 MCP/Playbooks）和子 Agent 地板（表 5）论证编排特性不是免费暴露的。一个 harness 是一个模型必须足够强才能兑现的契约。两个实际后果随之而来。第一，harness 能力应当按模型档优雅降级——在地板以下缩小工具目录并禁用委派——而非对所有模型呈现一个接口。第二，路由研究应当按特性需求路由，而非仅按提示难度：一个将锻炼子 Agent 的请求属于 Palmyra X6 或 Sonnet 4.6，无论其文本看起来多简单，而一个 grounded Q&A 请求可以无质量惩罚地走便宜 61% 的快速档（图 5，GDR 行：每个模型都提升）。

### 7.5 数据隐含的发布姿态
读作一个部署决策，证据支持：在两个跨过子 Agent 地板的模型（Palmyra X6、Sonnet 4.6）上通用可用；把开放权重候选按住待多步研究修复；以及用效率而非质量领导外部主张——效率是均匀且决定性的，质量在 n=22 下是方向性的。我们记录于此，因为它是表 3 的诚实读法：行业报告里的诱惑是给 +0.03 质量做标题；可辩护的标题是平价下 −38% token。

## 8 有效性威胁
样本量。n=22 个提示对于均匀、巨大的效率 delta 足够，对于质量推断不够；所有质量主张都是方向性的，标题是平价而非改进。单次运行基线。基线运行一次并冻结（2026-06-07）；基线上的运行间方差未测。Judge 依赖。任务完成度是 LLM 判的；judge 偏差被锁定标准和次要 judge 部分缓解但未消除。价格表依赖。美元数字继承一个固定的公开价格表；token 和延迟结果独立于价格并讲述同一故事。工作负载形状。任务集映射一个企业助手工作负载（grounding、工作流、工具、内容）；结果在长程编码基准上可能不同。六个点。harness-leverage 相关性在六个模型上计算，应读作等待更宽模型面板的强模式。一对。我们比较一个基线循环和一个 harness，都来自单一厂商；第 3 节的框架是一般的，但量级特定于这对。跨 harness 主张是架构性的。第 4.4 节从公开文档和设计时源码研究刻画其他系统；它不含跨 harness 度量，表 1 应读作设计比较而非基准。

## 9 结论
被保持在相同的 22 个任务上并由相同的面板评判，六个基础模型用少 38% 的 token、少 41% 的钱、少 44% 的时间做了同样的工作——因为环绕它们的软件变了，而非模型变了。效率是无条件的；质量增益去了足够强到赚取它们的模型；那一项新能力带着一个能力地板而来。Token maxing 是在编排层做的一个选择，并且可以在那里被撤销——机制接机制：缓存稳定的、压缩旧的、卸载庞大的、挂起等待的、给失败的设界。Harness 不是 Agent 系统的管道。在此证据下，它是 P&L。
