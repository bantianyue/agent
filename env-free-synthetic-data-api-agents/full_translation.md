# Environment-free Synthetic Data Generation for API-Calling Agents

## 摘要
训练 API 调用型大语言模型（LLM）智能体需要海量高质量的轨迹数据。然而，大规模收集此类数据通常需要具备可执行 API 和真实预填充后端数据库的完整环境，这造成了严重的可扩展性瓶颈。为此，我们提出了一种**无环境合成数据生成方法**，利用 LLM 作为即时数字世界模型。仅需 API 规范，我们的方法就能生成模拟智能体与有状态环境之间交互的轨迹。

具体而言，LLM 首先生成可使用提供的 API 解决的多样化任务。然后教师智能体迭代解决每个任务，同时 LLM 模拟器根据任务上下文和模拟历史生成连贯的合成 API 响应。最后，LLM 裁判过滤轨迹以确保生成数据集的质量。

我们在 AppWorld 和 OfficeBench 这两个具有挑战性的基准上评估了该方法，它们包含信息检索和状态变更任务。在合成数据上微调模型带来了显著的性能提升，证明无需任何可执行环境就能生成有效的 API 调用智能体监督信号。我们的结果确立了基于 LLM 的 API 模拟作为跨多样化 API 生态系统训练智能体的实用、可扩展解决方案。

## 1. 引言
大语言模型的快速发展推动了从被动文本生成器到主动 **API 调用智能体** 的范式转变。这些智能体通过执行 API 调用并对环境反馈进行推理来完成复杂的用户请求。然而，训练此类智能体需要捕获完整多步交互过程的高质量轨迹数据，包括用户指令、交错的读写 API 调用序列、执行结果和最终响应。与标准指令微调数据相比，这些多步轨迹在大规模收集时要困难得多，但它们对于教授智能体稳健的 API 使用、准确的状态追踪和有效的错误恢复仍然至关重要。

鉴于手动收集的困难，合成数据生成已成为自然解决方案，近期工作利用 LLM 大规模生成智能体轨迹。然而，这些工作假设可以访问具有可执行 API 和填充真实底层状态的后端数据库的完整环境。环境创建与数据合成之间的这种紧密耦合造成了主要的可扩展性瓶颈。要为新的 API 集合生成训练数据，必须首先构建相应的基础设施，更具挑战性的是，获取填充环境所需的多样化底层状态配置。

在这项工作中，我们提出了一个基本问题：**我们能否在完全不构建底层环境的情况下生成高质量的智能体轨迹数据？** 我们的核心猜想是，经过海量世界知识预训练的现代 LLM 可以作为动态数字世界模型。给定 API 规范、输入参数、任务指令和先前交互历史作为上下文，LLM 可以合成模拟真实环境反馈的真实执行结果，准确反映底层状态变化。基于这一洞见，我们引入了一种高度可扩展的智能体数据生成范式。我们不构建真实环境并执行实际 API，而是使用 LLM 直接从 API 规范即时模拟所有环境反馈。

为了实例化这一范式，我们提出了 **ESAT**（**E**nvironment-Free **S**ynthetic **A**gentic **T**rajectory）生成流水线，它仅使用 API 规范作为输入。流水线分三个阶段运行：
1. **任务合成阶段**：LLM 生成可由目标 API 解决的多样化真实任务，并用基于 LLM 的批评器过滤无效任务。
2. **轨迹合成阶段**：将教师智能体与基于 LLM 的 API 模拟器配对。当教师迭代发出 API 调用来解决任务时，模拟器使用用户任务和先前模拟历史作为上下文，即时无缝生成连贯的环境反馈。这种交互完全在模拟中生成完整的多步智能体轨迹，无需任何可执行环境。
3. **轨迹过滤阶段**：LLM 裁判评估生成的轨迹的正确性、完整性和冗余性，丢弃次优样本以确保高保真训练数据集。

ESAT 提供了两个关键优势：
- 它将智能体轨迹合成转化为轻量级规范问题。通过仅依赖 API 规范而非完全实现的环境或真实部署服务，它允许数据生成跨多样化 API 生态系统无缝扩展。
- 利用现代 LLM 的长上下文能力，我们的模拟器在连续 API 调用中保持状态一致性，允许生成远远超出孤立 API 调用示例的丰富多轮训练轨迹。

为了验证 ESAT，我们在 AppWorld 和 OfficeBench 上进行了大量实验，这两个具有挑战性的多应用基准测试评估智能体在复杂多步信息检索和状态变更任务上的表现。我们在从 1.7B 到 27B 参数的模型范围内的实验表明，在 ESAT 数据上进行监督微调（SFT）相对于相应的基础模型带来了显著的性能提升，在 AppWorld 上达到了 50.5%，在 OfficeBench 上达到了 60.5%。

值得注意的是，在提供官方训练任务集的 AppWorld 上，使用 ESAT 数据训练的模型优于使用从真实 AppWorld 环境收集的训练任务轨迹训练的模型。

**我们的贡献总结如下：**
- 我们引入了一个上下文感知、基于 LLM 的 API 模拟器，作为动态数字世界模型。通过利用任务上下文和交互历史，该模拟器生成连贯的环境反馈，无需任何真实 API 执行即可合成复杂的多步 API 调用轨迹。
- 我们提出了 ESAT，一种新颖的无环境数据合成流水线，将智能体轨迹生成简化为轻量级规范问题。通过仅要求 API 规范作为输入，ESAT 消除了与构建和填充可执行环境相关的基础设施和数据瓶颈，实现跨多样化 API 生态系统的无缝扩展。
- 我们证明了 ESAT 数据对于监督微调非常有效。在从 1.7B 到 27B 参数的各种模型中，我们的合成数据在 AppWorld 和 OfficeBench 数据集上带来了显著提升。

## 2. 方法
在本节中，我们介绍 ESAT，我们的无环境流水线，它将 API 规范转化为多步 API 调用轨迹数据集，无需依赖真实 API 执行、后端基础设施或人工编写的任务。ESAT 流水线包含三个阶段：(i) 从 API 规范合成任务，(ii) 使用教师智能体与基于 LLM 的 API 模拟器配对合成轨迹，以及 (iii) 通过 LLM 裁判过滤轨迹。

### 2.1 任务合成
此阶段生成可使用可用 API 解决的多样化用户任务。唯一需要的输入是一组 API 规范，详细说明每个 API 的名称、用途和输入/输出模式。

**分桶生成。** 为了确保广泛且平衡的覆盖，任务生成被组织成**配置桶**的组合网格。每个桶由属性元组定义，包括难度级别（简单、中等、困难）、动作类型（读、写、混合）、任务焦点（约束满足、推导）、应用数量（1、2 或 3）以及每个应用的 API 范围。这些桶以随机序列处理，任务生成器 LLM 被多次提示以生成每个桶所需数量的任务。

在每次调用中，我们随机采样与桶所需数量匹配的应用，并向 LLM 提供其完整的 API 规范，以及目标难度、动作类型、任务焦点和 API 计数。然后 LLM 生成一个任务以及解决它所需的 API 列表。

**基于逆频率的采样。** 为了确保应用和 API 的均匀覆盖，我们采用基于逆频率的采样策略。我们在所有生成的任务中维护每个应用和 API 的运行使用计数。在为生成步骤选择应用时，我们以与其当前计数成反比的概率对其进行采样，从而优先考虑代表性不足的应用。此外，我们根据计数对所选应用中的所有可用 API 进行排名，并明确指示任务生成器 LLM 专注于最少使用的 API。

**任务过滤。** 每个生成的任务都由 LLM 裁判评估，以确保其格式良好、可解决并与相应的桶配置一致。

**任务重写。** 直接从 API 规范生成的任务有时可能过于程序化，概述了详细的指令而非自然目标。为了解决这个问题，所有被裁判接受的任务随后由 LLM 重写，将任何程序化脚手架压缩为反映实际用户需求的简洁意图级请求。这些重写的任务随后由 LLM 裁判验证以确保它们仍然有效。如果重写的任务被裁判拒绝，则保留相应的初始任务用于轨迹合成。

### 2.2 轨迹合成
在此阶段，教师 LLM 智能体通过发出 API 调用迭代解决每个任务，同时基于 LLM 的 API 模拟器动态生成合成响应。这产生了完整的多步训练轨迹，包括智能体的推理、API 调用和模拟环境观察，所有这些都无需执行任何真实 API。

为了确保结构正确性和语义连贯性，模拟器 LLM 将其输出条件于丰富的输入上下文，包括：(1) 完整的 API 规范，(2) API 调用参数，(3) 正在解决的任务，(4) 轨迹中先前 API 调用的历史及其模拟响应，(5) 虚拟用户的姓名、电子邮件和电话号码，以及 (6) 当前日期和时间。为了防止输入上下文过长并加速模拟，我们将模拟历史限制为来自同一应用的先前 API 调用。

**模拟器规则。** 模拟器 LLM 由其系统提示中编码的四个核心规则指导：
1. **数据一致性**：它必须跨轮次保持状态（例如，较早分配给特定艺术家的歌曲必须保留在该艺术家名下）
2. **数据多样性**：列出的结果应包含任务相关和不相关项目的混合，以反映现实世界的噪声
3. **数据真实性**：生成的值必须遵守字段约束，如数值范围和唯一标识符
4. **模式合规性**：响应必须严格符合 API 规范中提供的模式

**模拟质量检查。** 为了确保模拟器产生准确和真实的响应，我们采用了多个阶段的质量控制。在调用模拟器 LLM 之前，对 API 调用参数进行缺失参数和类型不匹配的程序验证。如果检测到错误，模拟器直接返回适当的错误消息，而不调用 LLM。

对于有效的 API 调用，LLM 生成的响应经过多次检查。首先，针对预期的输出模式进行程序验证。在模式不匹配的情况下，使用模式错误作为反馈重新提示模拟器 LLM。一旦响应通过模式检查，使用与裁判相同的 LLM 评估其语义正确性和与模拟历史的一致性。如果裁判发现任何错误，提示模拟器 LLM 使用裁判的输出作为反馈来改进其响应。只有通过所有检查的响应才会被返回。我们允许固定数量的改进步骤；如果模拟器在耗尽所有重试后仍无法生成有效响应，我们声明模拟失败。

**轨迹终止。** 当智能体显式调用特殊的任务完成 API、超过预定义的执行步骤限制、或调用来自未用于合成相应任务的应用的 API 时，任务的轨迹生成结束。如果模拟器失败，该过程也会停止。

### 2.3 轨迹过滤
智能体通过调用任务完成 API 完成任务的轨迹最终使用轨迹级 LLM 裁判进行评估，该裁判决定智能体是否正确解决了相应的任务。每个轨迹被多次判断，我们只保留那些具有多数积极裁决的轨迹。

## 3. 实验
**基准测试。** 我们在两个用于测试复杂 API 交互的具有挑战性的多应用基准上评估了我们的方法：
- **AppWorld** 提供了严格的测试平台，包含需要智能体在多个应用之间协调大量读写 API 调用的复杂任务。该环境包含 9 个日常应用中的 457 个 API，平均任务需要 10 个唯一 API 和 45 个总调用。AppWorld 提供两个测试拆分：包含 168 个任务的 Test-Normal (Test-N) 和包含 417 个任务的 Test-Challenge (Test-C)。后者引入了两个未见过的应用来评估难度增加时的泛化能力。
- **OfficeBench** 专注于办公自动化，包含 8 个应用中的 20 个 API。任务要求智能体规划跨应用的长程工作流程，例如提取电子表格数据、安排日历事件和发送电子邮件。我们排除了依赖 OCR 和不可解决的任务，在 26 个双应用和 46 个三应用任务上进行评估。

**模型。** 我们使用 GLM-4.7-FP8 进行任务合成，GLM-5.1-FP8 进行轨迹合成（教师智能体和 API 模拟器），Gemini-3.1-Pro 进行轨迹过滤。生成的合成数据用于微调八个模型：Qwen3 (1.7B, 4B, 8B, 14B) 和 Qwen3.5 (2B, 4B, 9B, 27B)。

**训练。** 每个训练轨迹被格式化为多轮对话，包括任务指令、智能体的推理和 API 调用，以及模拟的 API 响应。我们遵循标准 SFT 策略，训练模型在每一轮中根据任务指令和所有先前的 API 调用及其响应预测智能体的输出。

**评估。** 本节报告的所有结果是八次推理运行的平均值，标准偏差在附录中提供。

### 3.1 AppWorld 基准结果
**来自 AppWorld API 的 ESAT 训练数据。** 我们使用 AppWorld 的 340 个 API 生成了 9K 条轨迹，将我们的选择限制在七个应用以严格排除 Test-C 拆分中的两个未见过的应用。该数据集表示为 ESAT-AW7。

**来自合成 API 的 ESAT 训练数据。** 为了增加数据多样性，我们定义了 52 个新的合成应用，包含 1017 个独立于 AppWorld 的 API，并使用这些 API 生成了 6K 条轨迹。这些新应用是通过直接提示 Gemini 生成涵盖电子商务、生产力、旅行、娱乐和金融等不同领域的 API 规范而创建的。我们将这个基于合成应用的数据集表示为 ESAT-S52。

**AppWorld 训练数据。** AppWorld 数据集提供了 90 个任务的训练集。我们使用 GLM-5.1-FP8 模型作为真实 AppWorld 环境中的智能体，为每个任务生成了 8 条轨迹，并使用数据集中包含的任务验证器过滤成功的轨迹。由此产生的 634 条轨迹称为 AWT 数据集。

**指标。** 遵循 AppWorld，我们报告任务和场景目标完成率（TGC 和 SGC）。由于空间限制，我们在本节中呈现 TGC 结果。

**ESAT 数据的有效性。** 
- **对新 API 的强泛化能力。** 在使用 52 个独立于 AppWorld 的合成应用生成的 ESAT-S52 数据集上进行微调，在所有模型中都带来了显著提升（8.4-47.0%）。这些结果证实，当使用多样化的合成 API 规范作为种子时，ESAT 流水线可以生成有效的训练数据，赋予稳健的 API 调用技能，能够泛化到未见过的 API。值得注意的是，对于几乎所有模型（除 Qwen3-1.7B 外），使用 ESAT-S52 数据实现的性能都超过了使用从真实 AppWorld 环境收集的 AWT 数据实现的性能，尽管 ESAT-S52 完全来自合成应用。

- **使用最少目标信息获得大提升。** 在合并的 ESAT-S52-AW7 数据集（合并了 ESAT-S52 和 ESAT-AW7）上进行微调，在几乎所有设置中都进一步提高了性能（高达 11.2%）。ESAT-AW7 子集提供了额外的合成轨迹，这些轨迹仅使用最少的目标域信息生成，完全依赖于来自七个 AppWorld 应用的 API 规范。

对于所有模型，在 ESAT-S52-AW7 数据上进行微调相对于在 AWT 数据上进行微调始终带来更好的性能（0.7-15.3%）。这表明，完全绕过训练期间对目标环境的需求，可以生成高效的、特定领域的监督信号。

此外，在 ESAT-S52-AW7 和 AWT 数据上进行微调，相对于仅在 AWT 数据上训练，对于 Qwen3 模型有显著提升（4.1-15.3%）。对于 Qwen3.5 模型，用 AWT 数据增强 ESAT 数据不会带来进一步的性能提升。这些结果证实，即使真实环境数据可用，ESAT 流水线也提供了高度有价值的监督。

**有效的知识迁移。** 当在 ESAT-S52-AW7 数据集上进行微调时，Qwen3（8B 和 14B）和 Qwen3.5（4B、9B 和 27B）模型的性能超过了大得多的 GPT-4o 和 Nemotron-3-120B 基线，而 Qwen3.5-27B 模型的性能与大得多的 GLM-5.1-FP8 教师模型相当（差异<3%）。这证明了我们方法在知识蒸馏方面的有效性，证实了复杂的 API 调用能力可以使用纯合成、无环境的数据迁移到更小的模型。

**对新型用户数据模式的泛化能力。** 在轨迹生成期间，我们的 API 模拟器充当数字世界模型，动态模拟正在解决的特定任务的虚拟用户的底层状态。因此，合成的数据模式完全独立于 AppWorld 环境中的模式。在 AppWorld 测试拆分上观察到的大性能提升表明，在 ESAT 数据上训练的模型成功地泛化到未见过的用户状态和数据分布。

### 3.2 OfficeBench 基准结果
**ESAT 训练数据。** 由于 OfficeBench 是仅评估的基准，没有训练集，我们使用 OfficeBench 的 20 个 API（跨越 8 个应用）生成了 1.7K 条轨迹。该数据集表示为 ESAT-OB。

**指标。** 遵循 OfficeBench，我们报告通过率，定义为其输出满足与每个任务关联的自定义评估函数（精确匹配、模糊匹配或基于执行的匹配）的任务的百分比。

**ESAT 数据的有效性。** 在我们的无环境合成数据上训练实现的性能提升（5.2-60.5%）再次证实，完全绕过训练环境的需求，可以为 API 调用智能体生成高效的监督信号。值得注意的是，Qwen3-4B 和 Qwen3.5-4B 等较小模型的性能能够超过大得多的 Nemotron-3-120B 和 GPT-4o 模型。我们还以显著优势（20% 或更多）超过了 Simia（最近专注于合成 API 调用数据的工作）。

### 3.3 LLM 裁判质量
为了理解用于轨迹过滤的裁判模型的影响，我们进行了一项消融研究，比较了 GLM-5.1-FP8 和 Gemini-3.1-Pro。结果显示了 Qwen3-8B 模型在由这些模型中的每一个过滤的 ESAT-S52-AW7 数据上训练的性能。与未过滤的基线相比，使用 GLM 进行轨迹管理实际上会降低性能。相比之下，Gemini 被证明是一个高效的过滤器。通过积极丢弃更大比例的低质量轨迹，它最终产生了卓越的下游性能。

**与真实环境正确性的相关性。** 为了量化我们的 LLM 裁判与真实可执行正确性的对应程度，我们对真实 AppWorld 环境进行了实证验证。我们使用 GLM-5.1-FP8 作为智能体生成了 720 条轨迹（在 90 个 AppWorld 训练任务中每个任务 8 条），并从 AppWorld 的基于执行的验证器获得了地面真相轨迹标签。然后，我们使用我们的 LLM 裁判 Gemini-3.1-Pro 重新评估了这些轨迹。裁判实现了 95.2% 的精确率，确认当我们的流水线将轨迹标记为正确时，它极有可能是真正正确的。这是数据管理最重要的属性，因为它限制了进入训练集的错误轨迹的比例。

**与人类注释者的一致性。** 为了进一步验证轨迹过滤阶段，我们对我们的 LLM 裁判进行了人类评估。我们随机抽样了 200 条轨迹（100 条被裁判接受，100 条被拒绝），并让人类注释者使用相同的评分标准评估它们。注释者仅在 8 条接受和 2 条拒绝的轨迹上与裁判意见不一致，总体一致性为 95%，Cohen's kappa 为 0.90。这种近乎完美的一致性证实了我们过滤过程以及我们管理的 ESAT 训练数据的高保真度。

### 3.4 API 模拟器质量分析
虽然上一节从下游模型性能方面确立了我们基于模拟器的 ESAT 流水线的有效性，但本节将模拟器作为独立组件评估其质量。为此，我们获取了使用 AppWorld API 生成的 1K 条成功轨迹，包含约 27K 个模拟 API 调用。我们使用 GPT-5.1 作为裁判评估所有这些调用的模拟响应。

对于每个 API 调用，裁判获得了模拟调用响应的历史（用作模拟器的输入上下文），并验证了当前模拟响应是否与 API 规范、调用参数以及从先前调用累积的状态一致。根据 GPT-5.1 的评估，我们的模拟器为 93.7% 的调用生成了有效响应，证实了我们 ESAT 训练数据集的高质量。

**响应长度的影响。** 模拟失败率随模拟响应长度的变化而变化。对于 500 token 以下的短响应，失败率保持较低（2-3%），表明当所需输出紧凑时，模拟器可靠地生成格式良好的响应。然后失败率随长度稳步上升，在 500-1K 范围内达到 8%，1K-2K token 达到 18%，超过 2K token 达到 23%。这种趋势可能是由于本工作中用作模拟器的 GLM-5.1-FP8 模型的固有局限性，并且可以通过使用更强大的前沿模型来解决，这些模型更擅长在长格式生成中保持一致性。

我们还研究了输入上下文长度对失败率的影响，未观察到显著相关性。

### 3.5 与现有合成 API 调用数据集的比较
我们将 ESAT 数据集与三个现有的合成 API 调用数据集进行了比较：
- **ToolAlpaca** 和 **ToolACE** 针对简单的 API 调用场景，不建模有状态环境；具体来说，它们的实例不需要在不断变化的环境状态上进行协调的读写序列。
- **Nemotron** 是最近的工作，将合成 API 调用数据扩展到 150 万条轨迹，但其 API 模拟器针对正确性标准而非维护状态在轮次级别生成每个响应。此外，其单轮和多轮场景不是为 AppWorld 和 OfficeBench 中存在的长程、多应用工作流程设计的。

相比之下，ESAT 的模拟器充当有状态的数字世界模型，在任务内的所有 API 调用中保持一致的虚拟状态。

在 AppWorld 和 OfficeBench 数据集上分别比较了这些合成 API 调用数据集在下游性能方面的有效性。在 ToolAlpaca 和 ToolACE 数据集上微调模型产生的性能与相应的零样本准确率相似或更差，而在 Nemotron 数据集上微调仅在某些情况下带来边际性能提升。这清楚地表明这些简单的工具调用数据集没有为智能体配备导航复杂、有状态环境所需的技能。相比之下，在 ESAT 数据集上训练在两个基准上都带来了显著的性能提升。

为了测试这些替代合成数据集是否提供有用的基础技能，我们进一步在从 AppWorld 环境收集的 AWT 数据上微调模型。即使有这种真实环境监督，它们的最终性能也显著低于在 ESAT 数据上训练的模型。

## 4. 结论
我们提出了 ESAT，一个无环境流水线，仅使用 API 规范为 API 调用智能体合成训练数据。通过结合覆盖感知的任务生成、状态一致的基于 LLM 的 API 模拟器和轨迹级 LLM 裁判，ESAT 无需使用任何功能性环境即可生成高质量的多步轨迹。

在具有挑战性的 AppWorld 和 OfficeBench 基准上的评估证明，在从 1.7B 到 27B 参数的各种模型中都有显著的性能提升。在 AppWorld 上，使用合成 ESAT 数据训练的模型优于使用从真实环境收集的轨迹训练的模型。在两个基准上，我们都能够使用 4B 到 8B 参数的显著更小的模型超越或接近 GPT-4o 的性能。这些结果确立了我们的无环境数据合成流水线作为训练 API 调用智能体的高效且可扩展的解决方案。
