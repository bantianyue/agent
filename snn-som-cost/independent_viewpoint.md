# 独立观点（草稿）

## 1. 软件协议的价值在被低估
业界盯着新kernel、新编译器，但这篇把"跨GPU依赖kernel的细粒度空间流水线"做成了对现有库零侵入的软件协议——只加 prologue/epilogue 就让 CUTLASS kernel 跨设备并发。这种"不改核心、只加首尾"的可移植性，比单点性能数字更值钱。

## 2. 与TP是正交，不是替代
CTA-pipelining 不取代 TP。它补齐了层内算子间那块 TP 够不着的延迟空间，又能作为正交维度与 TP 叠加。部署时该用 TP 用 TP，再用它压剩余延迟。

## 3. 真正瓶颈已转向互连拓扑
软件能做的它做了（绕开 All-Reduce、隐藏协议开销）。但中心化 NVLink 交换让"共享内存错觉"在物理上撑不住——生产者直写会长期占住同一链路，拖累计算-通信重叠。后续收益要看更分散的 NVSwitch 拓扑和硬件级 kernel 间信令。
